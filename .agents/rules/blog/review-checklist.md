# AI Mind 博客成稿检查清单

## 1. 开头

- [ ] 已在开头对应当前版本
- [ ] 已补项目背景简介
- [ ] 已照顾第一次阅读该篇博客、第一次接触该项目的读者
- [ ] 已预留前端展示图或结构图占位
- [ ] 已在前几段说明这篇文章为什么值得单独写
- [ ] 已有一句可提前收住全文的核心判断

## 2. 风格与口吻

- [ ] 口吻以“我 / 我们”为主
- [ ] 已尽量减少“你 / 你们”
- [ ] 整体风格偏掘金成稿
- [ ] 保持实战 + 教学兼具，但教学味不过重
- [ ] 没有写成产品宣传稿
- [ ] 没有写成纯教程说明书

## 3. 正文表达

- [ ] 已回答“为什么这样设计”
- [ ] 已写清楚本版取舍和边界
- [ ] 已说明当前刻意没做什么
- [ ] 已尽量减少重复性叙事
- [ ] 章节承接顺着陌生读者的理解路径
- [ ] 没有明显“方案文档转写”口吻

## 4. 文件名与代码

- [ ] 首次出现的重要文件名或模块名，已补括号职责说明
- [ ] 读者只看文件名也能大致知道它负责什么
- [ ] 只保留少量关键代码
- [ ] 每段关键代码前已说明它解决什么问题
- [ ] 每段关键代码后已解释关键逻辑或设计意义

## 5. 图片与展示

- [ ] 至少保留 1 处图片占位
- [ ] 图片占位写清了要展示什么
- [ ] 开头优先放前端展示图、结构图或效果图

## 6. 结尾

- [ ] 已给出 GitHub 地址
- [ ] 已有轻量 Star 引导
- [ ] 已补 1 到 2 句后续路线
- [ ] 结尾语气自然，不像硬导流

## 7. 发布前最后一遍

- [ ] 我从第一次阅读这篇文章的视角顺读过一遍
- [ ] 我能在前 5 到 8 段内知道项目背景、本版主题和文章价值
- [ ] 我能看懂这版到底解决了什么问题
- [ ] 即使跳过代码，我也能理解这篇文章的工程价值
