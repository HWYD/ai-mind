# 架构分层规则

## 目标

帮助 `AI Mind` 在接入 Skill、MCP、Agent 和数据层能力时，仍然保持边界清晰。

## 分层判断顺序

当新增一个能力时，先依次判断：

1. 它是不是 Tool
2. 它是不是 Skill
3. 它是不是 MCP 接入问题
4. 它是不是 Agent 问题
5. 它是不是数据层问题

## 核心约束

- Tool：原子能力、可独立注册、可被多个上层能力复用。
- Skill：稳定任务模式或一组 Tool 的组合能力。
- MCP：外部能力接入标准或能力来源通道，不应让主 Runtime 到处知道外部系统细节。
- Agent：多步计划、阶段推进、继续决策。
- 数据层：持久化、查询、实体模型和长期记录。

## 设计偏好

优先选择：

- Definition + Registry
- 显式边界
- 可替换层
- 可记录、可解释的结构

避免：

- 主流程塞满 `if capability === xxx`
- 单个版本里同时推进过多层
- 没有长期文档就直接接复杂基础设施
