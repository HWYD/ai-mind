# Feature Specification: Image Generation Agent

**Feature Branch**: `[codex/v0.4.12-image-generation-agent]`

**Version**: `v0.4.12`

**Created**: 2026-07-28

**Status**: Planned

**Input**: User description: "通过 `/image` 显式入口提供单一文生图 Agent；图像模型固定使用 doubao-seedream-5.0-lite；Agent 先形成 ImageBrief，再生成、检查并最多修订一次生图提示词；本版本不使用 HITL，不做成本预估、图像编辑或专业图像工具链；服务器不保存图片二进制，只要求当前前端能够预览并下载生成结果。"

## Summary

AI Mind v0.4.12 增加一个边界明确的单用途 Image Generation Agent。用户通过 `/image` 显式提交自然语言描述，系统将原始需求整理为结构化 ImageBrief，生成面向固定图像能力的执行提示词，依据 ImageBrief 检查提示词是否遗漏或冲突，并在必要时最多自动修订一次，随后生成一张图片供用户在当前前端页面预览和下载。

本版本聚焦单次文生图闭环，不把普通聊天中的绘图表达自动路由为生图，不提供模型选择、人工审核、成本预估、多轮修图或专业图像处理能力。服务器不提供生成图片的长期二进制存储，历史页面刷新、临时结果过期和跨设备恢复不属于本版本保证。

## Clarifications

### Session 2026-07-28

- Q: 用户应看到多少 ImageBrief 和提示词优化信息？ → A: 展示只读的安全 ImageBrief 摘要，不展示初始或优化后的内部执行提示词，也不允许用户编辑或确认。
- Q: 一次提示词修订后仍存在阻断问题时应如何处理？ → A: 不调用生图模型，任务以可理解失败状态收口，并提示用户重新提交更清晰的 `/image` 描述。
- Q: 生图执行期间是否允许用户停止？ → A: 提供停止入口；停止后任务进入取消状态，尽力中止外部请求，并忽略任何迟到图片。
- Q: 同一浏览器会话是否允许并发生图？ → A: 同一浏览器会话同一时间最多一个活动生图任务；新请求被拒绝并提示等待或停止当前任务。
- Q: v0.4.12 的内容安全边界是什么？ → A: 依赖 Seedream 内容审核；AI Mind 只做输入格式校验、安全错误映射和敏感信息保护，不新增独立 Prompt 或视觉内容审核。

### Session 2026-08-02

- Q: 生图任务的每日调用上限如何控制？ → A: 每个浏览器 Session 每日最多 3 个被接受的新 `/image` 任务；IP 维度默认每日最多 10 个作为防刷上限（服务端可在 10–20 范围内调整）。普通聊天不消耗生图配额；幂等重放、无效请求和活动任务冲突不计数；已接受任务即使 Provider 后续失败仍计 1 次。

## Goals

- 让用户能够通过清晰、可发现的 `/image` 入口完成一次文生图任务。
- 在不要求用户掌握专业提示词写法的前提下，将自然语言需求整理为可追踪的 ImageBrief 和优化提示词。
- 对照 ImageBrief 发现提示词中的关键遗漏或冲突，并允许一次有界自动修订。
- 让成功生成的图片能够在当前页面显示并由用户下载。
- 为生成过程提供明确的进行中、完成和失败反馈。
- 保持普通聊天链路不受影响，不因用户在普通消息中表达绘图意图而自动触发生图。

## Non-goals

- 本版本不支持参考图、图生图、连续组图或一次生成多个候选。
- 本版本不支持图片编辑、局部重绘、扩图、去背景、抠图、超分或 Canvas。
- 本版本不支持用户选择图像模型，也不支持多 Provider 路由、自动降级或跨 Provider 重试。
- 本版本不使用 HITL，不在生成前要求用户确认 ImageBrief、提示词、费用或生成操作。
- 本版本不向用户展示初始或优化后的内部执行提示词；用户可见范围仅包含只读的安全 ImageBrief 摘要。
- 本版本不展示成本预估、费用确认或成本优化建议。
- 本版本不对生成结果执行视觉理解、OCR、审美评分或生成后的自动重画。
- 本版本不新增独立 Prompt 内容审核模型或生成图片视觉审核链；图像内容是否允许生成由固定生图服务的内容审核结果决定。
- 本版本不保证生成图片的长期保存、历史消息恢复、刷新后继续查看或跨设备访问。
- 本版本不把开放式、多轮 ReAct 循环作为产品能力；提示词自动修订必须有明确条件和次数上限。
- 本版本不允许普通聊天、Tasklist Agent、Delivery Chain 或其他 Agent 隐式调用生图能力。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - Generate an Image Through the Explicit Entry (Priority: P1)

用户希望根据一段自然语言描述生成图片。用户在聊天输入框中使用 `/image` 并提供描述后，系统识别这是一次独立的生图任务，自动完成需求理解和图片生成，并将结果显示在当前页面。

**Why this priority**: `/image` 到可见图片是本版本最核心、可独立交付的用户价值；没有这条闭环，其他提示词优化或状态展示都没有实际意义。

**Independent Test**: 在普通聊天页面输入一条合法的 `/image` 请求，验证系统只创建一次生图任务、只生成一张图片，并在当前页面显示该图片；普通聊天回答不会同时执行。

**Acceptance Scenarios**:

1. **Given** 用户位于可正常发送消息的聊天页面，**When** 用户提交带有非空描述的 `/image` 请求，**Then** 系统创建一条独立生图任务并开始处理，不同时进入普通聊天回答链路。
2. **Given** 一条生图任务正在执行，**When** 图片成功生成，**Then** 当前页面显示一张与本次任务关联的图片以及明确的完成状态。
3. **Given** 用户在普通消息中写下“帮我画一张图片”但没有使用 `/image`，**When** 用户发送该消息，**Then** 系统继续按普通聊天处理，不隐式启动生图任务。
4. **Given** 用户只输入 `/image` 或仅附带空白字符，**When** 用户提交请求，**Then** 系统不启动生图任务，并提示用户补充图片描述。

---

### User Story 2 - Build and Refine a Prompt from an ImageBrief (Priority: P1)

用户只需要表达想要的画面，不需要手工编写专业提示词。系统从原始描述形成结构化 ImageBrief，再生成执行提示词；如果执行提示词相对 ImageBrief 存在关键遗漏、明显冲突或不可执行表达，系统最多自动修订一次后进入图片生成。

**Why this priority**: ImageBrief 是用户意图与实际生成提示词之间的稳定事实边界。一次有界检查和修订能够体现 Agent 的条件决策，同时避免开放循环、重复生成和不可预测行为。

**Independent Test**: 分别提交信息完整、信息缺失和包含冲突描述的 `/image` 请求，检查 ImageBrief、提示词检查结论和修订计数；验证任何任务的提示词修订都不超过一次，且最终只调用一次图片生成。

**Acceptance Scenarios**:

1. **Given** 用户描述包含明确主体、场景和风格且不存在冲突，**When** 系统形成 ImageBrief 并检查执行提示词，**Then** 系统可以直接进入生成，提示词修订次数为零。
2. **Given** 初始执行提示词遗漏 ImageBrief 中的关键主体或约束，**When** 系统完成提示词检查，**Then** 系统依据结构化问题说明修订提示词一次，再进入生成。
3. **Given** 提示词已经执行过一次自动修订，**When** 再次检查仍发现非阻断性不足，**Then** 系统停止继续修订并进入生成，不形成第二次修订或开放循环。
4. **Given** 用户没有指定画幅、光照或其他可采用合理默认值的信息，**When** 系统形成 ImageBrief，**Then** 系统可以使用一致默认值，并将这些默认判断记录为 assumptions。
5. **Given** 用户明确提供了主体、场景、画面文字或排除要求，**When** 系统生成或修订执行提示词，**Then** 执行提示词不得无依据删除这些关键要求或加入与其冲突的要求。
6. **Given** 系统已经形成 ImageBrief，**When** 当前页面展示本次生图任务，**Then** 用户能够查看只读的安全 ImageBrief 摘要，但看不到初始或优化后的内部执行提示词，也不能通过该摘要编辑或确认任务。
7. **Given** 提示词已经执行过一次自动修订，**When** 再次检查仍发现关键主体、约束或能力边界方面的阻断问题，**Then** 系统不调用生图模型，以明确失败状态结束任务，并提示用户重新提交更清晰的 `/image` 描述。

---

### User Story 3 - Preview and Download the Temporary Result (Priority: P1)

图片生成成功后，用户希望立即查看结果并保存到自己的设备。系统在当前页面提供预览和下载操作，即使服务器没有长期图片存储能力，用户仍能完成本次任务。

**Why this priority**: 预览和下载是无服务器图片存储前提下的完整交付动作，也是用户保留生成结果的唯一可靠方式。

**Independent Test**: 完成一次图片生成，在当前页面查看完整图片并执行下载；验证下载文件可由常见图片查看器打开，并且下载内容与页面预览属于同一生成结果。

**Acceptance Scenarios**:

1. **Given** 生图服务返回了有效图片结果，**When** 当前页面加载该结果，**Then** 用户能够看到完整图片，而不是原始编码、内部地址或无法理解的数据。
2. **Given** 图片已经在当前页面成功加载，**When** 用户点击下载，**Then** 浏览器下载一份可正常打开的图片文件。
3. **Given** 图片结果只在有限时间内可用，**When** 用户看到生成结果，**Then** 页面明确提示该结果是临时的，并建议及时下载。
4. **Given** 临时结果已经过期或无法再次读取，**When** 用户尝试预览或下载，**Then** 页面说明结果已不可用，并提供重新发起 `/image` 请求的明确路径。
5. **Given** 当前页面已展示本次成功生成的图片结果，**When** 生成任务进入完成状态，**Then** 页面继续展示推荐问题快捷入口；用户点击任一推荐问题后，系统按普通提问链路提交该问题，不重复触发生图任务。

---

### User Story 4 - Understand Progress and Failure (Priority: P2)

生图可能比普通聊天耗时更长。用户需要知道系统正在理解需求、优化提示词、生成图片还是已经失败，并在失败时得到可执行的下一步，而不是长时间停留在无反馈状态。

**Why this priority**: 清晰状态能够降低重复提交和误解，但它不应扩大本版本的生成能力范围。

**Independent Test**: 分别模拟正常生成、输入无效、服务拒绝、临时网络错误、结果无效和结果过期，验证每种情况都有唯一且用户可理解的状态及后续操作。

**Acceptance Scenarios**:

1. **Given** 生图任务尚未完成，**When** 任务从需求理解进入提示词处理和图片生成，**Then** 用户能够看到与当前阶段一致的进度反馈。
2. **Given** 生图服务拒绝请求或返回不可用结果，**When** 系统收口任务，**Then** 用户看到安全、明确的失败信息，不暴露内部配置、密钥、内部提示词或原始服务错误。
3. **Given** 当前浏览器会话已经存在活动生图任务，**When** 用户再次提交 `/image`，**Then** 系统不创建第二个任务，并提示用户等待或停止当前任务。
4. **Given** 生图任务尚未完成，**When** 用户点击停止，**Then** 当前页面立即停止等待，任务进入取消状态，并且任何之后到达的图片都不会重新显示或将任务改回完成。
5. **Given** 当前浏览器会话的上一项生图任务已经完成、失败或取消，**When** 用户再次提交合法 `/image`，**Then** 系统接受新任务，并保持新旧任务身份和结果互不混淆。

### Edge Cases

- `/image` 后只有空白、换行或不可见字符。
- 用户描述非常短，无法直接确定场景或风格，但可以采用合理默认值继续生成。
- 用户描述内部存在互相矛盾的主体数量、风格、画幅或排除要求。
- 一次提示词修订后，用户描述中的关键主体、约束或能力边界冲突仍无法消除。
- 用户要求图片编辑、局部重绘、参考已有图片或去背景等本版本不支持的能力。
- 用户要求一次生成多张候选图或连续组图。
- 用户在生图任务执行期间离开页面、刷新页面或关闭浏览器。
- 用户点击停止时外部生图请求已经被服务接受，无法确认是否能够真正中止。
- 生图服务返回临时 URL，但 URL 无法访问、已经过期、指向的内容不是有效图片或图片体积超出安全限制。
- 生图服务返回成功状态但没有可展示的图片。
- 生图服务因内容安全策略拒绝用户请求或不返回图片。
- 生图服务对请求执行结果不明确，例如连接在确认成功前中断；系统不得静默创建无限重试或多次生成。
- 用户多次快速提交 `/image`；同一浏览器会话只有首个合法请求能够成为活动任务，其余请求应提示等待或停止当前任务。
- 用户在同一 Session 内达到每日生图配额，或同一 IP 达到防刷上限；系统应拒绝后续新任务并给出可理解的次日恢复提示，不得退回普通聊天链路。
- 图片可以预览但浏览器不能直接跨域下载；用户仍应通过产品提供的下载入口取得同一图片。
- 当前页面释放临时图片资源后，旧预览或下载入口不可继续使用。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-052-001**: 系统 MUST 仅通过 `/image` 显式入口启动本版本的生图任务；普通聊天内容不得隐式触发生图。
- **FR-052-002**: 系统 MUST 要求 `/image` 请求包含非空自然语言描述，并在描述为空时拒绝创建生图任务。
- **FR-052-003**: 系统 MUST 为每次被接受的 `/image` 请求创建稳定的任务身份，并将其状态、提示词处理过程和最终结果关联到同一任务。
- **FR-052-004**: 系统 MUST 将用户原始描述作为不可被后续步骤覆盖的输入事实保留到本次任务收口。
- **FR-052-005**: 系统 MUST 在生成图片前形成结构化 ImageBrief；ImageBrief 至少表达生成意图、主体、可选场景、可选构图、可选风格、可选光照与色彩、画面文字、必须满足的约束、需要避免的内容、可选画幅和系统 assumptions。
- **FR-052-006**: 系统 MUST 在用户未指定非关键画面信息时采用一致、可说明的默认值继续执行，并将新增默认判断记录为 ImageBrief assumptions，不得伪装成用户明确要求。
- **FR-052-007**: 系统 MUST 根据 ImageBrief 生成一份面向本次固定图像生成能力的执行提示词。
- **FR-052-008**: 系统 MUST 在图片生成前对照 ImageBrief 检查执行提示词，检查范围至少包含关键主体遗漏、约束遗漏、明显冲突、无依据新增要求和超出本版本能力的请求。
- **FR-052-009**: 提示词检查结果 MUST 使用有限、结构化的问题类型和修订建议表达；不得向用户或公共诊断输出模型的隐藏思维过程。
- **FR-052-010**: 当提示词检查发现可修复的关键问题时，系统 MUST 最多自动修订一次执行提示词；单个任务的自动提示词修订次数 MUST 不超过 1。
- **FR-052-011**: 系统 MUST 在提示词无需修订或一次修订完成后停止提示词优化，不得进入开放式自我反思或无限修订循环；任何 ImageBrief、PromptInspection 或修订结果未通过严格结构校验时，该次调用仍计入 `maxPlanningModelCalls`，任务必须以安全的规划失败状态终止，不得执行隐藏的结构修复调用、自动重试或图片生成。若下一步仍需要规划调用但计数已经达到 5，系统 MUST 在调用前以同一安全规划失败状态终止。
- **FR-052-012**: 单个已接受任务 MUST 最多执行一次实际图片生成；提示词检查和修订不得提前生成候选图片，也不得在生成结果返回后自动重新生成。
- **FR-052-013**: 本版本 MUST 固定使用图像模型 `doubao-seedream-5.0-lite`，并通过火山引擎 Agent Plan 专属端点 `https://ark.cn-beijing.volces.com/api/plan/v3/images/generations` 调用；这两个值不得进入用户选择、普通聊天模型路由或多 Provider 路由。
- **FR-052-014**: 系统 MUST 在图片生成期间向当前页面提供可理解的任务阶段，至少能够区分已接收、需求整理、提示词处理、图片生成、结果准备、完成和失败。
- **FR-052-015**: 系统 MUST 在图片生成成功后，让用户在当前页面预览一张图片，并提供下载同一图片结果的操作；图片必须具有由公开 ImageBrief 摘要生成的安全替代文本，下载操作必须可通过键盘访问且具有明确名称，加载、完成和失败状态必须通过语义化状态或 `aria-live` 向辅助技术表达。
- **FR-052-016**: 系统 MUST 将生成图片视为临时结果，并在结果展示区域明确提示用户及时下载；不得承诺刷新后、临时来源过期后或跨设备恢复图片。系统 MUST 将结果可读取期限限制为 ready 后最多 10 分钟，并在 provider 提供更早可靠过期时间时取更早值；以该 `expiresAt` 强制执行逻辑过期，并通过有界清理在正常图片任务仓储操作和临时结果读取路径上将过期 provider URL 置空并把结果标记为 `expired`；即使物理清理尚未运行，过期结果也不得再次读取。
- **FR-052-017**: 系统 MUST 在不长期保存图片二进制的前提下交付预览和下载；图片二进制不得作为聊天文本、公开诊断或流式状态事件内容交付。
- **FR-052-018**: 系统 MUST 在读取临时图片结果时校验任务所有权，防止其他会话通过猜测任务身份读取图片。
- **FR-052-019**: 系统 MUST 拒绝超出安全体积、类型或来源边界的图片结果，并向用户提供安全的失败反馈。
- **FR-052-020**: 系统 MUST 对临时结果过期、结果缺失、结果无效、服务拒绝和无法确认的生成状态提供不同且可定位的失败结果；不得暴露 API Key、session cookie、内部提示词、provider config 或原始服务错误。过期结果的重新发起说明必须处于语义化错误区域，并能被辅助技术识别。
- **FR-052-021**: 系统 MUST 在无法确认上一次图片生成是否已被服务接受时停止自动再次生成，并向用户报告结果状态不明确，避免单个任务产生不可控的重复图片。
- **FR-052-022**: 系统 MUST 保持现有普通聊天、Tasklist Agent 和 Delivery Chain 的入口及结果语义不变。
- **FR-052-023**: 系统 MUST 不在本版本提供 HITL、生成前确认、费用确认、成本预估或生成后自动质量修正。
- **FR-052-024**: 系统 MUST 对编辑、局部重绘、扩图、去背景、参考图、多候选和组图请求给出能力边界说明，不得静默降级成含义不同的文生图操作。
- **FR-052-025**: 系统 MUST 为任务完成和失败提供安全的可观察信息，至少能够关联任务身份、当前阶段、各阶段安全耗时、从请求接受到结果就绪的服务端总耗时、是否发生过一次提示词修订和最终结果状态，但不得输出内部运行态或敏感信息。
- **FR-052-026**: 系统 MUST 向用户展示只读的安全 ImageBrief 摘要；该摘要不得包含初始或优化后的内部执行提示词，不得提供编辑、确认或恢复入口，也不得暴露内部运行态或敏感信息。
- **FR-052-027**: 当一次提示词修订后仍存在关键主体、约束或能力边界方面的阻断问题时，系统 MUST 在调用图像生成能力前以失败状态收口，并提示用户重新提交更清晰的 `/image` 描述；不得忽略、删除阻断要求或退回原始描述继续生成。
- **FR-052-028**: 系统 MUST 允许用户在生图任务完成前明确停止任务；停止操作必须可通过键盘访问并具有明确可访问名称。停止后当前页面 MUST 立即停止等待，任务 MUST 收口为取消，并尽力中止尚可取消的外部请求。外部服务随后返回的迟到图片不得展示、下载或将已取消任务改回完成状态。
- **FR-052-029**: 同一浏览器会话同一时间 MUST 最多存在一个活动生图任务；活动任务存在时的新 `/image` 请求 MUST 被拒绝并提示用户等待或到原任务卡停止当前任务，不得创建第二个停止控件或第二个任务消息。上一任务完成、失败或取消后，系统 MUST 允许该会话创建新的生图任务。
- **FR-052-030**: 系统 MUST 将固定生图服务的内容审核结果作为本版本是否允许生成的最终判定；AI Mind MUST 对请求执行格式和能力边界校验，并将内容安全拒绝映射为用户可理解的安全错误。系统不得向用户暴露原始审核响应、内部策略、provider config 或敏感信息。
- **FR-052-031**: 图片生成任务成功完成后，系统 MUST 在当前助手结果消息中保留可访问的推荐问题快捷入口；点击推荐问题 MUST 复用普通提问提交链路，不得创建新的生图任务或绕过现有输入校验。
- **FR-052-032**: 系统 MUST 对被接受的新 `/image` 任务执行独立的每日生图配额：同一浏览器 Session 默认最多 3 次，同一 IP 默认最多 10 次；IP 上限 MUST 支持由服务端在 10–20 范围内调整。普通聊天、Tasklist 和 Delivery Chain 请求不得消耗生图配额。
- **FR-052-033**: 生图配额 MUST 以新任务为计数单位；无效/不支持请求、幂等重放和活动任务冲突不得计数，已接受任务即使后续规划失败、取消或 Provider 失败仍计数 1 次；达到任一上限后，后续 `/image` MUST 返回安全的限流错误，不得创建任务或进入普通聊天链路。
- **FR-052-034**: 生图配额 MUST 按服务端自然日边界计算，并在次日自动恢复；限流实现不得向客户端暴露 Session Cookie、内部计数键或 Provider 配额细节。

### Implementation-Ready Rules

#### Command, Input and Structured-output Bounds

- 只有首个非空白 token 为精确 `/image` 的消息进入生图入口；`/imagex`、内嵌 `/image` 和普通文本中的绘图表达继续走普通聊天。
- 服务端先将描述规范化为 Unicode NFC，再去除首尾 Unicode whitespace；规范化后描述必须为 `1..2000` 个 Unicode code points。空值、超长值和只含空白/不可见分隔符的描述在创建 `StreamRun` 前被拒绝。
- ImageBrief 与 `PublicImageBriefSummary` 使用同一安全字段边界：`intent` 至多 160 字符；`subjects` 至多 8 项、每项至多 120 字符；`scene`、`composition`、`style`、`lightingAndColor` 各至多 240 字符；`visibleText` 至多 8 项、每项至多 120 字符；`mustInclude`、`avoid` 各至多 12 项、每项至多 160 字符；`assumptions` 至多 8 项、每项至多 160 字符。超出边界的结构化模型输出视为 `IMAGE_PROMPT_PLANNING_FAILED`。
- 产品内部仅使用 `square`、`landscape`、`portrait` 三个抽象画幅：未指定时为 `square`。T003 必须把这三者映射为固定 Provider 已确认的 `size` 字符串；未确认映射不得由实现自行猜测或发送请求。

#### Capability and Prompt-decision Rules

- 一个描述同时包含文生图意图和编辑、局部重绘、扩图、去背景、参考图、多候选或组图等非目标能力时，整个请求以 `IMAGE_CAPABILITY_UNSUPPORTED` 终止，禁止静默抽取其中文生图片段继续生成。
- 可修复问题仅限于：可由 immutable raw description 和 ImageBrief 直接恢复的主体、约束或画面要求遗漏/误写；这类问题可修订一次。阻断问题包括用户主体身份或数量、精确画面文字、`mustInclude`/`avoid`、能力边界或相互矛盾要求仍无法确定；阻断问题不得生成。非阻断问题只涉及用户未指定的场景、构图、风格、光照、色彩或画幅默认值，不得触发第二次修订。
- 系统只可假设用户未指定的场景、构图、风格、光照、色彩和抽象画幅；不得假设主体身份、数量、年龄、品牌/事实、画面文字、必须满足条件、避免条件或不支持能力。任何会改变这些禁止假设项的歧义都必须在生图前阻断。
- coordinator 在发出外部 HTTP 请求前，以同一原子状态转换将 `imageGenerationCount` 从 `0` 写为 `1` 并进入 `generating`。该时点之后即使取消或网络中断，任务也绝不自动再次生成；在该时点之前取消则外部调用次数为 0。

#### Presentation, Recovery and Cancellation Rules

- `ImageBriefPart`、`WorkflowProgressPanel`、`ImageResultPart` 依次出现在同一 assistant message 内；所有卡片宽度不超过消息容器。结果图在桌面端最大可视宽度为 640px、移动端为容器 100%，保持原始画幅。
- 临时提示“临时结果，请及时下载”从 ready 事件出现起至 Blob 成功加载和下载可用期间持续展示；结果过期、取消或 Blob 加载失败后改为对应失败提示，不再显示可下载状态。
- 下载按钮仅在同源内容读取成功、Blob 已创建、任务未取消且结果未过期时启用；loading、取消、过期、读取失败和无效结果时禁用或不渲染。
- 当前页面在已加载 Blob 后可继续预览/下载直到组件卸载；刷新、关闭标签页、stable local snapshot 恢复或 StreamEvent retention 清理后都不保证重建图片卡。若服务器仍保留未过期的 `ImageGenerationRun` 元数据，内容 route 可独立于事件 payload 返回图片，但产品不承诺刷新恢复该入口。
- 1 秒取消标准仅约束客户端从停止动作到显示 `cancelled` 的确认时间；Provider HTTP abort 是 best-effort，不构成 Provider 已停止或不计费的承诺。

### Key Entities _(include if feature involves data)_

- **Image Generation Request**: 用户通过 `/image` 明确提交的一次生图意图，包含稳定任务身份、不可变原始描述和所属会话。
- **ImageBrief**: Agent 对原始描述的结构化理解，是执行提示词生成和检查的需求事实来源；包含用户明确要求、合理默认值及 assumptions。用户只能看到其只读安全摘要，完整内部表示和执行提示词不属于 public DTO。
- **Image Prompt Draft**: 根据 ImageBrief 形成的待执行提示词，包含初始版本、检查结论和最多一个修订版本。
- **Prompt Inspection**: 对执行提示词与 ImageBrief 一致性的结构化检查结果，包含有限问题类型、是否需要修订和修订建议，不包含隐藏思维过程。
- **Image Generation Run**: 一次受控生图任务的生命周期，记录阶段、提示词修订次数、实际生成次数、最终状态和安全诊断关联。
- **Temporary Image Result**: 生图服务返回的临时图片引用及展示所需元数据；图片二进制不由 AI Mind 长期保存。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-052-001**: 在合法 `/image` 请求的验收测试中，100% 的任务只进入生图链路一次，且不会同时产生普通聊天回答。
- **SC-052-002**: 在不包含 `/image` 的普通聊天验收测试中，100% 不会启动生图任务，现有普通聊天行为保持不变。
- **SC-052-003**: 在信息完整、信息缺失和包含可修复冲突的提示词测试集中，100% 的任务形成结构化 ImageBrief，且任何任务的自动提示词修订次数不超过 1。
- **SC-052-004**: 在所有成功生成场景中，每个任务只产生一张图片并只执行一次实际图片生成；生成后自动重画次数为 0。
- **SC-052-005**: 在临时图片来源仍然有效的成功场景中，100% 的结果能够在当前页面预览，并能够下载为常见图片查看器可打开的文件；图片、下载、停止、加载、失败及过期恢复说明均能通过语义化角色与可访问名称被键盘和辅助技术识别。
- **SC-052-006**: 95% 的正常成功请求从服务端接受合法 `/image` 请求开始，到当前页面的 `ImageResultPart` 完成同源图片读取、Blob 创建并触发图片成功加载为止，不超过 120 秒；该端到端口径包含 ImageBrief、Prompt 处理、Seedream 调用、临时图片代理读取和浏览器解码。超过时限的任务必须显示仍在处理或明确失败，不能无状态停滞。自动化测试必须验证计时边界和超时状态转换，单次真实 smoke 只验证链路并记录样本耗时，不单独证明 95% SLO。
- **SC-052-007**: 对空描述、不支持能力、服务拒绝、无效图片、临时结果过期和状态不明确等验收场景，100% 提供可理解且可执行的后续说明，并且不泄露敏感信息。
- **SC-052-008**: 在跨会话访问测试中，100% 的未授权临时图片读取和下载请求被拒绝，且不会泄露图片内容或内部服务地址。
- **SC-052-009**: 当前页面释放图片资源、刷新页面或临时来源过期后，产品不会错误承诺图片仍可恢复；所有结果展示均包含临时性提示。
- **SC-052-010**: 现有普通聊天、Tasklist Agent、Delivery Chain 和流式消费的相关回归验收保持通过，用户可见行为不因 `/image` 新入口发生改变。
- **SC-052-011**: 在所有成功形成 ImageBrief 的任务中，100% 向用户展示只读安全摘要，且任何用户可见响应都不包含初始或优化后的内部执行提示词。
- **SC-052-012**: 在一次提示词修订后仍存在阻断问题的验收场景中，100% 的任务在实际生图前停止，实际图片生成次数为 0，并向用户提供重新描述的明确入口。
- **SC-052-013**: 在用户主动停止的验收场景中，100% 的当前页面在 1 秒内结束等待并显示取消状态；任何迟到图片都不会被展示、下载或覆盖取消终态。
- **SC-052-014**: 在同一浏览器会话并发提交 3 个 `/image` 请求的验收场景中，100% 最多只有一个活动任务和一次实际生图；其余请求均收到等待或停止当前任务的明确提示。
- **SC-052-015**: 在固定生图服务拒绝内容的验收场景中，100% 的任务以安全失败状态收口，不展示图片，不自动绕过审核重试，并且用户可见响应不包含原始审核信息或敏感配置。
- **SC-052-016**: 在图片生成成功并展示结果的验收场景中，推荐问题快捷入口持续可见且可通过语义化分组与按钮访问；点击后提交一次普通问题，不产生第二次图片生成。
- **SC-052-017**: 在配额验收场景中，同一 Session 连续提交 3 个被接受的新 `/image` 任务后，第 4 个请求 100% 被拒绝并返回“今日生图次数已用完”语义；普通聊天仍可正常提交。
- **SC-052-018**: 在 IP 防刷验收场景中，同一 IP 的第 11 个被接受新 `/image` 任务 100% 被拒绝（默认上限 10）；配置上限调整为 20 后，第 20 个允许、第 21 个拒绝，且不同 Session 共享该 IP 计数。
- **SC-052-019**: 在配额计数边界验收场景中，无效请求、幂等重放和活动任务冲突不增加生图计数；已接受任务的规划失败、取消或 Provider 失败仍保留一次配额消耗。

## Assumptions

- v0.4.12 只面向当前已有会话用户，不新增账号体系、跨用户共享或公开图片链接。
- 图像生成能力固定为 `doubao-seedream-5.0-lite`，服务地址固定为火山引擎 Agent Plan 专属端点 `https://ark.cn-beijing.volces.com/api/plan/v3/images/generations`；目标账号的服务开通状态和专属接口请求/响应细节需在 implementation 前通过 smoke test 确认，但不得因此替换模型或端点。
- v0.4.12 没有登录用户体系，Session Cookie 作为产品配额身份，IP 作为防刷边界；配额存储沿用当前服务端限流实现，进程重启和多实例一致性不在本次小需求内保证。
- `doubao-seedream-5.0-lite` 的服务端内容审核是本版本的生成安全依赖；AI Mind 不在本版本增加第二套 Prompt 或视觉内容审核模型。
- ImageBrief 和提示词处理可以复用 AI Mind 已有的对话模型能力；图像生成模型只负责最终图片生成。
- 本版本默认每个任务生成一张图片，不提供候选数量配置。
- 用户未指定画幅时采用统一默认画幅；具体默认值在 planning 阶段作为产品默认参数确定。
- 服务器没有 OSS、S3 或等价对象存储，且当前 Web 容器没有用于图片文件的持久卷。
- 系统可以保存任务状态和临时图片引用等小型元数据，但不保存生成图片二进制。
- 临时图片的可读取有效期取可靠 provider expiry 与结果 ready 后 10 分钟中的更早者；provider 未提供可靠 expiry 时使用 ready 后 10 分钟。用户需要在当前页面可用期间完成下载。
- 用户刷新或关闭页面即可能失去当前图片预览；如果临时来源仍有效，系统可以重新读取，但本版本不保证该行为。
- 本版本所称的提示词“自动修正”仅指生成前对照 ImageBrief 的一次有界修订，不代表生成后视觉评审或再次生图。
