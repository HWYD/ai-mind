| D-017 | 所有 Tool 的业务参数可由用户或模型生成；统一经 schema、工具语义、outbound-secret 与目标 policy 校验。参数错误由模型下一 Action 以新参数修正；同参 transport retry 仅适用于 retryable 瞬态错误。                                                                                                                                                              | 参数是查询候选而非外部事实。固定 Tool allowlist、Key/endpoint/serverId、public URL policy、预算、Trace 脱敏和 observation-based answer 继续构成安全边界。                                                                                                                                                     |
| D-018 | 面向用户的 Trace 总标题只反映 terminal lifecycle：completed constrained Run 显示“已完成思考”，`constrained` 仍保留为内部收口与 Memory eligibility 语义；受限 finalizer 继承 Tool result facts rule。                                                                                                                                                         | 避免把已正常输出最终回答的 Run 误报为失败，同时不隐藏具体 Tool 的空结果或失败。路线未返回距离/时长时不得由坐标、直线距离或经验推算。                                                                                                                                                                          |
| D-019 | **Superseded by D-021**：原策略只让已携带 HTTP/Host 分类的 timeout、connection、429、5xx 重试，MCP `isError` 统一不可重试。                                                                                                                                                                                                                                  | 高德 MCP 可以用 `isError` 表达短时频率限制；不能再把这一传输形态直接等同于参数或权限错误。                                                                                                                                                                                                                    |
| D-020 | `amap-maps` 在 MCP Client Manager 使用进程内、按 `serverId` 共享的批次调度：每批最多 3 条，当前批次全部 settled 后冷却 800ms，再启动下一批。全局 General ReAct 并发、20 秒 attempt、retry 与 adapter 语义保持不变。                                                                                                                                          | 真实 POI 详情验证证明更短的 500ms 冷却已为 9/9 成功；用户选择 800ms 作为更保守的实际配置，因此本次只更新值与确定性断言。非受控超过三条突发曾安全失败且冷却后恢复。批次屏障避免普通 semaphore 在请求提前返回时立即补位造成的突发。该保护只覆盖单进程，非账号级或跨实例限流。                                   |
| D-021 | AMap adapter 仅在内存中把 `isError` 归一为安全失败信号：先识别权限、额度耗尽和 4xx 参数等不可重试信号；明确的频率限制、服务繁忙、timeout、connection、429、5xx 才沿用 Runtime 最多两次指数退避；已通过 schema 但无法归类的只读 `isError` 最多兜底一次；空或 malformed 结果不重发。Runtime 对 `MCPHostError.retryable=false` 保持不可重试，即使同时携带 429。 | 高频调用可能以协议层 `isError` 而非 HTTP 429 返回。一次保守兜底能覆盖短暂上游拒绝，又不会把无效请求或额度耗尽放大为三次调用。原始正文只在 adapter 短暂解析，绝不进入 Trace、StreamEvent、Memory、快照、普通日志或持久化。                                                                                     |
| D-022 | General ReAct 的单 Run `maxLogicalToolCalls` 由 18 调整为 21，仍作为跨全部 Tool-bearing rounds 的累计 admission 上限；不调整 9 个 rounds、3 并发、4 个 retry permits、20 秒 attempt、235 秒 loop / 240 秒 pre-finalization deadline 或 48,000 字符 observation 总预算。                                                                                      | 21 是三条并发的完整七批容量，支持一次 Action 中更多相互独立的查询而不放宽瞬时并发、重试、权限或 public-data 边界。该值不是每轮额度，九个 rounds 不会形成 189 次调用；连续单调用工作流仍受 9 rounds 限制。                                                                                                     |
| D-023 | constrained finalizer 的正文输出不受应用内 deadline 限制。`preFinalizationDeadlineMs=240_000`（235 秒 loop + 5 秒 handoff reserve）只约束收口前阶段；finalizer 传递 `timeoutMs: null` 以绕过项目 Provider 默认 timeout，并保留父级显式取消 signal。chat service 不再设置 270 秒外层 abort，也不把 pre-finalization deadline 交给 durable projection。        | 实际 Run 中 finalizer 的首 token 可消耗 24 秒以上，原 30 秒 phase timer 会在正文刚开始后截断。仅延长到 270 秒仍会让慢首 token 或长正文失败，且投影 deadline 会污染无时限收口。`null` 是有意选择，区分“沿用配置 timeout”与“本 Runtime 不施加 timeout”；上游 Provider、网关或进程本身的外部限制仍可能终止连接。 |

## Supersession boundary

ADR-0019 中“remote MCP Tool 不 discovery”的安全原则继续成立；其中“当前七个固定工具”的枚举只描述 v0.6.1 已实现状态。v0.6.2 实施验收后，必须在同一版本收口中把 ADR-0019、Capability Surface 和部署文档的当前事实同步更新，并明确本版增加的是静态授权的远程工具，而非开放 discovery。
