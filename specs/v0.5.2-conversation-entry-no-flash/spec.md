# Feature Specification: Conversation Entry Without Scroll Flash

**Version**: `v0.5.2`
**Feature Branch**: `main`（用户指定主工作区）
**Created**: 2026-08-21
**Status**: Draft
**Input**: 用户选择或刷新恢复既有聊天会话时，应先看到最新消息；加载过程不得先显示历史顶部或其他会话内容，再产生可感知的滚动跳变。既有会话的本地选择不得等待服务端偏好持久化。消息滚动必须独立于页面文档滚动，并为后续尾页 cursor 分页保留稳定的消息视口。

## Summary

v0.5.2 改进 AI Mind 的既有会话进入体验。无论用户从桌面侧栏、移动会话抽屉选择历史会话，还是刷新后恢复上次会话，长历史都应从加载骨架直接进入最新内容位置。既有会话选择先在本地生效，并优先显示该会话的有效本地快照；服务端仅在后台确认选中偏好和会话可用性，失败时保留本地选择并在后续恢复时重试。服务端不可用时，用户仍可在已经存在的本地会话之间切换，但不能新建、删除或发送。独立消息视口必须占满聊天列可用高度；Composer 悬浮在其底部，消息末尾使用 Composer 的真实动态高度留出安全区。用户不应看到历史顶部、前一条会话的残留内容、等待选中偏好 POST 的中间态、延后插入的推荐问题或平滑滚动过程。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 打开历史会话时直接看到最新内容 (Priority: P1)

作为继续既有任务的用户，我希望打开长历史会话后先看到最近一轮对话，以便立即继续，而不是手动滚过历史内容。

**Why this priority**: 这是本版本的核心使用场景，直接影响每次会话切换与刷新恢复的效率。

**Independent Test**: 准备一条高度超过可视区域的完整会话，切换至该会话或刷新后恢复它，确认首个可见的真实消息状态位于最新内容处。

**Acceptance Scenarios**:

1. **Given** 一条历史消息超过可视区域的已完成会话，**When** 用户从桌面侧栏或移动抽屉选择它，**Then** 加载骨架直接替换为靠近输入区的最新消息，用户不会看到历史顶部或向下滚动动画。
2. **Given** 浏览器或 Electron 恢复了上次选中的长会话，**When** 会话内容加载完成，**Then** 用户首先看到的是真实历史中的最新内容。
3. **Given** 目标会话存在有效本地快照且服务端选中偏好请求尚未完成，**When** 用户选择该会话，**Then** 本地选择和该快照立即进入既有的隐藏定位流程，不展示前一会话内容。

---

### User Story 2 - 阅读历史时位置保持由用户控制 (Priority: P2)

作为正在回看历史的用户，我希望进入会话后的滚动位置只由我的阅读操作控制，避免非流式 UI 变化把我拉回底部。

**Why this priority**: 自动定位只应解决“进入会话”的起点问题，不能干扰用户的主动阅读。

**Independent Test**: 打开长会话后上滑阅读，再点击当前会话、聚焦输入框或触发非流式布局变化，确认页面不自动回到底部，且既有“回到底部”操作仍可用。

**Acceptance Scenarios**:

1. **Given** 用户已在当前会话中上滑查看历史，**When** 用户再次点击当前会话或操作输入框，**Then** 阅读位置保持不变。
2. **Given** 用户在流式输出期间主动上滑，**When** 输出继续到达，**Then** 保持现有的停止自动跟随和“回到底部”恢复行为。

---

### User Story 3 - 异步恢复不展示错误内容 (Priority: P3)

作为在网络不稳定环境中切换会话的用户，我希望快速切换、只读本地缓存、重试和新建会话首轮生成都不会显示错误会话的内容或引入额外闪动。

**Why this priority**: 会话内容异步恢复，错误归属会造成明显混乱；新建会话的流式首轮必须保持连续。

**Independent Test**: 延迟会话 A 的恢复后立刻切换到 B，并分别模拟本地快照、恢复失败后重试和草稿首轮晋升，确认只显示当前会话的正确状态。

**Acceptance Scenarios**:

1. **Given** 会话 A 的恢复尚未完成，**When** 用户切换到会话 B，**Then** A 的延迟结果不得显示或改变 B 的位置。
2. **Given** 当前会话只能从本地只读缓存恢复，**When** 内容准备完成，**Then** 仍直接显示该会话的最新缓存内容。
3. **Given** 用户在草稿会话发送首条消息，**When** 该会话被提升为正式会话并开始流式输出，**Then** 已显示的本轮内容持续可见，不出现历史加载骨架或二次定位。
4. **Given** 用户已在本地选择会话 B，**When** 后台持久化服务端选中偏好失败，**Then** 页面保持会话 B 和其可用本地历史，不回退到会话 A；下次注册表恢复或刷新时重试确认。
5. **Given** 服务端注册表不可用但本地已缓存会话 A 和 B，**When** 用户选择 B，**Then** B 立即成为当前会话且不发起新的注册表写请求；新建、删除与发送仍保持禁用。
6. **Given** 历史会话的最新 assistant 回复满足推荐问题展示条件，**When** 该会话首次可见，**Then** 推荐问题与回复处于同一次真实历史揭示中，不因后台选中偏好确认结束而在稍后插入。
7. **Given** 用户快速依次选择会话 A 和 B，**When** A 的本地索引写入或 selected-preference POST 尚未完成，**Then** 最终本地索引和服务端选中偏好都收敛为 B，且 A 的过期写入不得在后完成后覆盖 B。

### Edge Cases

- 会话内容短于可视区域时，进入行为不得产生空白、滚动动画或额外提示。
- 会话恢复失败时，只显示既有错误状态；成功重试后才显示对应会话的最新内容。
- 同一会话重复点击不视为一次新的会话进入，不重置用户阅读位置。
- 本地快照已显示后，服务端确认成功、不可用或网络失败都不得再次发布进入 token、重新隐藏内容或重复到底定位。
- 从无原生滚动条的骨架切到有原生滚动条的长历史时，Composer 的横向位置不得变化。
- 页面在桌面浏览器、移动浏览器和 Electron 远程工作页使用相同的会话进入语义。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-521**: 系统 MUST 在用户进入一条既有会话时，仅在独立消息视口内将首次可见的真实历史内容定位到该会话的最新消息区域。
- **FR-522**: 系统 MUST 在会话内容尚未可安全显示前只展示加载状态，不得展示前一会话内容、目标会话历史顶部或随后可感知的滚动跳变。
- **FR-523**: 系统 MUST 对侧栏选择、移动抽屉选择、刷新恢复和成功重试采用一致的既有会话进入行为。
- **FR-524**: 系统 MUST 在用户完成会话进入后保留其主动阅读位置；重复选择当前会话、输入框交互和非流式 UI 变化不得自动将页面拉回底部。
- **FR-525**: 系统 MUST 保持现有流式自动跟随、用户上滑锁定和“回到底部”恢复语义，不得因会话进入行为退化。
- **FR-526**: 系统 MUST 防止过期会话恢复结果影响当前选中会话的内容或位置。
- **FR-527**: 系统 MUST 让草稿会话首次晋升为正式会话时的流式内容连续显示，不将其误判为历史会话恢复。
- **FR-528**: 系统 MUST 让独立消息视口占满聊天列的完整可用高度；Composer MUST 悬浮在其底部而不缩短该视口，因此消息滚动条覆盖完整消息区域。Composer 卡片之外的悬浮层空白区域不得截获消息视口的滚动手势，且浮层的底部渐变遮罩必须遮住其后的消息内容。
- **FR-529**: 系统 MUST 使用 Composer 的真实动态高度作为消息内容末尾安全区，并额外保留 54px 底部间距（比原有间距增加 30px），保证最新消息不会被悬浮 Composer 覆盖；不得使用估算值、消息末尾锚点或 document scroll。
- **FR-532**: 系统 MUST 使 Composer 卡片与消息内容列左右边缘严格对齐；当消息视口出现原生滚动条时，Composer 必须使用该滚动条的实际宽度调整右边界，不得依赖固定平台像素值。
- **FR-533**: 系统 MUST 针对每一个未消费的历史会话就绪 token，在首次揭示前重新完成原生 scrollbar 宽度到 Composer 布局的同步；不得复用骨架或上一会话的宽度缓存。由此引起的 Composer 高度变化必须参与隐藏期内的最终到底定位。
- **FR-534**: 系统 MUST 在用户选择既有会话的同一交互周期内先更新本地选中会话及既有本地索引，再异步持久化服务端选中偏好；服务端持久化不得延迟目标会话的 hydration 或让前一会话继续作为当前内容显示。
- **FR-535**: 系统 MUST 在目标会话存在有效本地消息快照时，于该快照读取完成后立即标记 hydration 为 ready 并发布一次历史进入 token；后续服务端验证只能更新可用性/只读提示，不能再次发布 token 或替换当前本地展示源。
- **FR-536**: 系统 MUST 在唯一消息视口本身稳定预留原生 scrollbar gutter，使骨架、短内容和长内容之间的溢出状态变化不改变 Composer 的可用横向宽度或卡片位置；不得以强制显示空滚动条替代此策略。
- **FR-537**: 系统 MUST 将“选择已经存在的本地会话”与“新建、删除、发送等要求服务端可写的操作”分开控制；注册表只读缓存或选中偏好后台确认不得禁用前者。
- **FR-538**: 系统 MUST 将已完成历史回复的推荐问题纳入首次真实历史的隐藏布局和揭示；后台选中偏好确认进行中不得改变推荐问题的存在性或引入第二次内容高度增长。
- **FR-539**: 系统 MUST 将本地索引写入与 selected-preference POST 作为同一条非阻塞、按最新选择合并的串行后台链路；较早选择的未完成写入不得在较晚选择之后覆盖本地索引或服务端偏好。
- **FR-530**: 系统 MUST 在 Composer 高度变化前用户位于消息视口底部时重新对齐最新消息；用户已上滑阅读历史时不得写入其 `scrollTop`。
- **FR-531**: 系统 MUST 在历史消息卡片、Markdown 或字体等后续布局重排改变消息内容高度时，保持仍处于底端的消息视口对齐其新的真实末尾；已上滑阅读的用户不得因此改变位置。

### Key Entities

- **会话进入呈现状态**: 当前选会话从加载状态、可定位内容到可见内容的临时 UI 状态；仅用于本地呈现，不作为会话历史数据保存。
- **历史内容归属**: 当前渲染消息所属的会话标识，用于阻止延迟结果覆盖或展示在错误会话中。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-521**: 对高度超过一个可视区域的历史会话，桌面、移动与 Electron 的切换和刷新恢复场景中，首个可见真实历史状态均包含最新一轮消息区域，不出现历史顶部。
- **SC-522**: 在正常速度与 4 倍 CPU 降速的人工验证中，历史会话加载仅呈现“加载状态 → 最新内容”两个可见阶段，不出现“历史顶部 → 最新内容”的额外阶段。
- **SC-523**: 自动化测试覆盖会话切换、刷新恢复、只读缓存、重试、快速 A→B 切换、重复点击当前会话和草稿晋升，并验证所有场景的会话归属与位置行为。
- **SC-524**: 现有流式用户上滑锁定与手动回到底部相关回归测试继续通过。
- **SC-525**: 自动化测试证明首次进入、流式跟随和“回到最新”只修改消息视口；Composer 高度变化时安全区使用真实测量值，并遵循贴底跟随、上滑不打扰规则。
- **SC-526**: 自动化测试证明选中会话在服务端选中偏好请求未完成及失败后仍立即保持目标会话；有效本地快照在服务端验证完成前已 ready，且整个验证过程只产生一次进入 token。
- **SC-527**: 自动化与手工几何验证证明消息视口在短/长内容切换时保留稳定原生 gutter，Composer 与消息内容列的左右边缘不发生横向位移。
- **SC-528**: 自动化测试证明服务端注册表不可用时，用户可在两个已缓存会话之间立即切换且不触发新的 registry 写请求；新建、删除、发送仍不可用。
- **SC-529**: 自动化测试证明后台选中偏好确认未结束时，已完成历史回复的推荐问题已经存在于隐藏的首次揭示树中，确认结束不新增该推荐问题节点或改变消息区高度。
- **SC-530**: 自动化测试证明快速 A→B 选择时，乱序完成的本地索引写入和 selected-preference POST 最终均收敛到 B。

## Assumptions

- “进入会话”包含主动选择和页面刷新后的上次会话恢复，不包含重复选择当前会话。
- 会话没有未读游标或阅读位置偏好；v0.5.2 固定以最新内容作为进入位置。
- 本版本不增加服务端 API、数据库字段、Stream DTO、cookie、Electron IPC、本地持久化字段或 key；仅在现有本地会话索引和 localStorage 中即时更新已存在的选中会话值。
- 本版本不接入尾页 cursor 分页、向上加载或虚拟列表；后续版本在同一消息视口上接入端锚定虚拟化，不重做本版页面布局。
- 现有消息卡片继续为图片等异步内容预留稳定尺寸；本版本不等待任意远程资源完成后才显示会话。
