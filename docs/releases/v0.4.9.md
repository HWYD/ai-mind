# v0.4.9 Release Note

**状态**：Release candidate，等待已提交变更集上的 GitHub Actions 成功结果作为最终发布证据。

## 摘要

v0.4.9 为 pnpm/Turborepo workspace 增加了可执行的 Monorepo 边界治理和分层 CI 验证能力。

## 主要变化

- 强制使用 `@ai-mind/*` workspace 身份，并校验依赖方向、公共 `exports` 边界和源码 import 访问。
- 新增 stable、integration、manual external 三类 test lane，并为它们配置对应的 Turbo cache 策略。
- 将 CI 拆分为无状态的 `stable-validation` job，以及依赖它成功后才运行的 PostgreSQL `stateful-integration` job。
- 新增 workspace boundary、governance regression 和 test-lane 诊断命令，便于快速定位失败归属。
- 简化本地开发命令：`pnpm dev` 是默认启动路径；`pnpm dev:watch` 使用 Turbo 管理 stream-core watch 任务，不再依赖 `npm-run-all2`；日常启动只负责准备本地 PostgreSQL，`pnpm dev:db:setup` 才显式负责 Prisma、migration 和 runtime schema 初始化。

## 验证情况

本地已验证：frozen-lockfile 安装、workspace boundary、lint（保留 5 个既有 warning，无 error）、typecheck、governance regression、完整 test-lane inventory（包含“未受管测试目录必须失败”的回归检查）以及 stable lane（Webapp 114 个文件 / 748 个测试，stream-core 22 个测试，加上 PAS）。

显式的 `pnpm dev:db:setup` 路径也已完成 Prisma Client 生成、已提交 migration 应用，以及 Tasklist、chat-memory、UserMemory 相关 runtime schema 初始化。随后根命令 `pnpm test` 按 stable 先于 integration 的顺序完成：database integration 2 个测试通过，Webapp integration 14 个测试通过。完整 `pnpm build` 已在所有 workspace 上通过。

无数据库配置的 integration 负向路径会在 Turbo/Vitest 之前失败，不会把跳过的状态测试误报为成功。CI topology 已由 governance regression 覆盖：stable job 不允许包含 service、database env、migration 或 checkpoint setup；stateful job 必须依赖 stable job，并保持 Prisma generation -> migration -> checkpoint setup -> integration-test 的顺序。

剩余 release gate 是已提交变更集上的 GitHub Actions 证据：需要确认 `stable-validation` 通过后再执行并通过 `stateful-integration`，同时保留文档化的负向路径证据，即人为制造 stable failure 时 `stateful-integration` 被跳过，且不会产生 PostgreSQL service、migration 或 checkpoint setup 日志。External smoke validation 仍保持手动触发，不使用生产凭据。

## 部署影响

本版本不包含 production deployment、Docker、TCR、Compose、environment、secret 或 runtime 行为变更。
