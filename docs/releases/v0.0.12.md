# v0.0.12 Release Note

## Summary

`v0.0.12` 收紧本地 docs Resource 边界，接入 Tiptap Composer V1，并把 Tool 绑定迁移到 capability-driven runtime。

这版不是 Agent 或 workflow 版本，而是为后续受控 Agent 准备更稳定的输入、能力选择和文档上下文边界。

## Completed

- 本地 Resource 读取边界收敛到 `docs/**/*.md`。
- 本地 Resource URI 统一为 `docs://...`。
- 本地 MCP server 从 `project-files-server` 改为 `project-docs-server`。
- 下线模型可见的 `local-text-read` Tool。
- 新增 Tiptap Composer V1。
- 支持 `/summary`、`/tasklist`、`/check` inline command chip。
- 支持 `@docs://...` 与 `@project://latest-context` inline resource chip。
- 后端兼容旧 plain text 请求，并新增 composer hint 消费。
- 移除 `SkillDefinition.allowedTools`。
- Tool 绑定迁移到 `capabilitySelectors -> capability catalog -> Tool Runtime`。
- Remote MCP Tool 通过标准 tool call 链执行。

## Changed

- 本地项目文档读取从“项目文件”语义收口为受控 docs resource。
- 输入层从普通 textarea 升级为 Tiptap Composer，但不作为 Markdown 富文本编辑器使用。
- Tool 绑定来源从 `allowedTools` 迁移到 capability selector resolver。

## Technical Highlights

- Docs Resource Boundary 明确区分“公开文档知识区”和“任意项目文件读取”。
- Composer 被定位为增强输入框，而不是 Markdown 富文本编辑器。
- Command / Resource chip 进入用户消息展示，但 `plainText` 不混入 chip label。
- Active tool map 同时用于模型绑定、tool call 校验和执行，减少来源错绑风险。
- Resource / Prompt 继续保持独立语义，不急于全部模型化成 Tool。

## Known Limits

- Composer V1 当前只支持一个 command chip 和一个 resource chip。
- `/tasklist` 与 `/check` 当前只是 hint，不是 workflow。
- docs resource 不做搜索、索引或 RAG。
- remote MCP 数据仍然是 mock。
- 本版不做 Agent、workflow、多 remote server 或持久化。
