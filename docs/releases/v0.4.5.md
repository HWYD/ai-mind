# v0.4.5 Release Note

## 摘要

v0.4.5 是 `Long-term User Memory Store Baseline`。

本版在 v0.4.4 多会话短期记忆容器基础上，引入了 browser-session scoped `UserMemory Store`。同一个 browser session 下，不同 conversation 现在可以共享经过校验的长期用户偏好、稳定用户背景、稳定指令、工作流偏好、反复确认的约束和稳定项目上下文。

## 已完成

- 新增 `apps/webapp/lib/ai/runtime/user-memory/` runtime 边界，包含 provider、schema、validation、service、retrieval、context builder、candidate extractor 和 extraction pipeline。
- 长期记忆使用 LangGraph `Store` abstraction；生产方向支持 `PostgresStore`，开发/测试 fallback 为 `InMemoryStore`。
- 每个 eligible ordinary completed turn 都会在 assistant final turn 完成后 enqueue 一个 in-process best-effort extraction job。
- 模型以结构化 schema 输出带显式 `stability` 的 `0..N` UserMemory candidates；程序负责 deterministic validation、stable key、dedupe、suppression 和最终写入。
- stable key 由程序基于结构化 `identity.subject / facet / polarity` 规范化生成。
- `user_preference` 是通用长期偏好类型；`stable_user_context` 用于稳定、非敏感的用户背景。
- ordinary text chat 与 tool-assisted ordinary chat 现在可以按相关性召回同一 browser session 下的少量长期记忆，并作为 bounded supplemental context 注入；retrieval 优先依赖结构化 tags / structured identity / normalized text overlap，不在代码里维护隐藏的二级领域关键词分类；`stable_user_context` 对职业和工作背景问题支持受控短语匹配。
- compaction 成功后只会对新增或变化的 pinnedDecisions 做 conservative promotion。
- 自然语言 forget / negation 会 suppress 旧 memory，而不是物理删除。
- 新增独立 `db:user-memory:setup`，使用独立 `langgraph_user_memory` schema，且 setup 错误会做脱敏处理。

## 已知边界

- `UserMemory` 不是完整聊天历史，也不是账号级用户画像。
- 不做跨设备同步、Memory Inspector、memory edit/delete UI、memory management backend。
- 不做 embedding retrieval、pgvector、历史搜索或消息分页。
- `UserMemory` 不进入 hydration payload、Conversation Registry、ThreadState.messages、pinnedDecisions、stream chunk、frontend reducer、GraphState 或 RuntimeArtifact。
- Tasklist / Delivery 不读取、不写入 UserMemory。
- 主 assistant 不获得 memory-write tool。
