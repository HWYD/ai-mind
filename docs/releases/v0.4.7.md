# v0.4.7 Release Note

## 摘要

v0.4.7 是 `Browser-local Chat Session Persistence`。

本版为 AI Mind 增加浏览器本地最近会话与完整用户可见聊天快照恢复：页面刷新后先展示本地恢复结果，再由服务端会话列表做权威校准；会话内容展示、本地快照、服务端会话归属和 AI 运行时上下文继续保持分层边界。

## 已完成

- 使用 IndexedDB 保存最近会话索引、当前会话提示和完整用户可见消息快照。
- 支持刷新后恢复最近会话列表、当前会话选择和稳定的富 UI 消息展示。
- 引入 server-authoritative conversation-list reconciliation：有效服务端列表返回后，清理本地已失效旧会话，但不覆盖同 ID 会话的本地完整快照。
- 在服务端暂时不可用时提供 read-only cache state、明确提示和 retry 入口。
- 为桌面端与移动端统一提供三点菜单 + 删除确认弹窗，并在确认后同步删除服务端 Registry、ThreadState/checkpoint 与本地快照。

## 变更

- 会话恢复从单纯依赖服务端 bounded hydration，升级为 local-first UI restore + server validation。
- 本地完整 UI 历史继续只用于展示恢复，不升级为新的模型上下文来源，也不与服务端 `ThreadState` 做完整 transcript 合并。
- 会话删除仍然沿用当前 browser session 的 Conversation Registry 与 chat-memory 分层，不新增聊天历史业务表。
- 普通 chat、tool-assisted chat、Tasklist、Delivery 与 `@ai-mind/stream-core` 公开协议保持兼容。

## 技术亮点

- 按 `conversationId` 进行本地索引合并与快照隔离，避免不同会话互相覆盖。
- 同一会话并发写入采用 revision 覆盖较旧稳定快照，不做消息级合并。
- 有效服务端列表响应只更新元数据和清理无效本地会话，不重建、不覆盖本地完整 UI 历史。
- 删除失败时不清理本地快照，避免本地与服务端状态一起丢失。

## 验证

- focused local persistence / session / hydration / page / route / deletion suites 已通过。
- `pnpm --dir apps/webapp typecheck`、`pnpm lint:webapp` 和 `git diff --check` 已通过。
- `specs/047-browser-local-chat-persistence/acceptance.md` 已记录刷新恢复、rich UI 恢复、多标签页隔离、只读降级和删除链路的收口证据。

## 已知边界

- 不是 PG 完整聊天历史、账号体系、跨设备同步或云端历史恢复。
- 不承诺跨标签页实时同步，只保证较新的稳定快照不会被较旧快照覆盖。
- 服务端 bounded hydration 仍不是完整 transcript；没有本地快照时最多只作为降级展示。
- 当前只提供 Delete 单项会话操作，不扩展为完整历史管理面板。

## 下一步

如果后续要做账号体系、跨设备同步、历史搜索、导出或完整历史管理，必须单独设计新的服务端数据权威、迁移策略和产品边界，不能直接把 v0.4.7 的浏览器本地快照扩展成通用历史系统。
