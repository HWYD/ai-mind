# v0.4.8 Release Note

## 摘要

v0.4.8 是 `Monorepo pnpm / Turborepo Governance`。

本版不新增业务功能，重点把 AI Mind 的 workspace 安装、依赖版本、供应链脚本权限和跨 package 任务执行收口为一套可复现、可诊断的工程基线。本地、CI 与 Docker 现在共享 Node.js 22.x、`pnpm@10.34.0`、frozen lockfile 和 canonical Turbo task graph。

## 已完成

- 固定根 metadata、CI 和 Docker 的 pnpm 10.34.0 与 Node.js 22.x 基线。
- 强制内部 package 使用 `workspace:`，并在 `preinstall` 阶段校验 provider 缺失、普通 semver 和 `packages -> apps` 反向依赖。
- 使用 pnpm Catalog 集中 `@types/node@22.20.1`、TypeScript、Vitest、Zod、MCP SDK 和 dotenv，保留 Webapp-only 依赖在应用内管理。
- 使用显式 `allowBuilds` boolean matrix 管理 dependency install scripts。
- 使用 Turborepo 统一 lint、typecheck、test、build 与 dev/watch 的依赖顺序、输出和缓存边界。
- 保留数据库 migration/checkpoint setup 的显式顺序和 package-level 诊断入口。

## 变更

- 日常开发和 CI 的 canonical checks 统一为 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。
- Docker builder 使用根 `pnpm build` 执行相同任务图，不再手工维护一套 workspace build 顺序。
- database/Webapp 的非 hermetic tests 不缓存；stream-core/PAS 的 hermetic tests 保留缓存。
- package versions 按项目 lockstep 规则统一到 `0.4.8`。

## 技术亮点

- pnpm package graph 与 Turbo task graph 分工清晰：pnpm 决定“依赖哪个本地包”，Turbo 决定“任务按什么顺序执行”。
- 内部 provider 同时缺失且依赖误写普通 semver 时，validator 会在一次执行中报告两个问题，不会被单一错误短路。
- Prisma generation、migration、checkpoint setup 等副作用任务不会从普通 Turbo cache 中恢复。
- CI、Docker 和本地命令使用同一任务入口，减少三套编排长期漂移的风险。

## 验证

- pnpm 10.34.0 frozen install 通过，lockfile 仅包含预期 Catalog/importer 变化。
- workspace boundary regression：4/4 通过。
- 根任务图：lint 4/4、typecheck 6/6、test 6/6、build 4/4 通过；仅保留 5 个既有 Fast Refresh warnings。
- database integration 2/2、stream-core 22 tests、PAS 8 tests、Webapp 753 tests 通过；6 个 cloud/live smoke 继续按显式 opt-in 跳过。
- ordinary chat、tool-assisted chat、Tasklist、Delivery targeted smoke：65 tests 通过。
- Webapp runner、Project Assistant Service runner 与 PostgreSQL+pgvector 三个 image targets 构建通过；migration 和 runtime checkpoint setup 在临时 pgvector 环境通过。
- `git diff --check` 通过。

## 部署影响

- 线上部署步骤、TCR image names、Compose、生产 env、secret sync、数据库 setup 与服务器脚本不变。
- release workflow 构建镜像时会使用 pnpm 10.34.0 和根 Turbo build graph。
- 首次构建可能因 pnpm/Turbo/Docker layer 变化失去旧缓存，后续构建恢复正常缓存行为。

## 已知边界

- 不包含 affected-only CI、remote cache、Changesets、npm publishing 或 package release automation。
- 不迁移 pnpm 11、`pnpm deploy`、Nx，也不做 Docker slimming。
- 不改变业务 Runtime、Agent/Tool/MCP 权限、API、数据库 schema、stream protocol 或 UI。

## 下一步

后续可独立评估 affected-only CI、remote cache 和 package release automation；这些能力需要结合 CI 时长、缓存可信边界和实际发布需求另行设计，不在本版中提前启用。
