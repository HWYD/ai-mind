# v0.5.4 发布记录

**状态**：本地版本收口完成；尚未创建 tag 或 GitHub Release。

## Summary

v0.5.4 将普通聊天记忆改为按 token budget 压缩，并在模型调用前统一校验完整输入。压缩失败时，Runtime 使用只读的 ephemeral fit 继续当前回答，避免长对话在压缩后直接失去可用性。

## Completed

- 修复虚拟聊天首问、草稿升格、续问和完成后的滚动跟随。已完成 measurement 的正向总高变化会在下一帧回底，不再等待迟到的底部状态；用户上翻或手动展开时保持阅读位置，点击到底或向下实际回底恢复跟随；缓存刷新不再重挂载活跃列表。
- 新增顶部居中的 Base UI Messages 统一短暂操作反馈；持续故障显示在会话列表、Composer、消息占位或对应回复，移动导航移出虚拟消息 viewport。
- 流式 text/reasoning 保留 40ms 合并；pending Map 累计达到 48 个 Unicode code point 时提前请求既有 rAF，不新增滚动命令或展示队列。

- 云端普通聊天默认使用不超过 128K 的运行窗口，Ollama 使用不超过 32K 的运行窗口并显式传入 `numCtx`；模型物理窗口仍由 server-side catalog 管理。
- 持久化 compaction 按 token trigger 触发，每次请求最多尝试一次；只保存完整、缩小且位于目标预算内的候选。
- compaction 的生成、校验、保存或取消路径不会覆盖 last durable checkpoint；当前请求会以 ephemeral fit 继续，只有非记忆输入自身超限才返回输入过长错误。
- direct answer、Tool、Composer Context 与 Capability Context 的模型调用统一经过完整输入 preflight。
- Composer desktop skill-mode 工具栏新增只读聊天记忆用量圆环和可访问 Tooltip，不增加手工压缩操作。

## Changed

- 固定 recent turn/message count 不再作为 chat-memory compaction trigger。
- `AI_MIND_MAX_INPUT_CHARS` 仅继续保护最新用户输入和请求体；它不再代替完整模型输入预算。
- 压缩诊断只记录预算、token 数、原因和 fallback 枚举，不记录聊天正文、prompt、密钥或 Provider 配置。

## Technical Highlights

- 一个明确的 ContextBudget 同时处理模型物理能力、产品运行上限、输出预留和 runtime headroom。
- 持久化 checkpoint 与当前请求的临时输入投影分离，失败恢复不会以数据安全换取连续性。
- Tool schema、Capability Context 和 UserMemory 等动态输入均在请求前重新估算，避免 Provider 超限错误发生得过晚。

## Verification

- 定向自动化覆盖预算、token estimate、compaction、preflight、取消、Provider 选项、状态收口、兼容性、Composer usage hint 和反馈区域归属。
- Chrome 真实页面回归覆盖 Base UI Messages 的去重、关闭/超时、窄屏居中、Sheet stacking，以及 21 项虚拟滚动场景；慢速增量已测最长 3 帧重新贴底。当前 48 码点早刷下，快速 18 个 25ms delta 产生 18 次真实高度提交，最长 2 帧重新贴底，每帧至多一次回底命令，未观察到反向滚动。
- 最终收口已通过 `pnpm typecheck`、`pnpm lint`、`pnpm test:stable`、本地开发 PostgreSQL 下的 `pnpm test:integration`、`pnpm build` 与 diff integrity 检查；生产构建的 workspace boundary 验证和 Next optimized build 均完成。
- DeepSeek 与本地 Ollama Qwen3 external structured-compaction smoke 通过；Ollama 的运行时 context 为 32K。

## Known Limits

- Qwen external smoke 当时因账号免费额度耗尽返回 403；这是 Provider 环境限制，不是 Runtime fallback 或 Provider contract 的自动化失败。使用有可用额度的 Key 后可重新执行该 smoke。
- 运行窗口是产品策略，不等同于模型物理窗口；提高上限仍需评估成本、首 token 延迟与本地 KV cache 资源。
- Composer 指示器只反映 persisted chat memory，占用不包含 system、Tool、UserMemory 或本轮输入，也不提供压缩操作。
- 流式触底时的像素残影尚未建立可重复的视觉回归证据，后续作为独立体验优化处理；不影响本次已通过的几何和滚动命令回归。

## Next

后续可基于脱敏预算与 fallback 诊断观察不同模型、工具负载和 Ollama 资源配置下的运行效果；这不改变 v0.5.4 已确定的 token-budget 和 checkpoint 边界。

## Scroll Verification

Chrome 测试覆盖真实页面与 1000 条混合消息的 21 个场景，包含自动跟随全过程的按钮显隐，以及慢速和快速增量逐帧采样；慢速增量已测最长 3 帧重新贴底；当前 48 码点早刷下，18 个 25ms delta 产生 18 次真实高度提交，快速增量最长 2 帧重新贴底、每帧至多一次回底命令，未观察到反向滚动，稳定后跟随位置误差不超过 4px。边界见 [聊天消息视口](../architecture/chat-message-viewport.md)。
