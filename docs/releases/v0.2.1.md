# v0.2.1 Release Note

## Summary

`v0.2.1` 新增服务端 Model Provider Runtime，让 AI Mind 可以通过统一入口使用本地 Ollama 和配置后的 Qwen / DeepSeek。

模型选择由服务端白名单控制。前端只能选择当前可用模型，不接收或提交 API Key、base URL 和任意模型名。

## Completed

- 新增 Model Catalog，统一模型 ID、Provider 实际模型名和能力声明。
- 请求协议统一使用 `options.modelId`。
- 新增 ModelProvider / Registry 和统一模型创建入口。
- 新增 Ollama、Qwen、DeepSeek Provider。
- 普通聊天、Tool Calling 和 `/tasklist` Agent 共用 Provider Runtime。
- 新增 `GET /api/ai/models` 和服务端首屏模型预取。
- 前端模型选择器按“线上模型 / 本地模型”分组。
- 新增 Provider 错误标准化、中文提示和脱敏日志。
- 新增输入输出上限、请求超时和默认开启的轻量限流。
- 新增 usage / token best-effort 观测。

## Changed

- 旧 `options.model` 不再支持。
- 模型选择 ID 统一为 `provider/model-key`。
- 业务主链不再直接依赖 `ChatOllama`。
- 前端静态模型列表不再是事实源。
- 非法模型、Provider 未允许或能力不匹配时 fail closed。

## Technical Highlights

- Provider 差异被限制在 Provider 层，不污染 chat orchestrator 和 Agent graph。
- API Key 只在服务端使用，不进入公开模型 DTO、stream chunk 或 Debug Summary。
- tasklist route 使用独立且更严格的输出与每日请求上限。
- 真实 Qwen / DeepSeek smoke 覆盖普通聊天和完整 tasklist graph 链路。

## Verification

- webapp 全量测试通过：264 项通过，2 项 opt-in smoke 跳过。
- stream-core 15 项测试与 package build 通过。
- tasklist legacy / graph 回归通过。
- Qwen / DeepSeek 真实模型 smoke 通过。
- webapp production build、两个 app 的 typecheck、lint 和 diff check 通过。

## Known Limits

- 当前限流是单进程 Memory Store，不适合多实例强一致成本控制。
- usage 是 best-effort 日志，不是计费事实源。
- 不做多 Provider 自动 fallback。
- 不做用户自带 Key、模型市场、健康检查或成本看板。
- 本地小模型的 tasklist 结构化输出稳定性仍有限。
