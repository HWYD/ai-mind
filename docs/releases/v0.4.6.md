# v0.4.6 Release Note

## 摘要

v0.4.6 是 `UserMemory Semantic Retrieval Baseline`。

本版在 browser-session scoped `UserMemory Store` 上增加 vector semantic retrieval：用户以不同措辞提出相关问题时，runtime 可以选出少量相关长期 UserMemory，作为 ordinary chat 的补充上下文。

## 已完成

- 使用 `PostgresStore` vector search 作为唯一正式 UserMemory candidate source。
- 使用独立的火山引擎 Ark OpenAI-compatible embedding 配置，固定模型为 `doubao-embedding-vision`。
- 将 semantic index 限制为 validated `UserMemory.text` 和 `UserMemory.tags`，并保存最小内部 semantic metadata。
- 为 ordinary text chat、tool-assisted ordinary chat 和 eligible capability-context final answer 接入受控 retrieval；Tasklist、Delivery、HITL、Tool/MCP 原始输入路径继续排除。
- 固化 query 规范化、`topK = 8`、`semantic score >= 0.32`、最多 3 条与 900 字符的注入边界。
- 为 timeout、embedding/Store failure、异常 score 和边界不确定性提供 0 注入的安全降级。

## 变更

- v0.4.5 的长期 UserMemory 写入、validation、stable key、suppression、conflict handling 与 bounded context 语义保持兼容。
- 正式 runtime 不再把 rule-based / lexical retrieval 作为 candidate source 或 fallback。
- local development、integration、preview、staging 和 production 统一使用 `PostgresStore` runtime path；测试替身只存在于测试侧。
- 没有修改 `@ai-mind/stream-core` chunk union、hydration DTO、Conversation Registry 或 frontend reducer public shape。

## 技术亮点

- `text` / `tags` allowlist 避免完整 UserMemory document JSON 和运行时敏感内容被向量化。
- latest user input 永远高于 selected UserMemory；记忆不能覆盖当前输入、ThreadState summary、pinned decisions 或 recent messages。
- semantic retrieval 是 runtime-controlled context assembly，不向主 assistant 暴露 search tool，也不把内部向量、分数或原始错误暴露给用户。

## 验证

- focused provider、service、retrieval、context builder 与 chat orchestrator semantic suites 已通过。
- Route、hydration、Conversation Registry、frontend reducer、Tasklist / Delivery 非回归 suites 已通过。
- `pnpm --filter @ai-mind/stream-core test`、`pnpm --dir apps/webapp test`、`pnpm typecheck`、`pnpm lint:webapp` 与 `git diff --check` 已通过；lint 仅保留既有 shared UI/layout 的 `react-refresh/only-export-components` warnings。

## 已知边界

- 不是 RAG、聊天历史搜索、账号级用户画像或独立向量数据库产品。
- 不对旧 UserMemory 做 migration、semantic reindex 或 rule-based / lexical fallback。
- 不提供 Memory Inspector、编辑/删除 UI、批量管理后台或跨设备同步。
- 真实语义验证需要 PostgreSQL Store 与服务端 embedding 配置；缺失或异常时普通聊天会继续，但不会注入 UserMemory。
- 线上生产部署需要 pgvector-capable PostgreSQL 16 镜像；release workflow 会构建 `ai-mind-postgres-pgvector`、`ai-mind-webapp` 与 `ai-mind-project-assistant-service` 三个 TCR 镜像，服务器侧 `deploy-production.sh` 会在启动应用前执行 `db:setup:deploy`。

## 下一步

后续如需 keyword / hybrid retrieval、旧数据 reindex 或产品化 memory 管理，必须单独设计字段白名单、数据迁移和公开边界，不能直接复用完整 Store JSON 搜索。
