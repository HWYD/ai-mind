# AI Mind v0.3.6: Controlled Delivery Chain MVP

## 摘要

v0.3.6 在 v0.3.5 已经完成的 public demo resource boundary 基础上，新增一个受控交付链路入口：

```text
/delivery-chain
```

它把一个需求输入转成一份完整但非持久化的交付链路报告：

```text
需求理解 -> 实现方案 -> 任务拆解 -> 交付评审 -> Delivery Chain Report
```

## 为什么需要这个版本

v0.3.5 解决的是“public demo 的 Agent 能读什么”。
但 AI Mind 公开 demo 仍然主要围绕 `/tasklist + @demo://version-plans/*.md`。如果项目要进一步展示“需求 -> 方案 -> 任务 -> 评审”的 AI coding workflow，就需要一条比 Tasklist Agent 更完整、但仍然受控的链路。

v0.3.6 的目标不是做完整多 Agent 平台，而是先验证：

- public demo 可以承载一个更完整的交付 workflow
- 这条 workflow 仍然只依赖 `@demo://`
- 不需要引入新的 stream 协议、DB schema、artifact persistence 或 nested HITL

## 本版做了什么

### 1. 新增 `/delivery-chain` public command

本版对外只新增一个 public command：

```text
/delivery-chain
```

它必须显式触发，不会把普通聊天裸输入自动路由成 Delivery Chain。

### 2. 支持两类输入

#### Demo scenario 输入

```text
/delivery-chain + @demo://scenarios/request-limit-banner/requirement.md
```

运行时只接受 `requirement.md` 作为 scenario 入口，并继续在同一 scenario 目录下读取 `context.md`。

#### Inline requirement 输入

```text
/delivery-chain 帮我规划一个登录表单，支持手机号、密码、错误提示和加载状态
```

这种模式只基于用户文本和 demo governance / rubrics 生成报告，不读取真实项目目录。

### 3. 固定执行 PlanStage -> TaskStage -> ReviewStage

`/delivery-chain` 内部是一个受控 workflow runner，而不是开放式多 Agent：

```text
DeliveryChainGraph
  -> PlanStage
  -> TaskStage
  -> ReviewStage
  -> Delivery Chain Report
```

其中：

- `PlanStage` 负责需求理解、实现方案、非目标和风险
- `TaskStage` 负责任务拆解、顺序和高风险项
- `ReviewStage` 负责覆盖检查、一致性检查、范围漂移检查和结论

### 4. Delivery Chain 继续只读取 `@demo://`

本版继续复用 v0.3.5 的 public demo resource boundary：

- 允许读取 `@demo://scenarios/*/requirement.md`
- 允许读取同 scenario 下的 `context.md`
- 允许读取 `@demo://rubrics/*.md`
- 允许读取 `@demo://governance/*.md`

继续拒绝：

- `@docs://`
- `@specs://`
- `file://`
- 真实绝对路径
- `../`
- 反斜杠路径
- `@demo://version-plans/*.md` 作为 Delivery Chain 入口

### 5. Resource picker 和快速访问一起收口

- `@` picker 在 `/delivery-chain` 场景下只展示 `scenarios/*/requirement.md`
- 不展示 `plan.sample.md`、`tasks.sample.md`、`review.expected.md` 作为普通入口
- 快速访问新增 Delivery Chain demo 示例

### 6. 报告使用现有文本输出能力承载

Delivery Chain Report 不新增持久化 artifact，也不新增 stream chunk。
它直接使用现有 assistant text 输出承载以下结构：

- 输入来源
- 需求摘要
- 默认假设
- 实现方案
- 任务拆解
- 交付评审
- 风险
- 非目标
- 下一步建议

### 7. `/delivery-chain` 资源读取展示做了最小降噪

- 用户显式选择的 scenario `requirement.md` 不再单独占用大资源卡片，而是收敛进轻量分组摘要中。
- `context.md`、`rubrics/*.md`、`governance/*.md` 这类内部自动读取资源改为默认聚合折叠展示，主界面只显示“已读取 demo 上下文 N 项”。
- 展开后只显示轻量分组列表；URI、来源、服务和 preview 等调试信息退到二级 debug 详情。
- 最终 Delivery Chain Report 继续作为页面主要视觉焦点，不再被连续资源卡片淹没。

## 明确不做

v0.3.6 不做：

- 不暴露 `/plan`、`/task`、`/review`
- 不实现真正多 Agent orchestration
- 不实现 `@artifact://`
- 不做 artifact handoff 或 artifact persistence
- 不做 nested HITL
- 不做 chat persistence
- 不修改 Tasklist Agent Graph topology
- 不修改 HITL contract
- 不修改 checkpoint resume 语义
- 不修改 stream protocol
- 不修改 frontend reducer 数据结构
- 不修改 Prisma schema
- 不修改 PostgresSaver schema

## 验证重点

本版重点验证：

- `/delivery-chain + @demo://scenarios/*/requirement.md` 可用
- `/delivery-chain <inline requirement>` 可用
- `/delivery-chain` 空输入 fail closed
- `@docs://` / `@specs://` / `file://` / traversal 被拒绝
- `@demo://version-plans/*.md` 被识别为 `/tasklist` 资源而非 Delivery Chain 入口
- `@` picker 在 `/delivery-chain` 下只展示 scenario requirement
- 快速访问新增 Delivery Chain demo 示例
- 不改 Graph topology / HITL contract / stream protocol / frontend reducer / Prisma schema / PostgresSaver schema

## 对后续版本的意义

v0.3.6 先把“需求 -> 方案 -> 任务 -> 评审”的交付链路在 public demo 内跑通，但仍保持单入口、固定 stage、非持久化输出和强边界资源读取。

这为后续版本留下了清晰演进路径：

- v0.3.7 做 Delivery Chain presentation + trace
- v0.4.0 起重新收口为 Controlled Agent-as-tool Delivery Manager MVP
- 后续版本不再提前预排，待 v0.4.0 实现和评审后再定
