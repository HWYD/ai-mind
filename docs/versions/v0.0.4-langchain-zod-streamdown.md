# v0.0.4 LangChain Zod Streamdown

## Summary

`v0.0.4` 将 AI Mind 从一个能跑的本地聊天原型，收敛成一条更清晰的最小聊天链路。

本版本采用 `LangChain.js + Ollama` 作为模型接入层，使用自定义 NDJSON 流式协议，配合 `Zod` 做请求与协议校验，并用 `Markdown + typed parts + Streamdown` 建立内容渲染标准。

这一版的重点不是增加更多能力，而是先把“本地聊天闭环”的工程地基站稳。

## Goals

- 保留 `LangChain.js` 作为后续模型能力扩展基础。
- 使用 `Ollama` 承载本地模型运行。
- 去掉不必要的额外聊天 SDK 抽象，保持流式协议可控。
- 用 `Zod` 校验请求与流式 chunk。
- 建立 `typed parts` 消息结构。
- 使用 `Streamdown` 渲染流式 Markdown。
- 支持最小多轮上下文和请求取消。

## Non-goals

- 不做 Tool Calling。
- 不做 RAG。
- 不做 source 引用展示。
- 不做长期记忆。
- 不做多会话管理。
- 不做模型切换面板。
- 不做 Agent 或复杂 workflow。

## Key Changes

### 模型接入层

服务端通过 `LangChain.js` 调用 `ChatOllama`，把项目内部消息转换为 LangChain messages，再将模型输出转换成自定义流式协议。

这样做让项目内部消息模型和模型 provider 之间保持隔离，后续更容易接入 tool calling、structured output 或其他模型来源。

### 自定义 NDJSON 流式协议

本版本使用 NDJSON 作为前后端流式传输格式。

最小协议包含：

- `start`
- `text-start`
- `text-delta`
- `text-end`
- `finish`
- `error`

同时为后续 reasoning part 预留扩展空间。

### Typed Parts 消息结构

消息不再只是一段字符串，而是由 parts 组成。

首版重点支持：

- `text`
- `reasoning` 预留类型

这为后续 Tool、Resource、Source 等结构化消息打下基础。

### 前端 useChatStream

前端使用自定义 `useChatStream` 维护消息状态、发送请求、消费 NDJSON 流、合并 part 增量，并支持取消请求。

该 hook 只做最小聊天闭环，不承担复杂会话管理。

### Streamdown 渲染

`text` part 使用 Streamdown 渲染 Markdown，以适配 AI 输出的流式 Markdown 场景。

## Important Interface Changes

- 聊天请求使用结构化 `messages[]`。
- assistant 消息使用 `parts` 组织内容。
- 服务端响应为 NDJSON chunk 流。
- 前端通过 `useChatStream` 消费并合并 stream chunks。
- 请求与流式 chunk 均通过 `Zod` schema 校验。

## Test Plan

- 验证普通本地聊天可以流式返回。
- 验证多轮上下文能随请求发送。
- 验证 Markdown 内容可以通过 Streamdown 渲染。
- 验证请求取消可以停止当前流。
- 验证非法请求会被 schema 拒绝。
- 更详细工程验证记录：待补充。

## Result / Outcome

`v0.0.4` 完成了 AI Mind 的本地聊天最小工程骨架。

它让项目从“能调用模型”升级为“有清晰消息结构、流式协议、渲染标准和请求边界”的 Runtime Skeleton 起点。
