# AI Mind v0.4.9：Monorepo 边界与 CI 分层验证治理

## 摘要

v0.4.9 在 v0.4.8 已建立的 pnpm/Turborepo 基线上继续收紧工程治理，但不改变 AI Runtime、API、database schema、UI 或 production deployment 行为。本版本的重点是把 workspace 边界和测试分层从“约定”变成可以执行、可以回归验证的 repository contract。

## 变更内容

- 所有 workspace 身份统一使用内部 `@ai-mind/*` namespace；pnpm 会拒绝未命中的 filter、workspace cycle，以及意外的非 `workspace:` 本地依赖范围。
- 新增 preinstall-safe boundary validator，用于验证 manifest、依赖方向、循环依赖和跨 workspace import。内部 package 只能通过声明过的 public `exports` 被消费。
- 测试被划分为 stable、integration、external 三类 lane。stable workspace tests 保持 cacheable 且不依赖外部状态；governance regression 始终进入 stable lane；integration 和 external lane 明确设置为 non-cacheable。
- 当 `DATABASE_URL` 缺失时，integration validation 会在 Vitest 之前失败，避免状态测试被跳过后伪装成成功。
- Cloud/live smoke tests 只允许通过 `AI_MIND_RUN_EXTERNAL_TESTS=1` 手动触发，不进入普通本地验证、PR CI 或定时 CI。
- CI 先运行不带 service 的 stable job，只有 stable 成功后，依赖它的 integration job 才会创建 PostgreSQL 状态并执行 integration lane。
- 本地开发将日常 PostgreSQL readiness 和数据库变更操作分开：`pnpm dev*` 只启动并 health-check 本地 PostgreSQL；显式的 `pnpm dev:db:setup` 负责 Prisma generation、已提交 migration 和 runtime schema setup。stream-core 的 transpile/type watch 并行由 Turbo 管理，不再需要额外的 package-level process runner。

## 非目标

- 不启用 remote Turbo cache、affected-only execution、pnpm/Nx 迁移、发布自动化或 package extraction。
- 不引入 scheduled external test execution，也不在 CI 中注入生产凭据。
- 不修改 Docker、TCR、Compose、production environment 或 deployment flow。

## 验证方式

使用文档化的根目录验证流程：

```powershell
pnpm validate:workspace-boundaries
pnpm test:governance:boundaries
pnpm validate:test-lanes
pnpm test:governance
pnpm test:stable
pnpm test:integration
pnpm build
```

External smoke validation 是显式的人工验证，需要使用非生产凭据环境：

```powershell
$env:AI_MIND_RUN_EXTERNAL_TESTS = '1'
pnpm test:external
```

更多背景见 [治理架构文档](../architecture/monorepo-pnpm-turborepo-governance.md) 和 [v0.4.9 spec](../../specs/049-monorepo-boundary-ci/)。
