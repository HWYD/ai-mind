# AI Mind v0.3.7: Delivery Chain Workflow Progress Presentation

## 摘要

v0.3.7 在 v0.3.6 已完成的 `DeliveryChainGraph` 基础上，为 `/delivery-chain` 增加了可渐进展示的 workflow progress panel，让用户能在执行过程中看到系统已经做了什么、正在做什么，并在报告输出后折叠为紧凑摘要。

```text
workflow-progress-start
workflow-progress-step
workflow-progress-end
```

这套事件命名和组件设计是通用化的，但首版只绑定 `/delivery-chain`，不影响 `/tasklist`、普通 ResourcePanel、ToolPanel、PromptPanel 或 AgentTracePanel。

## 为什么需要这个版本

v0.3.6 已经把 Delivery Chain 的固定阶段 workflow 跑通了，但用户主要只能看到资源读取摘要和最终 Markdown 报告。对于公开 demo 和 reviewer 来说，最明显的体验缺口是：

- 看不到系统正在做什么
- 看不到阶段是按什么顺序推进的
- 报告出来后缺少一眼可扫的结构化过程回顾

v0.3.7 解决的是 presentation 和 trace surface，不是 artifact handoff、multi-agent、HITL 或 persistence。

## 本版做了什么

### 1. 为 `/delivery-chain` 新增 workflow progress stream surface

runtime 现在会围绕固定的五个 graph 节点发出过程事件：

```text
loadDeliveryChainContext
-> runPlanStage
-> runTaskStage
-> runReviewStage
-> buildDeliveryChainReport
```

对应用户可见阶段：

```text
读取上下文
-> 方案规划
-> 任务拆解
-> 交付评审
-> 生成交付计划报告
```

### 2. steps 按真实执行顺序逐步出现

- `workflow-progress-start` 只开启 panel，不预填完整 pending 列表
- 每个 step 在真正开始时才出现
- 同一 step 支持 `running -> completed` 或 `running -> failed` 更新
- `workflow-progress-end` 在最终 report 文本输出前发出，给前端自动折叠提供依据

### 3. 运行时展开，完成后折叠

`/delivery-chain` 执行中，workflow progress panel 默认展开。  
当 workflow 完成并开始输出报告时，panel 会折叠成类似“已处理 6m25s”的一行摘要，并支持点击重新展开查看本轮过程。

### 4. step details 只展示 curated safe summary

本版允许在 step 中展示少量、可读、安全的过程摘要，例如：

- `已读取 demo 上下文 6 项`
- `调用模型：生成方案 (plan)`
- `调用模型：拆解任务 (tasks)`
- `调用模型：交付评审 (review)`

但这些 details 不是普通 tool/resource/prompt 事件的自动回放，也不是通用 observability transcript。

### 5. Delivery Chain Report 改为更清晰的 section presentation

当 report headings 稳定时，前端会按 section 展示：

- 输入来源
- 需求摘要
- 默认假设
- 实现方案
- 任务拆解
- 交付评审
- 风险
- 非目标
- 下一步建议

当 section parsing 失败时，仍然完整回退到普通 Markdown。

### 6. 保持 v0.3.6 的 compact resource grouping

`/delivery-chain` 内部自动读取的 demo resources 继续保持 compact grouping，不回退成多个大 ResourcePanel。  
同时，显式入口 requirement 也不会重新退化成大资源卡片。

## 明确不做

v0.3.7 不做：

- 不新增 `/plan`、`/task`、`/review`
- 不实现真正 multi-agent orchestration
- 不实现 `@artifact://`
- 不做 session artifact handoff
- 不做 artifact persistence
- 不做 chat persistence
- 不新增 DB schema / Prisma migration / PostgresSaver schema
- 不接 PostgresSaver
- 不新增 checkpoint / interrupt / HITL / resume
- 不修改 Tasklist Agent Graph topology 或 HITL decision contract
- 不复用 `/tasklist` 的 `agent-graph-*` 时间线 UI
- 不把 workflow progress 升级成通用 tool/resource/prompt 日志回放

## 对后续版本的意义

v0.3.7 把 `/delivery-chain` 从“只看最终报告”推进到了“能感知过程、能复盘步骤、但仍保持界面整洁”的状态。  
它为后续版本保留了三个很重要的扩展点：

- v0.4.0 的 session artifact handoff
- v0.4.x 之后更多 Agent 复用同类 workflow progress UI
- 在不破坏当前主链的前提下，逐步演进到 controlled multi-agent orchestration
