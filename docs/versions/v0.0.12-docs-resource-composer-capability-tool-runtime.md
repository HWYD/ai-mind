# v0.0.12 Docs Resource + Composer + Capability Tool Runtime

## Summary

`v0.0.12` 是一版边界收口版本。

它基于 `v0.0.11` 的 Capability Surface，进一步解决三个问题：

- 本地文档读取不能继续像任意文件访问一样扩张。
- 用户输入需要能表达 command 与 resource reference。
- Tool 绑定不能继续依赖 Skill 上的 `allowedTools` 字段。

因此本版做了三件事：

- 将本地 Resource 边界收敛到 `docs/**/*.md`。
- 引入 Tiptap Composer V1。
- 将 Tool 绑定迁移到 capability-driven runtime。

## Goals

- 使用 `docs://...` 作为本地 docs resource URI。
- 只允许读取 `docs/**/*.md`。
- 下线模型可见的 `local-text-read` Tool。
- 保留 `local-file-summary` Prompt，语义调整为 docs 文档摘要。
- 用 Tiptap 替换普通输入框。
- 支持 `/` command 与 `@` resource inline chip。
- 后端兼容旧请求，并新增 composer hint。
- 删除 `allowedTools`。
- 使用 `capabilitySelectors` 解析本轮 active tools。
- Remote MCP Tool 通过标准 Tool Runtime 执行。

## Non-goals

- 不做 Agent。
- 不做 workflow。
- 不做 RAG、chunking 或 indexing。
- 不做 docs 全量搜索。
- 不做完整 Resource Picker。
- 不做多资源选择。
- 不做 Markdown 富文本编辑器。
- 不做 Prompt / Resource tool 化。
- 不做多 remote server。
- 不接数据库或第三方 API。

## Key Changes

### Docs Resource Boundary

本地项目知识读取只允许进入 `docs/`：

- `docs://README.md`
- `docs://architecture/runtime-boundary.md`
- `docs://architecture/stream-core.md`
- `docs://architecture/capability-skill-surface.md`

旧的 `project://README.md`、`project://package.json` 和根目录读取语义不再作为成功路径。

### Composer V1

Composer 是 AI 指令输入框，不是富文本编辑器。

它支持：

- 自然语言输入。
- Enter 发送。
- Shift + Enter 换行。
- 中文 IME 防误发。
- `/summary`、`/tasklist`、`/check` command chip。
- `@docs://...` 与 `@project://latest-context` resource chip。

发送 payload 中：

- `plainText` 是主输入。
- `command` 表达任务意图。
- `references` 表达引用资源。
- Tiptap `editorJSON` 是前端实现细节，不进入 `ChatRequest`，后端只信任 `plainText / command / references`。

本版只对 `/summary + @docs://...` 做窄链路消费。`/tasklist` 与 `/check` 只作为任务意图 hint，不会自动触发 remote Prompt 或 remote Tool。

### Capability-driven Tool Runtime

Skill 不再直接声明 `allowedTools`。

本轮 Tool 绑定链路为：

```text
skill.capabilitySelectors
  -> capability catalog
  -> active tool definitions
  -> model.bindTools(activeTools)
  -> tool call validation / execution
```

这样可以让 Tool 来源、模型绑定、Zod 校验和执行保持一致。

### Remote Tool 标准化

Remote MCP Tool `check_doc_consistency` 不再由 `capability-context` 特判执行。

它会被适配成标准 `ChatToolDefinition`，在 `reader-skill` 场景中进入 Tool Runtime，由模型真实 tool call 触发。

## Important Interface Changes

- Local docs resource URI：`docs://...`
- Local docs server id：`project-docs-server`
- Chat request 新增可选 `composer`
- Composer payload 包含 `plainText`、`command`、`references`
- `SkillDefinition.allowedTools` 移除
- Tool binding 入口改为 capability selector resolver

## Test Plan

- 验证 `docs://README.md` 可读取。
- 验证越界路径、根目录文件、非 Markdown 文件被拒绝。
- 验证 `/summary + @docs://...` 可生成文档摘要。
- 验证 `@docs://...` 单独引用可进入上下文。
- 验证 `@project://latest-context` 可作为 remote context。
- 验证 `check_doc_consistency` 走标准 tool call。
- 验证普通问答和 utility-skill 不退化。
- 验证 Composer Enter、Shift + Enter、IME、chip 删除和 payload 同步。

## Result / Outcome

`v0.0.12` 让 AI Mind 在进入 Agent 之前，先具备了更清晰的输入边界和能力绑定边界。

它没有把系统推向复杂 planner，而是先保证：用户表达意图更结构化、docs context 更安全、Tool Runtime 更统一。
