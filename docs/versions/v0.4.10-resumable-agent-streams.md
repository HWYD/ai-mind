# AI Mind v0.4.10：Resumable Agent Streams

## 摘要

v0.4.10 为 AI Mind 当前三类 NDJSON 流补齐断线恢复、幂等提交和显式取消能力：

- 普通聊天；
- Tasklist Agent；
- Delivery Chain。

本版本没有把 `fetch POST + NDJSON` 改成浏览器原生 SSE，而是参考 SSE 的 `Last-Event-ID` / replay 思路，在现有 POST 初始执行和 NDJSON 协议上固定使用 envelope、event store、GET recovery 和 client reconnect policy。

## 用户可见能力

- 浏览器流式读取中断后，前端可以用同一个 `runId` 和最后确认的 cursor 恢复输出。
- 重复提交相同 `Idempotency-Key` 和相同请求不会重新执行模型、Agent 或 Delivery workflow，而是返回 replay descriptor。
- 初始 `POST /api/chat` 尚未获得 `runId` 时，当前页面会在网络响应丢失、缺少流 body 或 `408`/`502`/`503`/`504` 下复用原 `Idempotency-Key` 和 payload 重试；最多 3 次、总等待不超过 20 秒。收到 replay descriptor 后转入既有 GET recovery，不跨刷新或关闭页面继续提交。
- 相同 key 但不同 request fingerprint 会返回 `409 IDEMPOTENCY_CONFLICT`。
- 用户显式停止时，客户端会停止 retry，并向服务端写入 cancel intent，run 进入明确的 cancellation outcome。
- 前端可以区分 reconnecting、paused/HITL waiting、terminal 和 recovery unavailable 等状态。

## 技术变更

- `@ai-mind/stream-core` 增加 `StreamEventEnvelope`、lifecycle payload、terminal state 和固定 envelope NDJSON writer。
- database schema 增加 `StreamRequest`、`StreamRun`、`StreamEvent`。
- webapp 增加 `stream-recovery` service / store / projector / coordinator。
- `POST /api/chat` 固定返回 resumable envelope，并支持 duplicate replay descriptor。
- 新增 `GET /api/chat/runs/{runId}/stream` recovery endpoint。
- 新增 `POST /api/chat/runs/{runId}/cancel` cancel endpoint。
- ordinary chat、Tasklist Agent、Delivery Chain 均接入 public event projection。

## Non-goals

- 不支持 Node.js process crash 后的 active executor takeover、worker queue 或跨实例执行接管。
- 不承诺外部 Tool/MCP side effect exactly-once；本版本只保证 transport 层幂等与客户端去重边界。
- 不迁移到原生 `EventSource`、WebSocket 或新的 queue service。
- 不提供无限历史、任意时间点 replay 或永久事件保留。
- 页面刷新或关闭后不恢复活动订阅；若最终业务结果已经持久化，重新进入时由普通会话 hydration 查询。
- 页面关闭后半截本地快照与服务端最终结果的优先级问题延后处理。

## Follow-up reliability closure

- 初始 POST 的 20 秒恢复预算是端到端上限：挂起请求会在剩余预算到期时被中止，而非无限等待。
- 未携带 terminal 或 paused lifecycle 的干净 EOF 会触发同一 `runId` 的 cursor-based GET recovery；replay descriptor 的首次 GET 临时失败同样如此。
- draft conversation 注册若在 StreamRun 创建后失败，运行会被安全收口为 `failed`，不会留下无 executor 的 `running` 状态。

## 部署与迁移前提

- 需要应用 v0.4.10 Prisma migration。
- 需要可用 PostgreSQL，因为 recovery event store 是状态能力。
- 初始请求必须携带 `Idempotency-Key`；完整 webapp 镜像部署后，旧 raw one-shot consumer 不再受兼容性保证。
- 前端恢复能力依赖 `Idempotency-Key`、`X-Run-Id`、envelope cursor 和 recovery GET endpoint。

## 验证方式

本版本需要覆盖：

- stream-core protocol / writer tests；
- webapp stream-recovery store / run-service / projector / coordinator tests；
- chat route / recovery GET / cancel route tests；
- Instamind stream reader / hook / reconnect policy tests；
- ordinary chat、Tasklist Agent、Delivery Chain 的 integration recovery tests；
- webapp typecheck / lint；
- quickstart 中定义的 controlled disconnect/reconnect smoke flow。
