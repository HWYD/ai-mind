# AI Mind v0.5.3：Long Message Virtualization

## Summary

v0.5.3 为非空聊天消息列表引入统一的可视区渲染能力，解决长会话中完整 DOM 同时参与布局带来的性能与稳定性问题。实现使用免费 MIT `react-virtuoso`，并保留 AI Mind 既有的流式跟随、用户阅读锁定和历史会话进入语义。

## Goals

- 限制同时挂载的消息根节点数量，让长历史会话可以连续浏览。
- 正确处理 Markdown、代码、图片、Tool、Resource、Prompt、Agent 与 Workflow 等异构消息的动态高度。
- 明确底层滚动与业务 Scroll Policy 的职责边界，避免多方竞争滚动位置。
- 让重要详情在离屏回收后仍保持用户的展开状态。

## Non-goals

- 不增加 cursor pagination、向上加载、服务端窗口化或消息数据淘汰。
- 不修改聊天 API、Stream DTO、服务端数据库 schema、Provider Runtime 或 Electron IPC。
- 不保存或恢复跨刷新的阅读位置、未读游标或完整 virtualizer state。
- 不保证离屏消息可被浏览器原生全文查找或同时存在于可访问树。

## Key Changes

- 所有非空消息列表统一交给 `react-virtuoso@4.18.12` 管理可见范围、底层滚动和真实 DOM 尺寸测量；空会话继续使用原有展示路径。
- Scroll Policy 保持业务层职责：历史首次定位、流式末尾跟随、用户向上阅读锁定、显式“回到底部”和下一轮请求重置。它只通过列表 handle 表达意图，不读取或写入消息区域的像素滚动位置；`followOutput` 保持关闭。
- 列表根据消息结构和消息列宽度生成初始高度估算，覆盖文本、代码、卡片 chrome 与图片比例。图片的 loading、ready、expired、error 状态保留一致的卡片几何，降低资源状态转换造成的布局变化。
- 对已完成且稳定展示的历史消息，浏览器可在独立 IndexedDB store 保存可失效的高度提示。提示同时受会话、消息身份、渲染指纹、列宽和展示状态约束；任何不匹配、缺失或不可用情况都会静默回退到结构化估算。
- Reasoning、Agent、Workflow 和原始详情等具有阅读意义的展开状态按会话和消息身份隔离，在虚拟列表离屏回收后可恢复；复制与 hover 等短暂反馈仍可重置。
- 历史会话在尾部定位完成前使用与消息列对齐的非滚动骨架；Composer、消息列与原生 scrollbar gutter 共用稳定布局坐标，避免首次刷新或切换时的横向偏移和滚动条形变。

## Important Interface Changes

本版本没有新增或修改公开聊天 API、Stream DTO、服务端数据库 schema 或 Electron IPC。

浏览器本地持久化新增仅用于性能优化的 `message-height-hints`：它不包含消息正文、图片 Blob、scrollTop 或服务端字段，不参与跨设备同步，也不改变会话快照的保留策略。

## Test Plan

- 自动化覆盖稳定消息 identity、动态高度、静态阅读不自动回底、流式跟随、历史首次揭示、会话切换取消与离屏详情状态。
- 真实浏览器覆盖 1,000 条混合消息 fixture 与本地最长真实会话，检查跨段浏览、刷新、拖拽、图片与详情场景。
- 高度提示以冷/暖路径验证正确展示和滚动行为；性能数值持续作为诊断信息，而不是改变滚动正确性边界的开关。

## Outcome

v0.5.3 已完成实现和本地浏览器验收。长消息的底层虚拟化、动态高度处理与业务滚动策略现在各自职责明确，为后续评估分页、搜索或更大规模会话提供稳定的消息视口基础。
