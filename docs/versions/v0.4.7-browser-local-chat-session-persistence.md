# AI Mind v0.4.7: Browser-local Chat Session Persistence

## Summary

v0.4.7 在不引入 PG 完整聊天历史、账号体系或跨设备同步的前提下，为 AI Mind 增加浏览器本地聊天会话持久化。客户端使用 IndexedDB 保存最近会话索引与完整用户可见消息快照，页面刷新后先本地恢复，再由服务端会话列表做权威校准。

这版明确保持三层权威边界：浏览器本地快照只负责完整 UI 历史展示；Server Conversation Registry 只负责会话身份、归属和最近会话保留；Server ThreadState 继续只负责 AI 运行时短期上下文。

## Goals

- 刷新后恢复最近会话列表、当前会话选择和当前会话的稳定用户可见消息。
- 保留文本、reasoning、tool/resource/skill/prompt、workflow progress、Agent trace、artifact 等富 UI 展示历史。
- 在服务端恢复成功后，以服务端会话列表为准校正本地索引，同时保留同 ID 会话的本地完整快照。
- 在服务端暂时不可用时，提供明确的只读缓存降级和可重试入口。
- 提供桌面端与移动端一致的单会话删除体验，并同步删除服务端 Registry、ThreadState/checkpoint 与本地快照。

## Non-goals

- 不新增 PG 完整 chat-history business table。
- 不引入账号体系、跨设备同步、云端历史恢复或浏览器间同步承诺。
- 不把本地完整 UI 历史升级为新的模型上下文来源。
- 不新增聊天历史搜索、导出、分享、重命名、归档或完整历史管理产品能力。
- 不修改 `@ai-mind/stream-core` 的公开协议。

## Key Changes

- 新增浏览器本地索引与快照存储，按 `conversationId` 隔离保存完整用户可见 UI 历史。
- 刷新恢复改为 local-first：先展示本地列表与当前会话，再请求 `GET /api/chat/conversations` 与 `GET /api/chat/thread` 做服务端确认。
- 有效的服务端会话列表响应成为本地最近会话索引的唯一权威；基线中的本地旧会话若不在服务端列表中，会被硬删除本地索引与快照。
- 同 ID 会话的本地完整消息快照不参与服务端完整历史比对，也不会被 bounded `ThreadState` 静默覆盖。
- 当 registry 或 thread 恢复失败但本地快照仍可用时，页面进入显式 read-only cache state，并提供 retry。
- 新增会话三点菜单与删除确认弹窗：桌面端 hover/focus 可见，移动端始终可触达；确认后同时删除服务端 Registry、ThreadState/checkpoint 和本地快照。

## Important Interface Changes

- `GET /api/chat/conversations` 的成功返回继续是最近会话列表的权威来源，但客户端会在成功后主动清理基线中的本地旧会话。
- `DELETE /api/chat/conversations` 新增单会话删除语义：只接受 `conversationId`，删除当前 browser session 的 Registry entry 与对应 ThreadState/checkpoint，并返回新的服务端权威列表状态。
- `/api/chat/thread` 继续只返回 bounded runtime context，不升级为完整 transcript。

## Test Plan

- 覆盖 local snapshot schema、revision 覆盖、容量裁剪、无效数据恢复与不同会话隔离。
- 覆盖 local-first 恢复、服务端权威会话列表校准、失败保留本地数据、只读缓存降级与恢复。
- 覆盖删除成功、删除失败、当前会话 fallback、最后一个会话删除与桌面/移动端交互。
- 执行 focused Vitest、`pnpm --dir apps/webapp typecheck`、`pnpm lint:webapp`、`git diff --check` 和浏览器 smoke。

## Result

v0.4.7 完成了浏览器本地聊天会话持久化收口。AI Mind 现在可以在同一浏览器环境中恢复最近会话与完整用户可见历史，同时继续把服务端会话归属和 AI 上下文维持在现有 Registry / ThreadState / UserMemory 边界内，没有引入新的服务端完整历史数据层。
