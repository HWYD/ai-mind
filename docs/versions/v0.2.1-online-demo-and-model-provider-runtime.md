# AI Mind v0.2.1：Online Demo & Model Provider Runtime

## Summary

`v0.2.1` 将 AI Mind 从本地 Ollama 单一模型入口，升级为由服务端统一治理的多 Provider Model Runtime。

本版支持：

- 本地开发使用 Ollama；
- 配置后使用 Qwen 或 DeepSeek；
- 前端在服务端白名单模型中切换；
- 普通聊天、Tool Calling 和 `/tasklist` Agent 共用同一模型创建入口；
- Provider 错误标准化、输入输出限制、默认限流和 usage 观测。

本版不扩大 Agent 权限，也不把 AI Mind 做成自由模型市场。核心变化是让模型来源从业务代码里的具体 SDK 依赖，收口为可配置、可校验、可观察的运行时边界。

## Goals

- 建立服务端 Model Catalog，作为模型白名单和能力声明的唯一事实源。
- 请求统一通过 `modelId` 选择模型。
- 抽出项目级 ModelProvider 与 Registry。
- Ollama、Qwen、DeepSeek 通过统一模型 handle 接入聊天主链。
- 前端模型选择器消费服务端公开模型列表。
- API Key 和 Provider 原始配置只存在于服务端。
- Provider 错误转换为稳定错误码和中文提示。
- 为公开 Demo 增加输入输出上限、超时和轻量限流。
- 记录 best-effort usage / token 信息，但不作为计费事实源。
- 保持 v0.2.0 Controlled Agent Graph 的入口与权限边界不变。

## Non-goals

- 不做用户自带 API Key。
- 不允许前端填写任意 Provider、base URL 或模型名。
- 不做模型市场。
- 不做多 Provider 自动 fallback。
- 不自动按任务类型切换更贵模型。
- 不做 Provider 健康检查与自动摘除。
- 不做精确计费、成本看板或数据库 UsageLog。
- 不做 Redis / KV 分布式限流。
- 不扩展 Agent 的资源、工具、写入或循环权限。

## Key Changes

### Model Catalog

模型选择事实源统一为：

```text
modelId -> Model Catalog -> provider / providerModel / capabilities
```

稳定模型 ID 使用 `provider/model-key` 格式，例如：

- `ollama/qwen3-8b`
- `qwen/qwen3.6-flash`
- `deepseek/deepseek-v4-pro`

Catalog 区分前端使用的稳定 ID、Provider 实际模型名和项目能力声明。非法模型、未允许的 Provider、环境不匹配或能力不支持时均 fail closed，不静默回退。

### Model Provider Runtime

业务主链不再直接创建 `ChatOllama`，而是通过 Registry 选择 Provider 并返回项目级模型 handle。

- Ollama Provider 负责本地模型和本地特有参数。
- Qwen / DeepSeek 复用 OpenAI-compatible Provider 基础层。
- Provider 参数差异停留在 Provider 层。
- 普通聊天和 tasklist legacy / graph runner 共用同一入口。

`modelId` 只决定使用哪个模型，不改变 Tool、Skill、MCP 或 Agent 权限。

### Public Model List

新增 `GET /api/ai/models`，返回服务端当前可用模型和默认模型。

公开模型 DTO 只包含选择器需要的：

- `id`
- `label`
- `provider`

接口不返回 API Key、base URL、底层模型名、完整能力对象或 Provider 原始错误。

首屏模型状态由 Server Component 从同一服务端事实源预取，再交给 Client Component 初始化，避免前端静态列表与服务端配置分叉。

### Frontend Model Selector

模型选择器按“线上模型 / 本地模型”分组，模型项优先展示图标、模型名和选中态。

- 只展示当前服务端允许且已配置的模型；
- 不展示 embedding 模型；
- 不允许手输任意模型名；
- 切换模型只影响后续请求；
- 请求只提交 `options.modelId`。

### Provider Errors

Provider 原始异常被转换为项目级错误：

- 未配置；
- 鉴权失败；
- 余额或额度不足；
- Provider 限流；
- 请求无效或上下文过长；
- 超时；
- 服务不可用。

用户只看到稳定错误码和手写中文提示。日志只记录脱敏 metadata，不记录密钥、headers、完整输入或完整输出。

### Limits and Usage

本版增加：

- 输入总字符限制；
- 普通聊天输出 token 上限；
- tasklist 输出 token 上限；
- Provider 请求超时；
- 按 IP 和 HttpOnly session 的每日限流；
- usage / token best-effort 脱敏日志。

限流默认开启，但当前 Store 只存在于单个 Node.js 进程内。它适合单实例轻量 Demo，不保证多实例一致性。

## Important Interface Changes

### Chat Request

请求字段从旧的裸模型名迁移为 Catalog ID：

```ts
type ChatRequestOptions = {
    modelId?: string
}
```

旧 `options.model` 不再被接受。

### Public Model DTO

```ts
type PublicChatModel = {
    id: string
    label: string
    provider: 'ollama' | 'deepseek' | 'qwen'
}
```

### Stream Errors

流式错误协议新增 Provider 相关错误码，用于表达未配置、鉴权失败、额度不足、限流、请求无效、超时和不可用。

## Test Plan

- Model Catalog、Provider config 和模型选择 resolver 单元测试；
- Ollama / OpenAI-compatible / Qwen / DeepSeek Provider 单元测试；
- models API 和 Server Component 初始模型状态测试；
- 前端模型选择器、请求 `modelId` 和滚动行为测试；
- Provider 错误标准化与 stream error 测试；
- 输入长度、输出上限、IP / session 限流和 cookie 测试；
- ordinary chat、Tool Calling、Reader Skill、Utility Skill 回归；
- tasklist legacy / graph runner 回归；
- Qwen / DeepSeek 真实普通聊天与 tasklist smoke。

## Outcome

v0.2.1 已完成本地 Ollama 与线上 Qwen / DeepSeek 的统一 Provider Runtime，并让前端模型选择、普通聊天和受控 Agent 共用服务端模型事实源。

真实云模型 smoke 已验证普通聊天和完整 `/tasklist` graph 链路。Provider 错误、输入输出边界、默认限流和 usage 观测也已落地。

当前仍保持克制：没有自动 fallback、没有模型市场、没有用户 Key、没有分布式限流，也没有扩大 Agent 权限。

## Known Limits

- production 只展示允许的云模型，不提供本地 Ollama 模型。
- 当前限流计数会在服务重启后清空，多实例之间不共享。
- usage 不是精确账单依据。
- 本地小模型的 tasklist 结构化规划稳定性弱于已验证的云模型。
- 云平台模型行为和可用性仍可能随平台更新变化。

## Future Work

- Redis / KV 分布式限流；
- Provider 健康检查；
- 持久化 UsageLog 和成本观测；
- 更完整的模型能力标签；
- 对 Provider 模型版本变化建立显式升级流程。
