# AI Mind v0.5.4：Token-aware Memory Compaction

## Summary

v0.5.4 将普通聊天记忆的压缩触发从固定消息数改为模型感知的 token budget。Runtime 在模型调用前预检完整输入，在压缩失败或历史过长时使用不写回 checkpoint 的 ephemeral fit，让 chat memory 不再单独阻断当前问题。

## Goals

- 按模型可见 chat memory 的 token 占用触发持久化压缩，避免短消息仅因累计轮次而频繁压缩。
- 统一处理 system instructions、Tool/Capability payload、UserMemory、chat memory 与最新用户问题的完整输入预算。
- 让压缩生成、候选校验或保存失败时仍能继续回答，并保持已有 checkpoint 可恢复。
- 对云端与本地模型提供可预测的运行窗口：云端最多 128K，Ollama 最多 32K。
- 在 Composer 中提供只读、无操作的聊天记忆用量提示。

## Non-goals

- 不把模型的物理 256K 或 1M 窗口直接作为默认运行窗口。
- 不增加手工压缩按钮、前端可配置预算或新的公开模型字段。
- 不修改现有 hydration DTO、Stream DTO、数据库 schema 或 ThreadState 字段 shape。
- 不把 Tool transcript、GraphState、RuntimeArtifact 或原始 Provider 结果写入 chat memory。

## Key Changes

- 修复虚拟聊天首问、草稿升格、续问和完成后的滚动跟随。已完成 measurement 的正向总高变化会在下一帧回底，不再等待迟到的底部状态；用户上翻或手动展开时保持阅读位置，点击到底或向下实际回底恢复跟随；缓存刷新不再重挂载活跃列表。
- 根 layout 新增基于 shadcn Base UI Toast 的顶部居中 Messages，用于项目链接复制等短暂操作反馈；同一操作使用稳定 id 原位更新，通知不进入 Virtuoso 几何。
- 会话服务错误、只读缓存、hydration 和生图限额分别保留在会话列表、Composer、消息占位和对应回复；移动会话导航移到消息 viewport 外，Virtuoso Header 默认留空。
- 流式 text/reasoning 改为按模型配置合并窗口（默认 40ms，大粒度 delta 模型可配置更短窗口），移除固定的 Unicode code point 提前 flush，以缩短大粒度模型 delta 的等待时间；不新增滚动命令或展示队列。

- Model Catalog 保留 server-only 的物理 context-window metadata；Runtime 按环境计算 effective window、输出预留、hard input budget、compaction trigger 与 post-compaction target。Ollama Provider 以有效窗口显式配置 `numCtx`。
- Chat Orchestrator 为 direct answer、tool planning/final、Composer Context 和 Capability Context 共用完整输入 preflight。只有排除 chat memory 后其余输入仍超限时，才返回既有输入过长错误。
- 持久化 compaction 只在 token trigger 被跨越时每请求尝试一次。候选必须 schema 合法、保留完整 user/assistant turns、位于目标内且严格缩小，才会原子更新 checkpoint。
- compaction 生成、校验或保存失败时，不覆盖 summary、pinned decisions 或时间戳；当前请求使用 ephemeral fit，按 pins、summary、最新完整 turns 收敛输入，且不改写持久化状态。
- Composer desktop skill-mode 工具栏新增无数字圆环；Tooltip 显示“聊天上下文已使用 xx%（128K/32K）”。该 read model 只暴露百分比和有效窗口，不暴露原始记忆、token 数或 Provider 配置。

## Important Interface Changes

现有 `AiMindThreadState` 字段、聊天 hydration DTO、公开模型列表、`thread-memory-status` chunk、前端 reducer 与数据库 schema 均保持不变。

浏览器新增同源的 chat-memory usage read model，只返回 `usedPercent` 和 `effectiveWindowTokens`；它不替代现有 hydration 或 stream contract，也不提供压缩操作。

## Test Plan

- 自动化覆盖预算精度、token estimator、持久化 compaction、候选拒绝、失败恢复、取消传播、完整输入 preflight、Provider options、旧 DTO 兼容与 Composer usage hint。
- 定向回归覆盖 safe final-turn、hydration、stream status、持久滚动意图、完成后的延迟布局、Messages/局部 Alert 和现有聊天路径。
- 最终收口通过 `pnpm typecheck`、`pnpm lint`、`pnpm test:stable`、本地开发 PostgreSQL 下的 `pnpm test:integration` 与 `pnpm build`；生产构建的 workspace boundary 验证和 Next optimized build 均完成。
- external structured-compaction smoke 已通过 DeepSeek 与本地 Ollama Qwen3；Ollama 运行时 context 为 32K。Qwen external smoke 受免费额度耗尽影响，作为 Provider 环境限制保留，不影响自动化 Provider contract 验证。

## Outcome

普通聊天的长期上下文现在以显式 token budget 管理，固定消息数不再驱动压缩。持久化失败不再使用户在压缩后无法继续提问；同时系统、工具和补充上下文的动态占用进入同一预检边界。Composer 可以在不暴露原始上下文的前提下提示记忆占用。

## Scroll Verification

Chrome 测试覆盖真实页面与 1000 条混合消息的 21 个场景，包含自动跟随全过程的按钮显隐，以及慢速和快速增量逐帧采样；慢速增量已测最长 3 帧重新贴底；按模型配置合并窗口后，快速增量最长 2 帧重新贴底、每帧至多一次回底命令，未观察到反向滚动，稳定后跟随位置误差不超过 4px。像素残影属于后续独立视觉优化项。边界见 [聊天消息视口](../architecture/chat-message-viewport.md)。
