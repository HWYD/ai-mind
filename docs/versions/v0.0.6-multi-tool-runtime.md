# v0.0.6 Multi-Tool Runtime

## Summary

`v0.0.6` 将 `v0.0.5` 的单 Tool Calling 验证版，升级为可扩展的多 Tool Runtime。

本版本不是 Agent，也不是 MCP，而是先把 Tool Registry、参数校验、执行策略、结果展示和运行时兜底整理成更稳定的能力层。

## Goals

- 从单工具扩展到多工具。
- 接入 `calculator`、`datetime`、`text-transform`。
- 建立统一 Tool Registry。
- 让每个 Tool 内聚自己的 schema、参数归一化、执行逻辑和展示信息。
- 保持普通问答、多 Tool 问答、多轮上下文稳定。
- 增强 runtime 兜底能力。

## Non-goals

- 不做 Agent loop。
- 不做 Skill 系统。
- 不做 MCP 接入。
- 不做长期记忆。
- 不做工具权限系统。
- 不做并行工具执行。
- 不做工具调用可视化平台。

## Key Changes

### 统一 Tool Registry

Tool 从单个 `calculator` 扩展为 registry 管理的多个 Tool。

每个 Tool 通过统一定义暴露：

- `name`
- `tool`
- `schema`
- `normalizeArgs`
- `formatInput`
- `formatOutput`
- `resultIsAuthoritative`
- `isAvailable`

Runtime 面向 registry 查询和执行，不直接感知具体 Tool 文件。

### 三个首批工具

本版本包含：

- `calculator`：确定性数值计算。
- `datetime`：当前时间、日期偏移、星期判断。
- `text-transform`：Markdown 转纯文本、链接提取、代码块提取、JSON 格式化。

这三类工具分别验证确定性计算、时间处理和文本转换。

### Runtime 兜底

本版本补强了多类失败场景：

- 未注册工具。
- 参数校验失败。
- 工具执行失败。
- 模型未按预期发起 tool call。
- 流式请求取消。
- controller 已关闭后的安全收束。

目标是让错误被限制在局部，而不是污染整条聊天链路。

### Tool Part 展示增强

前端 Tool 展示开始支持更统一的信息：

- 工具名。
- action。
- 输入摘要。
- 输出结果。
- 错误状态。

## Important Interface Changes

- Tool Registry 成为 Runtime 消费工具能力的统一入口。
- Tool definition 增加展示与可用性相关字段。
- Tool part 支持更清晰的状态表达。
- Runtime 对工具错误输出结构化事件。
- 上下文发送开始考虑最近轮次窗口。

## Test Plan

- 验证 `calculator` 计算题。
- 验证 `datetime` 当前时间、日期偏移、星期判断。
- 验证 `text-transform` 的 Markdown、链接、代码块、JSON 处理。
- 验证普通问答、工具问答、多轮上下文不互相污染。
- 验证工具参数错误、工具未注册和工具执行失败有结构化反馈。
- 验证 typecheck 与 build。

## Result / Outcome

`v0.0.6` 让 AI Mind 从单 Tool Calling 验证版，进入多 Tool Runtime 雏形。

项目开始具备更清晰的能力注册、执行、展示和兜底边界，为后续 Skill、MCP、Agent 演进打基础。
