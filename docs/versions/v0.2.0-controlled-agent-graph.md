# AI Mind v0.2.0：Controlled Agent Graph

## Summary

`v0.2.0` 是 AI Mind 中 `Version Plan to Tasklist Agent` 的一次编排层演进。

这一版引入 LangGraph，但目标不是把 AI Mind 扩展成通用 Agent 平台，也不是让模型获得更自由的资源读取、工具调用、循环规划或文件写入能力。

本版的核心目标是：

> 将 v0.1.1 已经跑通的受控 `/tasklist + @docs://versions/*.md` Agent 主链路，从手写 runner / 状态机流程编排，迁移为 LangGraph `StateGraph` 编排。

换句话说，v0.2.0 改变的是 Agent 执行路径的“表达方式”和“可观察性”，而不是扩大 Agent 的能力边界。

原来手写 runner 中的顺序调用和 `if / else` 分支，在这一版中被收敛为：

```text
StateGraph
  -> node
  -> edge
  -> conditional edge
  -> state patch
  -> graph event
```

本版验证的重点不是“Agent 更自由”，而是：

- Agent 执行路径是否可以更显式；
- 条件分支是否可以从手写逻辑收敛为可命名 route；
- 中间状态是否可以更容易观察；
- 后续 checkpoint / interrupt / HITL / replay 是否有更自然的架构入口；
- controlled / bounded / incremental 的路线是否能和 LangGraph 共存。

---

## Version Goals

v0.2.0 的主要目标包括：

- 引入 `@langchain/langgraph`，只用于 `Version Plan to Tasklist Agent` 的编排层。
- 新增 `VersionPlanTasklistGraph`，用 `StateGraph` 表达 v0.1.1 已有的受控主流程。
- 新增 graph runner，并通过服务端 runtime config 在请求开始前选择 legacy runner 或 graph runner。
- 复用 v0.1.1 已有 readiness、planner、resource、tasklist、validation、revision 和 final artifact 逻辑。
- 将 `PlanningDecisionAction` 映射为 graph conditional edge。
- 将 `WarningDisposition` 映射为 graph conditional edge。
- 保留 legacy runner 作为迁移期 fallback，但不复制两套业务规则。
- 新增 AI Mind 自己的 graph stream chunks，用于展示 node、route 和脱敏 state patch summary。
- 升级 `AgentTracePanel`，让它可以展示 graph timeline。
- 保持 `AgentTextArtifactPanel` 的最终 tasklist Markdown 展示语义不变。
- 保持普通问答、普通 docs summary、Tool Calling、Reader Skill、Utility Skill 主链路不退化。

---

## Non-goals

v0.2.0 不做以下内容：

- 不做通用 Agent Runtime；
- 不做多 Agent；
- 不做自由 tool calling；
- 不允许模型自由选择任意下一步；
- 不允许模型自由读取资源；
- 不支持从裸目标生成 tasklist，即仍不支持 `from_goal`；
- 不自动扫描 `docs/versions/*`；
- 不自动发现最新版本方案；
- 不读取历史 tasklist；
- 不读取源码目录；
- 不写入 `docs/tasklists/*`；
- 不写入任何 docs 文件；
- 不做生产级 checkpoint；
- 不做 pause / resume；
- 不做 replay / time travel；
- 不做 Human-in-the-loop 审批按钮；
- 不做 state 编辑后重跑；
- 不做历史 run 列表；
- 不做完整 GraphState 调试台；
- 不做前端 runtime switch；
- 不做运行中 graph 失败后自动切回 legacy runner 继续执行；
- 不直接透传 LangGraph 原始 debug stream；
- 不做 Artifact 持久化、编辑、下载、diff 或多 Artifact 工作台。

## Current Baseline

v0.1.1 已经完成了 `Version Plan to Tasklist Agent` 的主要能力。

当前 Agent 入口仍然严格收口为：

```text
/tasklist + @docs://versions/*.md
```

只有当用户显式选择 `/tasklist`，并显式引用本地 `docs://versions/*.md` 资源时，Agent 才会进入受控链路。

当前已有能力包括：

- 读取用户显式引用的 version plan；
- 生成 `VersionPlanExtract`；
- 判断 `PlanReadinessResult`；
- 让模型只在白名单 `PlanningDecisionAction` 中做一次有限选择；
- 最多读取 1 个白名单 optional context；
- 生成 `TasklistStrategy`；
- 生成 `tasklistDraft v1`；
- 调用 `validate_tasklist_structure` 做确定性结构校验；
- 通过 `WarningDisposition` 判断是否需要自动修正；
- 最多修正一次生成 `tasklistDraft v2`；
- v2 再次校验，但不生成 v3；
- 通过 `RevisionEffectResult` 评估修正效果；
- 最终 tasklist Markdown 通过 `AgentTextArtifactPanel` 展示。

当前状态机已经约束了关键边界：

- optional context 最多读取一次；
- draft 必须在 strategy 后执行；
- validation 必须在 draft 或 revise 后执行；
- warning disposition 必须在 v1 validation 后执行；
- revise 只能在 v1 validation 后执行，且最多一次；
- revision effect 必须在 validation 后执行；
- final answer 必须在 `revision_effect_evaluated` 后执行。

因此，v0.2.0 的 Graph 不能绕过旧状态机 guard。Graph 是新的编排表达方式，不是新的边界事实源。

## Core Design Decisions

### 1. LangGraph 只替换编排层

本版使用 LangGraph，但只替换 Agent 的编排方式。

LangGraph 接管：

- node 编排；
- edge 编排；
- conditional edge 路由；
- graph state partial update；
- graph event 输出。

LangGraph 不接管：

- Agent 入口边界；
- resource whitelist；
- tool scope；
- `maxSteps`；
- `maxOptionalContextReads`；
- `maxDraftRevisions`；
- `stopped` 状态边界；
- v2 后禁止继续修正；
- final 前必须校验和评估 revision effect；
- 不写文件；
- 不读源码；
- 不自由 tool calling。

一句话：

> LangGraph 负责“流程怎么走”，现有 runtime guard 继续负责“哪些事不能做”。

---

### 2. 不做前端 Runtime UI 开关

本版不提供：

```text
Legacy Runner / Graph Runner 前端切换按钮
```

原因是 legacy 和 graph 是底层编排实现差异，不是两个用户功能。

最终策略：

```text
legacy / graph runtime 全部通过服务端集中配置控制。
前端只根据后端 stream parts 展示 Trace / Debug。
```

用户不需要知道底层是手写 runner 还是 LangGraph runner。

---

### 3. 保留 legacy runner，但不复制业务规则

v0.2.0 保留 v0.1.1 手写 runner，作为迁移期 fallback。

但禁止维护两套业务逻辑。

正确关系是：

```text
legacy runner：手写编排方式
graph runner：LangGraph 编排方式
shared step operations：共同业务步骤
shared guard / limits：共同边界规则
```

两套 runner 应共用：

- readiness rule；
- planning decision schema；
- optional context resource whitelist；
- optional context 读取函数；
- TasklistStrategy prompt builder；
- draft / revise prompt builder；
- validate_tasklist_structure；
- warning disposition；
- revision effect；
- final artifact emitter；
- state-machine guard；
- limits。

---

### 4. 不做运行中自动 fallback

本版不做：

```text
graph runner 执行一半失败后自动切 legacy runner 继续执行
```

原因是 graph runner 可能已经发出 stream chunks，前端 Trace 可能已经开始展示，`runId / threadId / partId / artifactId` 也可能已经生成。

中途切换会导致：

- UI 混乱；
- 重复模型调用；
- 重复 artifact；
- Trace 语义不一致。

允许的是：

```text
请求开始前由服务端配置选择 legacy 或 graph。
```

---

### 5. Graph events 不透传 LangGraph 原始事件

本版新增 AI Mind 自己的 graph stream chunks。

不直接透传：

- LangGraph debug event；
- 完整 LangGraph state；
- 原始 node output；
- 原始 model messages；
- prompt；
- tasklist draft 正文；
- tool raw output。

原因是 AI Mind 已经有自己的 stream-core 协议。前端需要的是产品化 trace，而不是框架内部调试流。

---

### 6. GraphState 不替代现有 AgentState

v0.2.0 不重写业务状态。

`VersionPlanTasklistAgentState` 仍然是 Agent 的业务事实源。

GraphState 只包裹它，并增加 graph 执行轨迹，例如：

```text
threadId
currentNode
visitedNodes
routes
statePatchSummaries
runtimeMode
checkpointMode
output
```

设计原则：

- 不完全重写 v0.1.1 state；
- `agentState` 仍是业务事实源；
- graph 字段只记录图执行轨迹；
- graph node 只返回 partial state update；
- stream event、debug summary、UI view model 和日志都不能暴露完整业务状态。

## Runtime Config

v0.2.0 新增服务端集中配置。

推荐环境变量：

```env
AI_MIND_TASKLIST_AGENT_RUNTIME=graph
AI_MIND_GRAPH_EVENTS=on
AI_MIND_GRAPH_CHECKPOINT=off
AI_MIND_GRAPH_DEBUG_VIEW=off
```

开发环境可以使用：

```env
AI_MIND_TASKLIST_AGENT_RUNTIME=graph
AI_MIND_GRAPH_EVENTS=on
AI_MIND_GRAPH_CHECKPOINT=memory
AI_MIND_GRAPH_DEBUG_VIEW=on
```

回退 legacy 时可以使用：

```env
AI_MIND_TASKLIST_AGENT_RUNTIME=legacy
AI_MIND_GRAPH_EVENTS=off
AI_MIND_GRAPH_CHECKPOINT=off
AI_MIND_GRAPH_DEBUG_VIEW=off
```

配置规则：

- 所有 tasklist agent runtime 配置统一从集中配置读取；
- 禁止在业务代码中散落读取 `process.env`；
- runtime 配置只影响 `/tasklist + @docs://versions/*.md`；
- 普通问答不受影响；
- `/summary` 不受影响；
- `/check` 不进入本版 tasklist Agent；
- `graphEventsEnabled` 只在 graph runtime 下生效；
- `graphCheckpointMode=memory` 只允许 development；
- production 下 checkpoint 强制降级为 `off`；
- `graphDebugViewEnabled` 只控制后端是否输出脱敏 debug summary；
- 前端不提供 runtime switch。

## Agent Main Flow

v0.2.0 的 Graph 主流程为：

```text
START
  ↓
readVersionPlan
  ↓
evaluatePlanReadiness
  ↓
planningDecision
  ↓
routeAfterPlanningDecision
    ├─ askClarification
    │     ↓
    │    END
    │
    ├─ stopWithBoundaryMessage
    │     ↓
    │    END
    │
    ├─ readOptionalContext
    │     ↓
    │   decideTasklistStrategy
    │
    ├─ recordManualReviewItems
    │     ↓
    │   decideTasklistStrategy
    │
    └─ decideTasklistStrategy
          ↓
      draftTasklistV1
          ↓
      validateTasklistV1
          ↓
      decideWarningDisposition
          ↓
      routeAfterWarningDisposition
        ├─ reviseTasklistV2
        │     ↓
        │   validateTasklistV2
        │     ↓
        │   evaluateRevisionEffect
        │     ↓
        │   emitFinalArtifact
        │     ↓
        │    END
        │
        └─ evaluateRevisionEffect
              ↓
            emitFinalArtifact
              ↓
             END
```

关键点：

- `routeAfterPlanningDecision` 是 conditional edge；
- `routeAfterWarningDisposition` 是 conditional edge；
- `askClarification` 和 `stopWithBoundaryMessage` 是提前结束路径；
- `readOptionalContext` 最多出现一次；
- `reviseTasklistV2` 最多出现一次；
- 非修正分支也必须经过 `evaluateRevisionEffect`；
- final artifact 仍通过 `AgentTextArtifactPanel` 展示；
- ordinary assistant text 只输出摘要，不输出完整 tasklist 正文。

## Graph Node Mapping

| v0.1.1 能力                      | v0.2.0 Graph Node / Edge       |
| -------------------------------- | ------------------------------ |
| 读取 version plan + extract_plan | `readVersionPlan`              |
| 判断方案完整性                   | `evaluatePlanReadiness`        |
| 执行一次规划决策                 | `planningDecision`             |
| 根据规划决策分流                 | `routeAfterPlanningDecision`   |
| 读取 optional context            | `readOptionalContext`          |
| 记录人工复核点                   | `recordManualReviewItems`      |
| 决定 TasklistStrategy            | `decideTasklistStrategy`       |
| 生成 tasklist v1                 | `draftTasklistV1`              |
| 校验 tasklist v1                 | `validateTasklistV1`           |
| 判断 warning 处理方式            | `decideWarningDisposition`     |
| 根据 warning 分流                | `routeAfterWarningDisposition` |
| 修正 tasklist v2                 | `reviseTasklistV2`             |
| 校验 tasklist v2                 | `validateTasklistV2`           |
| 评估最终质量                     | `evaluateRevisionEffect`       |
| 输出最终 artifact                | `emitFinalArtifact`            |
| 输出澄清问题                     | `askClarification`             |
| 输出边界提示                     | `stopWithBoundaryMessage`      |

其中，`evaluateRevisionEffect` 不只服务于 v2 修正路径。即使没有触发 v2，它也是 final 前统一的质量评估节点。

## Stream Protocol

v0.2.0 保留已有 stream chunks：

```text
agent-step-start
agent-step-end
artifact-start
artifact-delta
artifact-end
```

新增 graph chunks：

```text
agent-graph-node-start
agent-graph-node-end
agent-graph-route
agent-graph-state-patch
```

P1 如开启 debug view，可增加：

```text
agent-graph-debug-summary
```

设计原则：

- graph events 只在 graph runtime 且 graph events 开启时发送；
- graph state patch 只发送摘要；
- 不发送完整 GraphState；
- 不发送完整 AgentState；
- 不发送 prompt；
- 不发送 tasklist draft 正文；
- 不发送 tool raw output；
- Graph events 不替代 final artifact。

- route 摘要；

不展示：

## Debug Summary

Debug Summary 是 GraphState 的安全摘要，不是完整状态调试台。

允许展示：

- `runId`
- `threadId`
- `runtimeMode`
- `checkpointMode`
- `currentNode`
- `visitedNodes`
- `lastRoute`
- `readiness.status`
- `decision.type`
- `strategy.granularity`
- `strategy.expectedStepRange`
- `optionalContext.status`
- `manualReviewItems.length`
- `validationV1.status`
- `validationV1.score`
- `warningDisposition.fixNow.length`
- `warningDisposition.manualReviewItems.length`
- `validationV2.status`
- `validationV2.score`
- `revisionEffect.finalDecision`
- `stepCount / maxSteps`
- `optionalContextReads / maxOptionalContextReads`
- `draftRevisions / maxDraftRevisions`

禁止展示：

- 完整 prompt；
- 完整 model messages；
- 完整 version plan 原文；
- 完整 optional context 原文；
- 完整 tasklist draft；
- 完整 tool output；
- 完整 AgentState JSON；
- 完整 GraphState JSON；
- API Key / token / env；
- 未脱敏错误堆栈。

一句话：

> Debug Summary 是“脱敏仪表盘”，不是完整内部状态查看器。

## Checkpoint Design

v0.2.0 的 checkpoint 只作为开发态能力。

支持：

```text
AI_MIND_GRAPH_CHECKPOINT=memory
```

边界：

- 只在 development 环境允许；
- production 下强制 off；
- 使用 LangGraph memory checkpointer；
- 每次 graph run 绑定 `threadId`；
- 不暴露 checkpoint controls；
- 不做 resume；
- 不做 replay；
- 不做 state edit；
- 不做历史 run list。

它的作用是：

- 本地调试 GraphState；
- 复盘每一步 checkpoint 状态；
- 辅助理解 node、route、state patch；
- 为后续 durable checkpoint / HITL / resume 打基础。

它不是：

- 用户历史记录；
- 线上恢复能力；
- 断线重连；
- 生产级 checkpoint；
- 长期 memory。

## Acceptance Criteria

v0.2.0 完成后，应满足以下条件：

### Runtime

- `/tasklist + @docs://versions/*.md` 可通过服务端配置选择 legacy 或 graph。
- 不提供前端 runtime switch。
- graph runner 只影响 tasklist Agent。
- 普通问答不受配置影响。
- `/summary` 不受配置影响。
- `/check` 不进入本版 tasklist Agent。
- graph 失败不会中途自动切 legacy 继续。

### Agent Behavior

- ready plan 可生成 v1、校验并 final。
- `needs_review` 可继续并输出人工复核点。
- `ask_clarification` 进入 stopped，不生成 draft。
- `stop_with_boundary_message` 进入 stopped，不生成 draft。
- optional context 成功后继续生成 strategy 和 tasklist。
- optional context 失败后降级继续并输出人工复核点。
- warning 只有人工复核项时不触发 v2。
- fail 或 fixNow 时最多生成 v2。
- v2 必须再次校验。
- v2 后不生成 v3。
- final 前必须完成 revision effect。
- final tasklist 正文只通过 Agent Text Artifact 展示。

### Graph

- Graph node 能覆盖 v0.1.1 主路径。
- `PlanningDecisionAction` conditional edge 正确路由。
- `WarningDisposition` conditional edge 正确路由。
- Graph runner 复用共享 step operation。
- legacy runner 不复制 graph 业务规则。
- GraphState 内部可以持有完整 `agentState`，但 graph event、debug summary、UI view model 和日志不得泄露完整 prompt、draft、resource content。

### Stream / UI

- `agent-step-*` 仍兼容。
- `artifact-*` 仍兼容。
- graph node start/end 可被 schema 接受。
- graph route 可被 schema 接受。
- graph state patch 只展示摘要。
- `AgentTracePanel` 能展示 graph node timeline。
- `AgentTextArtifactPanel` 不回归。
- Resource / Tool inline detail 归并不回归。

### Checkpoint / Debug

- `AI_MIND_GRAPH_CHECKPOINT=memory` 只在 development 生效。
- production 下 checkpoint 强制 off。
- debug summary 只展示白名单字段。
- debug view 不展示完整 state。
- debug view 不展示 prompt、draft、tool raw output 或 env。
- debug view 只放在 `AgentTracePanel` 折叠区域内，不新建复杂页面。

## Risk Management

### 风险 1：LangGraph 迁移成本高于预期

止损策略：

- 停在共享 step operation 抽取；
- 保留 legacy 为默认；
- 将本版降级为 `Controlled Agent Graph Spike`；
- 暂缓 graph events / checkpoint。

### 风险 2：两套 runner 业务规则分叉

止损策略：

- 强制抽共享 step operation；
- Graph node 只调用共享 step；
- route function 只做路由，不做业务判断；
- 所有 guard 继续走状态机。

### 风险 3：Graph events 复杂度过高

止损策略：

- P0 只保留 `agent-step-*`；
- graph events 降级为服务端内部日志或测试断言；
- P0+ 单独推进 graph events。

### 风险 4：Debug View 泄露过多状态

止损策略：

- 只允许 `buildGraphDebugSummary()` 输出白名单字段；
- 测试断言 summary 不包含敏感片段；
- `graphDebugViewEnabled` 默认 off；
- production 可强制 off。

### 风险 5：Checkpoint 被误解为产品能力

止损策略：

- 文档明确 development-only；
- production 强制 off；
- UI 不提供 resume / replay 控件；
- release note 不把 checkpoint 写成正式用户能力。

## Legacy Runner Lifecycle

v0.2.0：

- 保留 legacy runner；
- 允许服务端配置回退；
- 不做运行中 fallback；
- legacy runner 和 graph runner 共用 step operation。

v0.2.x 后续：

- 如果 graph runner 覆盖所有 v0.1.1 分支测试；
- graph events 稳定；
- 普通问答和 docs summary 回归稳定；
- README / runtime note / release note 已同步；

再讨论移除 legacy runner。

移除条件：

- graph runtime 至少稳定一个版本；
- 已没有测试只覆盖 legacy 而不覆盖 graph；
- legacy 不再承担迁移期止损价值。

## Final Target

`v0.2.0 Controlled Agent Graph` 的最终目标是：

> 在不扩大 Agent 权限、不破坏普通聊天主链路、不复制业务规则的前提下，把 `Version Plan to Tasklist Agent` 的 v0.1.1 手写 runner 迁移到 LangGraph `StateGraph`。

本版完成后，用户仍然只通过 `/tasklist + @docs://versions/*.md` 触发该 Agent；最终 tasklist 仍然通过 Agent Text Artifact 展示；普通回答仍然只输出校验、修正和人工复核摘要。

工程侧则获得：

- 可配置的 legacy / graph runtime；
- 显式 graph node / route；
- 脱敏 state patch summary；
- 可继续演进 checkpoint / debug / HITL 的结构基础。

本版不是 Agent 平台化版本，而是受控 Agent 编排层的稳态迁移版本。
