# v0.1.1 Controlled Planner Lite

## Summary

`v0.1.1` 在 `v0.1.0 Controlled Tasklist Agent` 的基础上继续演进。

这一版不做通用 Agent，也不引入 LangGraph。它只在既有受控入口中增加一次有限决策：

```text
/tasklist + @docs://versions/*.md
  -> 读取版本方案
  -> 判断方案完整性
  -> 选择下一步 action
  -> 确定 tasklist 拆分策略
  -> 生成 tasklist 草稿
  -> 结构校验
  -> 必要时修正一次
  -> 评估修正效果
  -> 输出最终结果
```

本版的重点是验证：一个受控 Agent 是否可以从固定流程前进到有限判断，同时仍然保持 Runtime 边界清晰。

## Goals

- 在 `Version Plan to Tasklist Agent` 中新增一次 Planning Decision。
- 只允许模型在 Runtime 白名单 action 中选择下一步。
- 使用规则判断 version plan 是否 ready / needs_review / blocked。
- 允许最多读取一个白名单 optional context。
- 让 `TasklistStrategy` 影响 tasklist draft 的粒度、数量、分组和优先级。
- 将 warning 分流为自动修正或人工复核点。
- 评估 v1 -> v2 修正效果，但不生成 v3。
- 用通用 Agent Text Artifact 展示最终 tasklist Markdown 产物。
- 保持普通问答、docs summary、Tool Calling、Reader Skill、Utility Skill 主链路不退化。

## Non-goals

- 不做通用 Agent Runtime。
- 不做多 Agent。
- 不用 LangGraph 替换现有 Runtime。
- 不做 Human-in-the-loop 按钮审批。
- 不做 pause / resume / checkpoint。
- 不持久化 AgentState。
- 不写入 `docs/tasklists/*`。
- 不自动扫描 `docs/versions/*`。
- 不读取历史 tasklist。
- 不从裸目标直接生成 tasklist。
- 不做 RAG / chunking / indexing。
- 不开放自由 tool calling。
- 不生成 `tasklistDraft v3`。
- 不做 artifact 持久化、编辑、下载、diff 或复杂工作台。

## Key Changes

### Plan Readiness

Runtime 读取 version plan 后，会用规则生成 `PlanReadinessResult`。

状态分为：

- `ready`：信息足够，可以继续生成 tasklist。
- `needs_review`：可以继续，但存在弱项，需要最终人工复核。
- `blocked`：缺少关键目标或内容无法拆分，不应直接生成。

这个判断不调用模型。

### Planning Decision

模型只允许选择 5 类 action：

- `proceed_to_tasklist_strategy`
- `read_optional_context`
- `ask_clarification`
- `proceed_with_manual_review_items`
- `stop_with_boundary_message`

所有 action 都必须通过 schema 校验。

如果 action 不合法，Runtime fail closed，不让模型自由补救。

### Optional Context

`read_optional_context` 最多读取一个白名单资源，例如：

- `docs://README.md`
- `docs://architecture/runtime-boundary.md`
- `docs://architecture/stream-core.md`
- `docs://architecture/capability-skill-surface.md`
- `docs://architecture/agent-runtime.md`
- `project://latest-context`

读取失败不会整体失败，而是降级继续，并把失败说明写入人工复核点。

### Tasklist Strategy

`TasklistStrategy` 会进入 draft prompt，影响：

- Step 数量范围。
- 拆分粒度。
- 分组方式。
- checklist 优先级。

这让 Planning Decision 不只是展示文案，而是真的改变后续生成行为。

### Warning Disposition

`validate_tasklist_structure` 的 warning 不再全部触发自动修正。

结构硬伤进入自动修正；轻度弱项进入人工复核点。

这样可以减少不必要的 v2，也让最终答案更准确地区分“必须修”和“需要人看一眼”。

### Revision Effect

如果生成 v2，Runtime 会比较 v1 / v2 的结构校验结果。

输出包括：

- 是否 improved。
- 修正前后分数。
- 已修复 issue。
- 仍然存在的 issue。
- 最终决策：`final`、`final_with_manual_review_items` 或 `blocked`。

即使 v2 仍然失败，本版也不会继续生成 v3。

### Agent Text Artifact

最终 tasklist 正文通过通用 Agent Text Artifact 协议输出。

这组 stream chunk 包括：

- `artifact-start`
- `artifact-delta`
- `artifact-end`

第一版只支持文本产物，tasklist 通过 `artifactKind: 'tasklist'` 表达。

前端展示分工：

- `AgentTracePanel` 展示执行过程。
- `AgentTextArtifactPanel` 展示最终 tasklist Markdown 正文。
- 普通 assistant text 展示结构校验、修正效果和人工复核点摘要。

这不是 artifact 工作台，也不保存历史版本；它只是把最终校验后的产物从普通聊天正文中拆出来，让交付体验更接近主流 Agent 应用的“过程 + 产物”分层。

## Important Interface Changes

- Agent 状态机新增 readiness、decision、optional context、strategy、warning disposition、revision effect 相关状态。
- `maxSteps` 从 8 调整为 12。
- `TasklistWeakSection` 新增稳定 issue code。
- `AgentTracePanel` 新增 planner lite 标签映射。
- `ChatStreamChunk` 新增通用 text artifact chunk。
- `MindMessage` 新增 artifacts 聚合字段。
- final answer text 只保留修正效果和人工复核点摘要；最终 tasklist 正文通过 artifact 展示。

## Test Plan

- ready plan 可以正常生成 tasklist。
- needs_review plan 可以继续生成，并输出人工复核点。
- blocked plan 可以提前输出澄清问题。
- boundary case 可以提前输出边界提示。
- optional context 成功后继续生成。
- optional context 失败后继续生成，并带 warning review item。
- warning 只有人工复核项时不触发 revise。
- fail 时最多 revise 一次，不生成 v3。
- `/tasklist` 缺少 version plan 仍 fail closed。
- `/summary @docs://README.md` 不进入 Agent。
- `/check` 不进入本版 tasklist Agent。
- 普通问答不进入 Agent。
- calculator / datetime 等既有工具不退化。
- `validate_tasklist_structure` 不进入 utility-skill 默认工具绑定。
- AgentTracePanel 能展示 decision / strategy / disposition / revision effect 摘要。
- artifact chunks 可以聚合为最终 tasklist 产物，且不会混入普通 text part。
- AgentTextArtifactPanel 可以渲染 Markdown、复制全文，并展示失败态。

## Result / Outcome

`v0.1.1` 让 AI Mind 的第一个 Agent 从“固定受控流程”前进到“有限受控决策”。

它仍然不是通用 Agent，但已经具备更像 Agent 的一个关键特征：模型可以在 Runtime 允许的 action 集合内做一次选择，而 Runtime 继续掌控资源、工具、写入、循环和停止边界。

最终输出层也从“一段普通 assistant 正文”升级为“AgentTracePanel 过程 + AgentTextArtifactPanel 产物 + 普通 text 摘要”的分层展示。
