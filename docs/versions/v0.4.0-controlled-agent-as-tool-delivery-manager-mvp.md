# AI Mind v0.4.0: Controlled Agent-as-tool Delivery Manager MVP

## 摘要

v0.4.0 把 `/delivery-chain` 从 v0.3.6 / v0.3.7 的固定 stage main path，推进成受控的 `ControlledDeliveryManager`。

新的主链路是：

```text
/delivery-chain
  -> resolveDeliveryChainInvocation
  -> load demo context
  -> ControlledDeliveryManager
       -> plan-subagent
       -> task-subagent
       -> review-subagent
  -> Delivery Chain Report
```

这版仍然不是自由 Supervisor，也不是多 Agent 平台。它只证明一件事：AI Mind 已经能在 `/delivery-chain` 内部，以受控 tool-calling 的方式建立第一版 Manager -> Subagent Tool -> Result -> Synthesis 架构。

## 为什么需要这个版本

v0.3.7 已经让 `/delivery-chain` 的执行过程可见，但本质上仍然是固定 stage workflow。  
如果继续沿着“节点换名”的方向走，`/delivery-chain` 和 Tasklist Agent 在展示上会越来越像，但在架构上没有真正拉开。

v0.4.0 的目标是明确区分两条路线：

- `/tasklist`：继续保持 LangGraph + HITL + checkpoint 的受控 Graph Agent
- `/delivery-chain`：切到受控 Manager 通过 tool-calling 委派子 Agent tool 的第一版

这样项目就不再只是“把多个 Agent 名字塞进节点”，而是真正出现了受控 Manager runtime。

## 本版做了什么

### 1. `ControlledDeliveryManager` 接管 `/delivery-chain`

`apps/webapp/lib/ai/runtime/delivery-chain/index.ts` 不再保留旧的 graph main path。  
现在 `startDeliveryChainRun()` 解析请求、加载 demo context 后，直接进入 `runControlledDeliveryManager()`。

### 2. 新增 delivery-chain-local manager contracts

新增目录：

```text
apps/webapp/lib/ai/runtime/delivery-chain/manager/
```

其中包含：

- `types.ts`
- `subagent-tool-schemas.ts`
- `runtime-artifacts.ts`
- `delegation-policy.ts`
- `subagent-tools.ts`
- `workflow-progress.ts`
- `report-synthesis.ts`
- `controlled-delivery-manager.ts`

这些 contract 只服务 `/delivery-chain`，不提升成全局 Agent Catalog。

### 3. 三个受控子 Agent tool

本版只定义三个 delivery-chain-local subagent tools：

- `plan-subagent`
- `task-subagent`
- `review-subagent`

它们通过项目现有 tool binding 心智模型接入模型，但不会出现在用户可选 tool surface 中。

### 4. RuntimeArtifact 只在 run-local runtime 内部流转

Manager 在本轮运行里使用四类内部 artifact：

- `plan`
- `tasks`
- `review`
- `delivery_report`

这些 artifact 不进入：

- `artifact-*` stream chunks
- frontend `message.artifacts`
- DB / persistence
- `@artifact://`

### 5. 固定顺序 + fail-closed policy

v0.4.0 的 delegation policy 非常保守：

- 只允许 `plan -> task -> review`
- `maxToolCalls = 3`
- 不允许 parallel
- 不允许 nested delegation
- 不允许未注册 tool
- 不允许乱序 tool
- 缺少必要 artifact 时直接安全失败
- 模型不支持 tool-calling 时直接安全失败，不降级成 runner fallback

### 6. 继续复用 workflow progress，但不暴露内部 transcript

`workflow-progress-*` 保持不变，只把 step 语义改成：

- 读取上下文
- 委派 Plan Subagent Tool
- 委派 Task Subagent Tool
- 委派 Review Subagent Tool
- 汇总 Delivery Chain Report

progress 只展示 curated safe summary，不透传 raw invocation、raw result、RuntimeArtifact、prompt 或 stack。

## 明确不做

v0.4.0 仍然不做：

- `/plan`、`/task`、`/review`
- user-selectable subagent picker
- `@artifact://`
- artifact persistence / chat persistence
- DB schema / Prisma migration
- PostgresSaver
- HITL / checkpoint / resume
- parallel subagents
- nested subagents
- free supervisor / dynamic routing
- global Agent Catalog
- 让 delivery-chain 子 Agent 调用 Tasklist Agent HITL Graph

## 验证重点

本版重点验证：

- delivery-chain manager contracts
- controlled manager legal serial delegation
- fail-closed invalid tool call / invalid result
- runtime artifact internal-only boundary
- workflow progress safe summary
- `/tasklist` non-regression
- `@demo://` boundary non-regression
- stream schema / reducer / assistant message non-regression

说明：当前 workspace 直接执行部分 `pnpm` focused tests 会先触发本地 build policy / ignored builds 约束，因此 focused validation 使用本地 `vitest` / `tsc` binary 入口完成，作为等价验证。

## 对后续版本的意义

v0.4.0 的价值不是把 `/delivery-chain` 变成完整 Agent 平台，而是把 AI Mind 从：

```text
固定 stage workflow
```

推进到：

```text
受控 Manager + Agent-as-tool delegation
```

这为后续版本留下了真正清晰的演进空间：

- 是否引入更严格的 tool-call observability
- 是否引入 HITL-aware delegation
- 是否引入更真实的 agent-as-tool registry
- 是否继续推进更强的 manager synthesis

但这些都不属于 v0.4.0。
