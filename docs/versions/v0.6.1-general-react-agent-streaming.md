# AI Mind v0.6.1：General ReAct Agent Streaming

## Summary

v0.6.1 改造通用 General ReAct Agent 的正文 authority：模型轮次的公开正文会立即流式展示，不再为正常无 Tool 回答固定追加一次 Answer 模型调用。Tool、Skill、Resource、Prompt 与模型可公开说明保持同一条按发生顺序排列的 Trace；安全 read source 直属于产生它的 Tool；最终正文仍在 Trace 外使用现有 Markdown 呈现。

## Goals

- 无 Tool 的自然完成正文在同一次 loop 调用中直接成为 final answer。
- 含 Tool 的模型说明作为 run-level commentary，先于 Tool dispatch 收口并与 Tool 行一起折叠。
- 明确区分 `pending`、`commentary` 与 `final_answer`，避免过程文字污染复制、Memory 和下一轮上下文。
- 以可回放的 `finalizationMode` 标识 normal 与 constrained 收口。

## Non-goals

- 不替换 LangChain `createAgent(version='v2')` 为手写 Chain 或 Runnable Tool loop。
- 不公开 raw reasoning、provider 原始事件、Tool input/output/error 或完整网页正文。
- 不实现 Tool 行 nested detail；`Nested Trace Row Disclosure` 在本版保持 Deferred。
- 不改变 Tasklist、Delivery Chain、Image Agent 的独立协议与展示。

## Key Changes

- 新增 additive `agent-text-start/delta/end` 协议和 `AgentTextPart`；普通 `text-*` 继续保持原义。
- start 到 end 之间由客户端派生 `pending`；Tool turn 解析为 `commentary`，符合自然收口证据的 no-Tool turn 解析为 `final_answer`。
- 纯正文完成保留“已完成思考”标题，但无详情时没有箭头、没有可交互 disclosure。
- 所有可见 Agent 正文从首 delta 起使用正文 Markdown、无文本图标；有 detail 时 pending/commentary 与 Tool 按事件顺序留在同一折叠 Trace，无 detail 的 pending 才显示在无箭头标题下；Tool 行保持单行，`web-search` 仅显示本次调用自身安全 `discovered` 来源数且不公开 query/input。
- constrained finalizer 成功时最终正文可用，但标题显示“处理未完成”、live Trace 默认展开，并排除 Chat Memory/UserMemory。
- General Agent 预算调整为 9 个含 Tool 轮次、14 次逻辑 Tool Call、10 次 loop 模型调用、最多 1 次 constrained finalizer 和 270 秒 hard deadline。
- 已知 ToolCall 在 provider 执行前因预算、安全、参数、重复或 URL provenance 被拒绝时，也会显示为一个脱敏的失败 Tool 行；它表示“模型请求未执行”，不会伪装成完成或已读取。
- 用户当前提供的安全公开 URL 无需点击授权；同会话最多可受限复用八个服务端原始 user URL。该候选清单不包含 assistant/Memory/摘要，也不能证明上一轮真的读取过页面。

## Important Interface Changes

completed `agent-run-end` 对已经产生 Agent text 的 v0.6.1 Run 必须携带 `finalizationMode: normal | constrained`。历史无 Agent text 的 Run 保持兼容；缺 provenance 的新 Run 在客户端 fail closed，不由 UI 猜测最终语义。

## Outcome

通用 ReAct 现在可以在不调用 Tool 时直接把正文作为流式最终答案，同时仍把带 Tool 的可见说明、执行事实、异常 provenance 与恢复边界保留为可观察、可验证的结构化过程。
