# v0.0.9 MCP Host MVP

## Summary

`v0.0.9` 将本地 `stdio` MCP Host MVP 接入现有 Skill Runtime。

这一版最核心的取舍是：对外能力名保持稳定，只替换底层能力来源。`reader-skill` 对模型仍然暴露 `city-weather` 和 `local-text-read`，但它们背后的实现开始分别来自 MCP Tool 和 MCP Resource。

本版本没有单独新起一套 MCP Runtime。MCP 在这里先作为能力来源层进入当前 Runtime，而不是成为新的顶层运行时形态。

## Goals

- 让现有 `reader-skill` 能消费 MCP-backed 能力。
- 使用本地 `stdio` MCP server 作为第一条 MCP 接入路径。
- 将天气查询迁移为 MCP Tool。
- 将项目文件读取迁移为 MCP Resource。
- 在流式协议和前端卡片中明确区分 Tool 与 Resource。
- 保持普通聊天和 `utility-skill` 行为稳定。

## Non-goals

- 不做 Agent Runtime。
- 不做 remote MCP transport。
- 不做 MCP sampling。
- 不做 Resource Picker。
- 不做 MCP server 管理 UI。
- 不把 `utility-skill` 迁入 MCP。
- 不做多 server 编排策略。

## Key Changes

### MCP Host 基础层

MCP Host 基础层基于官方 TypeScript SDK `@modelcontextprotocol/sdk`。

Host 层按职责拆分为几个稳定边界：

- Server registry 声明静态 MCP server，例如 `weather-server` 和 `project-files-server`。
- Client manager 按 `serverId` 复用 MCP client。
- Transport 在首版只支持本地 `stdio`。
- Adapters 将 MCP Tool / Resource 原始响应映射为当前 Runtime 可消费的结果。

这样可以避免 MCP 协议细节进入 `chat-service`、Skill 定义和前端消息渲染。

### 天气走 MCP Tool

模型可见能力名仍然是 `city-weather`。

内部实现上，`city-weather` 被适配到 MCP Tool `weather-server.get_weather`。这样既保留当前 Tool Runtime 与 Tool card 行为，又让底层能力来源变成 MCP-backed。

### 文件读取走 MCP Resource

模型可见能力名仍然是 `local-text-read`。

内部实现上，文件读取被映射到 `project-files-server.resources/read`。本版本把文件内容视为 Resource，而不是继续强行伪装成 Tool 结果。

文件访问边界保持收紧：

- 只允许项目根目录直接文本文件。
- 拒绝绝对路径。
- 拒绝父级目录穿越。
- 拒绝非文本文件。
- 大文件或超长内容继续按现有边界裁剪或拒绝。

### 流式协议与前端卡片

流式协议新增 Resource 事件，让前端可以把文件读取表达为独立消息 part。

本版本中，天气继续显示为 Tool card，文件读取显示为 Resource card。两类卡片都可以展示 `source`、`serverId` 等来源信息。

### reader-skill 作为 MCP 入口

`reader-skill` 成为第一个消费 MCP-backed 能力的 Skill。

它仍然只负责天气查询、项目文件读取、项目文件总结等阅读类场景，不扩张成 Agent、workflow、搜索层或任意文件访问层。

## Important Interface Changes

- `ChatStreamChunk` 支持 `resource-start` 和 `resource-end`。
- `MindMessagePart` 支持 `resource`。
- Tool part 可以携带 `source` 和 `serverId`。
- Resource part 携带 `resourceName`、`uri`、`serverId`、`status`、`contentPreview` 和可选错误信息。
- 对外能力名保持不变：`city-weather` 与 `local-text-read`。

## Test Plan

- 验证本地 MCP server 可以初始化。
- 验证 `city-weather` 可以调用 MCP Tool，并以 Tool card 展示。
- 验证 `local-text-read` 可以通过 MCP Resource 读取允许的项目文件。
- 验证非法路径和不支持的文件类型会被拒绝。
- 验证 Tool、Resource、reasoning、text parts 可以在同一条流中共存。
- 验证普通聊天和 `utility-skill` 不受影响。

## Result / Outcome

`v0.0.9` 证明了现有 Skill Runtime 可以在不重写聊天主链的前提下，消费 MCP Tool 和 MCP Resource。

更重要的结果不是“支持 MCP”这句话本身，而是：对外稳定能力名可以不变，底层能力来源可以替换为 MCP-backed。
