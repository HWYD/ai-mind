# AI Mind v0.4.5: Long-term User Memory Store Baseline

v0.4.5 在 v0.4.4 多会话短期记忆的基础上，引入了 browser-session scoped 的 `UserMemory Store`。同一个 browser session 下，不同 conversation 之间现在可以共享经过校验的长期用户偏好、稳定用户背景、稳定指令、工作流偏好、反复确认的约束，以及稳定项目上下文。

## 目标

- 在 ordinary text chat 和 tool-assisted ordinary chat 中按相关性召回长期用户记忆
- 把长期记忆作为 bounded supplemental context 注入，而不是混入 `ThreadState`
- 在 assistant final turn 完成后，后台异步提取 `0..N` UserMemory candidates
- 通过 deterministic validation、stable key、dedupe、suppression 和 safe degradation 保护持久化边界
- 在 compaction 成功后，仅对新增或变化的 pinnedDecisions 做 conservative promotion

## 非目标

- 不做完整聊天历史系统
- 不做 account-level / cross-device memory
- 不做 Memory Inspector、memory edit/delete UI
- 不做 embedding retrieval、pgvector、历史搜索
- 不把 UserMemory 混入 hydration payload、Conversation Registry、stream chunk、frontend reducer、GraphState 或 RuntimeArtifact
- 不把 Tasklist / Delivery 接入 UserMemory retrieval 或 extraction

## 关键实现

- 长期记忆使用 LangGraph `Store` abstraction；生产方向为 `PostgresStore`，开发/测试 fallback 为 `InMemoryStore`
- 新增 `apps/webapp/lib/ai/runtime/user-memory/` 模块，承载 provider、schema、validation、service、retrieval、context builder 和 extraction pipeline
- 每个 eligible ordinary completed turn 在 final turn 后 enqueue 一个 in-process best-effort extraction job
- 模型只负责结构化输出 candidates，包括显式 `stability` 字段；程序决定 validation、stable key、dedupe、suppression 和最终写入
- stable key 基于结构化 `identity.subject / facet / polarity` 生成；程序使用 structured identity normalization 确定记忆身份
- `user_preference` 作为通用长期偏好类型；`stable_user_context` 承接稳定、非敏感、对协作有帮助的用户背景
- retrieval 使用 rule-based scoring：优先依赖结构化 tags、structured identity 和 normalized text overlap，不在代码里维护 food / clothing / activity 这类二级领域关键词分类；对 `stable_user_context` 的职业/工作背景问题允许受控短语匹配，例如 `工作 / 工作经验 / 前端工程师`；最多 3 条，每条最多 300 字，总注入不超过 900 字；无关记忆允许 0 条注入
- 自然语言 forget / negation 会 suppress 旧记忆，而不是物理删除
- `db:user-memory:setup` 独立于 checkpoint setup，并通过 sanitize helper 避免泄露 `DATABASE_URL`
