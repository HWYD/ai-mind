# v0.0.7 Utility Skill

## Summary

`v0.0.7` 在 `v0.0.6` Multi-Tool Runtime 之上，引入第一层 Skill Runtime。

本版本只落地一个正式 Skill：`utility-skill`，并新增一个确定性 Tool：`unit-convert`。

这一版的重点不是继续堆 Tool，而是验证 Runtime 是否能在 Tool 之上稳定承接一层高层能力封装。

## Goals

- 引入 Skill Definition 与 Skill Registry。
- 落地第一版 `utility-skill`。
- 通过 `options.skill` 显式启用 Skill。
- 让 Skill 能过滤当前可用 Tool。
- 将 Skill prompt 注入聊天主链。
- 新增 `unit-convert` 并纳入 `utility-skill`。
- 保持普通开放式问答自然可用。

## Non-goals

- 不做自动 Skill 选择。
- 不做多 Skill 串联。
- 不做 Skill UI。
- 不做 Skill 级记忆。
- 不做 Skill 配置中心。
- 不做 MCP。
- 不做 Agent 化执行。

## Key Changes

### Skill Runtime 第一层

Skill 在本版本中承担高层任务域约束。

它负责：

- 定义任务域。
- 给出 system prompt。
- 限制 allowed tools。
- 给出输出风格偏好。

它不直接执行 Tool，也不等同于 Agent。

### utility-skill

`utility-skill` 覆盖日常确定性实用任务：

- 精确计算。
- 时间与日期。
- 文本轻量转换。
- 单位换算。

它要求结果简洁、最终结果优先、确定性 Tool 结果优先，同时不能把普通开放式问题强行工具化。

### unit-convert

新增 `unit-convert` Tool。

第一版支持：

- 长度：`mm / cm / m / km`。
- 重量：`mg / g / kg`。
- 温度：`C / F / K`。

它是确定性工具，结果可作为权威结果使用。

### Runtime 接入方式

请求通过 `options.skill` 显式传入 Skill。

Runtime 根据 Skill 读取：

- `systemPrompt`
- `allowedTools`
- `outputPolicy`
- `resultPolicy`

再用 `allowedTools` 过滤当前工具集合。

## Important Interface Changes

- `ChatRequest.options` 支持 `skill`。
- 新增 Skill Definition 与 Skill Registry。
- `utility-skill` 成为默认实用能力层。
- Runtime 可以按 Skill 过滤 active tools。
- 新增 `unit-convert` Tool Definition。

## Test Plan

- 验证不传 Skill 时旧路径仍可用。
- 验证 `utility-skill` 能正确过滤 allowed tools。
- 验证普通开放式问题不会被强行工具化。
- 验证 calculator、datetime、text-transform、unit-convert 正常。
- 验证非法工具参数会产生结构化错误。
- 验证 typecheck 与 build。

## Result / Outcome

`v0.0.7` 让项目第一次从多 Tool Runtime 升级为带 Skill 雏形的 AI Runtime。

这一层成立后，后续继续演进更多 Skill、MCP 能力接入和 Agent Runtime 会更自然。
