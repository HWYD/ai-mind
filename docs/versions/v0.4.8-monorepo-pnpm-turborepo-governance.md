# AI Mind v0.4.8: Monorepo pnpm / Turborepo Governance

## Summary

v0.4.8 是一次 Monorepo 工程治理版本，不新增业务功能。它统一 AI Mind 四个 workspace 的 Node.js / pnpm 基线、依赖声明边界、共享依赖版本策略和跨 package 任务编排，让本地开发、CI 与 Docker 构建使用同一套可复现入口。

pnpm 继续负责 workspace discovery、单一 lockfile、`workspace:` linking、Catalog 和 dependency build-script policy；Turborepo 只负责任务依赖、并行执行、输出与有限缓存。两者职责不重叠。

## Goals

- 根 metadata、CI 与 Docker 固定 Node.js 22.x 和 `pnpm@10.34.0`。
- frozen install 使用同一份 `pnpm-lock.yaml`，内部包缺失时禁止回退到 registry。
- 对内部依赖、workspace 层级和 dependency build scripts 建立可执行治理门禁。
- 使用选择性 pnpm Catalog 集中真正共享且兼容的依赖版本。
- 使用 `turbo.json` 统一 lint、typecheck、test、build 与 dev/watch 的任务依赖和缓存边界。
- 保持 package-level scripts、数据库 setup、CI、Docker 与生产部署链路可诊断且兼容。

## Non-goals

- 不引入 `--affected` execution 或 remote cache。
- 不引入 Changesets、npm publishing 或 package release automation。
- 不迁移到 pnpm 11、`pnpm deploy`、Nx 或新的 package extraction 结构。
- 不修改业务 Runtime、Agent、Tool、MCP、API、数据库 schema、stream protocol 或 UI 行为。
- 不改变 TCR 镜像命名、Docker Compose、生产 env、数据库 setup 和服务器部署脚本。

## Key Changes

### 1. 可复现安装基线

- 根 `packageManager`、GitHub Actions 和 Dockerfile 统一到 `pnpm@10.34.0`。
- 根 `engines.node` 固定 Node.js 22.x。
- CI 与 Docker 继续使用 frozen lockfile，不在安装阶段静默重算依赖。
- `pnpm-workspace.yaml` 对 dependency build scripts 使用逐项 boolean `allowBuilds`，未审查脚本不扩大权限。

### 2. Workspace 依赖边界

根 `preinstall` 执行 workspace boundary validator，拒绝：

- 本地 workspace 依赖使用普通 semver 而不是 `workspace:`。
- `@ai-mind/*` 内部 provider 缺失。
- `packages/*` 反向依赖 `apps/*`。

永久回归测试同时覆盖正常路径、两个独立错误和“普通 semver + provider 缺失”的组合错误，确保一次执行报告全部违规。

### 3. 选择性 Catalog

Catalog 集中 `@types/node`、TypeScript、Vitest、Zod、`@modelcontextprotocol/sdk` 和 dotenv。`@types/node` 统一到 Node.js 22 类型线；Next.js、React、UI/editor 等 Webapp-only 依赖继续由 Webapp 自己管理。

### 4. Canonical Turbo Task Graph

根 `pnpm lint`、`pnpm typecheck`、`pnpm test` 和 `pnpm build` 统一经 Turborepo 执行。`build` 和 `typecheck` 尊重 upstream package graph；数据库 typecheck/test 会等待同 package 的 Prisma generation。

数据库与 Webapp 当前测试包含外部状态，因此不缓存；stream-core 与 Project Assistant Service 的 hermetic tests 保留本地缓存。dev/watch 与 Prisma generation 同样禁用缓存。

### 5. CI、Docker 与部署兼容

CI 保留 PostgreSQL migration 和 runtime checkpoint setup 的显式顺序，再执行统一根任务图。Docker builder 改为根 `pnpm build`，仍产出原有 Webapp 与 Project Assistant Service runner；生产 dependency stage 继续显式生成 Prisma Client。

线上发布仍按既有流程构建并推送三个 TCR 镜像，再由 `deploy-production.sh` 拉取、执行 `db:setup:deploy` 并启动服务。无需新增 env、secret、Compose 字段或服务器步骤。

## Important Interface Changes

- 新增 canonical root commands：`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。
- 新增 `pnpm validate:workspace-boundaries` 和 `pnpm test:workspace-boundaries`。
- `pnpm dev` 通过 Turbo 启动 Webapp 及其 dependency watch tasks；`pnpm dev:pas` 保持独立。
- package-level commands 继续支持故障定位，不作为第二套 canonical orchestration。
- 没有业务 API、公开 DTO、stream chunk、数据库 schema 或生产 env 变化。

## Test Plan

- 使用 pnpm 10.34.0 执行 frozen install，并确认 lockfile 不发生意外变化。
- 执行 workspace boundary 4 个永久回归用例和 disposable negative checks。
- 从根目录执行 lint、typecheck、test、build，确认 Turbo 输出 workspace/task 级失败信息。
- 在无 generated Prisma Client 的隔离状态验证 database build 先于 typecheck/test。
- 验证 ordinary chat、tool-assisted chat、Tasklist 与 Delivery 旧链路。
- 构建 Webapp、Project Assistant Service 和 PostgreSQL+pgvector 镜像，并执行 migration、runtime setup 与数据库 integration tests。

## Result

v0.4.8 完成 Monorepo 工程治理收口：47 个实现任务和 60 个需求 checklist 项均完成；frozen install、workspace boundary、四组根命令、package 回归、PostgreSQL integration、三个 Docker image targets 与产品 smoke paths 均通过。

这版只改变依赖安装与工程任务编排方式，不改变线上业务行为和部署操作契约。
