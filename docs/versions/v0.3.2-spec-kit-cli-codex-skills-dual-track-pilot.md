# AI Mind v0.3.2: Spec Kit CLI + Codex Skills Dual-track Pilot

## 摘要

v0.3.2 是 AI Mind 的治理 pilot 版本，不新增业务功能。

它在 v0.3.1 治理基线之上，进一步验证官方 Spec Kit CLI 与 Codex skills 是否适合成为 AI Mind 后续复杂版本开发的统一入口。

这版不修改 Tasklist Agent Runtime、不修改 Graph、不修改数据库、不修改 stream 协议，也不改变前端交互。它解决的是“后续版本怎么更稳定、更省提示词地推进”。

## 为什么需要这个版本

v0.3.1 已经把 AI Mind 的复杂版本开发流程规范化为：

```text
constitution -> spec -> plan -> tasks -> acceptance -> decisions -> ADR -> implementation review
```

但在实际使用里，仍然存在一个体验问题：

- 复杂版本启动时，仍然需要人频繁手写大段提示词。
- clarify / checklist / analyze 已经有规则，但没有统一、顺手的执行入口。
- 官方 Spec Kit 正在快速演进，如果 AI Mind 完全只靠本地私有约定，后续容易脱离官方最佳实践。

v0.3.2 要回答的不是“要不要治理”，而是“要不要把官方 CLI 和 Codex skills 接进这套治理流程里”。

## 本版变化

- 新增 `specs/032-spec-kit-cli-codex-skills-pilot/`，沉淀 v0.3.2 的 spec / plan / tasks / acceptance / decisions。
- 新增 `docs/adr/0006-spec-kit-cli-and-codex-skills-dual-track.md`，记录双轨长期决策。
- 新增 `docs/architecture/spec-kit-tooling.md`，解释 CLI、Codex skills 和人工等价三条路径。
- 在项目内新增三枚 lightweight pilot skills：
    - `speckit-clarify`
    - `speckit-checklist`
    - `speckit-analyze`
- 真实试跑官方 Spec Kit CLI：
    - `specify version` 成功
    - `specify init <temp-project> --integration codex --integration-options="--skills" --ignore-agent-tools --script ps` 成功
- 确认官方 CLI 在 Codex skills mode 下会生成完整 `speckit-*` 套件，但本版不直接覆盖当前仓库规则。
- 用户已在全新 Codex 会话中人工校验项目内 `speckit-*` skills 可发现、可触发。

## 本版结论

v0.3.2 确立了 AI Mind 的当前策略：

- AI Mind 采用官方 Spec Kit CLI + Codex skills 双轨 pilot。
- CLI 和 skills 都不是事实源；事实仍以代码、tests、constitution、specs、ADR、architecture docs 为准。
- 人工等价 clarify / checklist / analyze 必须长期保留，防止外部 tooling 不可用时阻塞开发。
- 当前仓库内三枚 `speckit-*` skills 是 AI Mind lightweight pilot，不是官方完整 skills 套件的永久替代。
- v0.3.2 不把官方 CLI 升级为默认必装，也不接入 CI 强制门。

## 非目标

v0.3.2 不做：

- 不修改 runtime。
- 不修改 Tasklist Agent Graph。
- 不修改 Prisma schema。
- 不修改 PostgresSaver。
- 不修改 stream chunk 协议。
- 不修改 API route。
- 不修改前端 reducer。
- 不实现 pending HITL recovery。
- 不实现 Run History。
- 不把官方生成物直接覆盖进当前仓库。
- 不要求所有 Level A / B 小改都强制走完整 Spec Kit tooling。

## 后续版本如何复用

从 v0.3.2 开始，AI Mind 后续复杂版本可以优先这样启动：

1. 先读 constitution、目标版本 `specs/`、相关 ADR 和 architecture docs。
2. 用 `$speckit-clarify`、`$speckit-checklist`、`$speckit-analyze` 或人工等价方式做质量闸门。
3. 如果后续版本决定引入官方 full skills，则在保持 AI Mind 项目边界的前提下逐步合并，而不是直接让官方模板接管仓库。

## 价值

v0.3.2 的价值不在于新增功能，而在于把“治理规则”推进成“可执行工作流”：

- 后续复杂版本启动成本更低。
- Codex 更容易按统一流程工作。
- AI Mind 与官方 Spec Kit 的距离更近，但仍保留项目自己的事实源和边界控制。
- v0.3.3 可以更从容地评估是否引入官方 full skills、pinned CLI 或更强约束。
