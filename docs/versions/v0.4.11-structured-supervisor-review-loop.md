# AI Mind v0.4.11：Structured Supervisor Review Loop

## 摘要

v0.4.11 将 `/delivery-chain` 从"固定阶段外包裹模型工具调用"的受控多 Agent workflow，推进为具备有限真实决策能力的 `ControlledDeliverySupervisor`：

- 每个 run 只有一个 Runtime 分配身份的 `SupervisorDispatchPlan`，Supervisor 在受控边界内做有限但真实的执行前和评审后决策。
- 所有影响调度的 Agent 输出使用严格、角色专属的 closed Zod Contract；缺少必填字段、非法枚举或出现未知字段时整个结果被拒绝。
- Review Group 固定为 General、Risk、Boundary 三类 Reviewer 各一次，由 Runtime 强制校验完整性，Supervisor 不得跳过或替换。
- 初次 Review 后允许一次由 Runtime 从已验证 finding 派生的 Revision；返修后直接生成报告并等待人工确认，不执行 Re-review。
- 最终状态由确定性硬规则生成：`pass`、`clarification_required`、`needs_changes`、`needs_review`、`blocked`、`failed`。
- 业务生成使用用户选定模型，结构化 Contract 和 repair 固定使用 `deepseek/deepseek-v4-pro`。

## 用户可见能力

- 输入 `/delivery-chain` 后，Supervisor 判断输入是否充分并给出 `execute`、`clarification_required` 或 `blocked` 决策。
- 执行阶段按固定顺序：Plan → Tasks → General/Risk/Boundary 并行 Review。
- 初次 Review 中的必改问题会驱动 Plan、Tasks 或两者的一次返修，返修后直接收口。
- 进度展示覆盖 Supervisor decision、Plan、Tasks、Review Group、Revision 和 Report 阶段。
- 最终报告包含需求摘要、方案概览、任务拆解、评审结论和下一步建议。

## 架构变化

- 新增 role-specific closed Contract schemas 和至多一次 repair 的安全结构化调用边界。
- 删除从 Markdown 正文中提取 disposition、severity、boundaryStatus 等业务结论的行为。
- Review Group 由 Runtime 执行 exact multiset 校验，不再依赖模型生成的工具调用。
- 新增 ADR-0013：Structured Supervisor Review Loop。

## 非目标

不做 ReAct、通用 DAG、Agent Catalog、A2A、HITL、checkpoint、resume、持久化、LLM 最终润色，不修改 Tasklist Agent Graph 或 stream protocol public shape。

## 验证情况

- 58 个实现任务完成（T001–T058）。
- 确定性测试：133 文件 / 914 测试通过，覆盖 Contract、policy、Review Group、status matrix、loop 和 evaluation harness。
- typecheck 和 lint 通过。
- 外部模型评测（8 case × 3 baseline）的 harness 和 fixture 已就绪，真实 provider 评测待后续执行。
