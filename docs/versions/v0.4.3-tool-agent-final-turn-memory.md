# AI Mind v0.4.3: Tool & Agent Final Turn Memory

## 摘要

v0.4.3 在 v0.4.2 的单会话 chat memory baseline 上，继续扩展“可恢复的最终回合”范围。

新的可恢复路径变为：

```text
ordinary chat / tool-assisted final answer / MCP-resource final answer
tasklist final answer summary / delivery final report
  -> capture only the latest user input text
  -> capture only the completed user-visible assistant final text
  -> append once into the same chat ThreadState
  -> keep hydration DTO text-only and compatible
  -> keep compaction text-only and bounded
```

## 为什么需要这个版本

v0.4.2 已经解决了普通 text chat 刷新丢历史的问题，但仍明确排除了 tool、MCP/resource、Tasklist Agent 和 Delivery Chain。

这会带来一个很实际的体验缺口：

- 用户已经在当前会话里完成了一轮 tool 或 Agent 对话。
- 页面一刷新，用户刚刚看到的最终答案就不在 thread history 里了。
- 但这些链路的中间执行态、raw transcript、GraphState、RuntimeArtifact 又不能直接进 chat memory。

v0.4.3 的目标就是把“用户真的看见的最终问答”补进同一个 ThreadState，而不是把运行时执行过程持久化。

## 核心设计

### 只保存最终用户可见文本

persisted `ThreadState.messages` 继续只保存：

- user text
- assistant final text

继续不保存：

- raw tool args / result / ToolMessage
- raw MCP envelope / resource content
- Tasklist artifact markdown、GraphState、checkpoint、interrupt payload
- Delivery RuntimeArtifact、workflow progress、subagent raw result
- raw prompt、provider response、stack、cookie、API key

### append-time final-turn boundary

v0.4.3 不扩展 persisted message schema，也不把 source metadata 透传前端。

新增的是 append-time final-turn guardrail：

- ordinary tool、reader/utility、docs summary、MCP/resource 复用现有 orchestrator final text capture
- Tasklist 只保存 final answer text summary，不保存 artifact markdown
- Delivery 只保存 completed / blocked final report text；超长时按 8000 字符确定性截断
- paused / interrupted / failed / cancelled output 不保存
- 同一 completed final turn 仍最多写入一次

### hydration、context、compaction 继续兼容

- 继续使用 `GET /api/chat/thread`
- hydration DTO 与 v0.4.2 保持兼容
- hydrated messages 仍是普通 user / assistant text messages
- recent messages 现在可以包含 persisted tool / Tasklist / Delivery final turns
- compaction 继续只处理 text-only state，并且 failure 只能 no-op

### follow-up polish

本版收口还补了两项实际运行体验修正：

- Tasklist 和 Delivery final-turn append 命中压缩时，也会像普通 chat 一样 relay `thread-memory-status`
- Tasklist HITL resume 在 `agent-resume` 之后的 provider/runtime 失败，错误标准化现在和普通 chat 路径对齐，不再一律塌成 `MODEL_STREAM_FAILED`

## 与 v0.4.2 的关系

| 维度                                     | v0.4.2              | v0.4.3                      |
| ---------------------------------------- | ------------------- | --------------------------- |
| memory baseline                          | 普通 text chat only | 扩展到安全 final turn       |
| tool / MCP final answer refresh recovery | 无                  | 有                          |
| Tasklist final answer refresh recovery   | 无                  | 有，仅 final answer summary |
| Delivery final report refresh recovery   | 无                  | 有，仅 final report text    |
| persisted message schema                 | text-only           | 仍然 text-only              |
| hydration DTO                            | 安全 text DTO       | 保持兼容                    |
| stream-core / reducer                    | 不变                | 继续不变                    |

## 非目标

- 不做 ChatSession / ChatMessage 业务表
- 不做多会话历史、分页、搜索
- 不做 contextEntries
- 不做 execution summary / reasoning summary / agent run summary
- 不做 Tasklist checkpoint / resume 语义扩展
- 不做 Delivery artifact persistence 或 checkpoint/resume
- 不做 stream chunk 协议扩展
