# v0.1.0 Controlled Tasklist Agent

## Summary

`v0.1.0` 引入 AI Mind 的第一个受控单 Agent：`Version Plan to Tasklist Agent`。

这一版不是通用 Agent 平台，也不是让模型自由规划再执行的开放式 Agent。它只验证一条明确主路径：

```text
/tasklist + @docs://versions/*.md
  -> 读取用户显式引用的版本方案
  -> 生成 tasklist 草稿
  -> 执行结构校验
  -> 必要时最多自动修正一次
  -> 输出可复制草稿、校验结论和人工确认点
```

本版的重点是验证受控 Agent 在 Runtime 中如何被触发、约束、观察和停止。

## Goals

- 建立第一个受控单 Agent：`version-plan-to-tasklist-agent`。
- 只支持从用户显式引用的 `docs://versions/*.md` 版本方案生成 tasklist 草稿。
- 由 Runtime 固定主路径、状态转移、资源边界、工具权限和失败收束。
- 新增 Agent Step typed part，让前端展示 Agent 执行过程。
- 新增 `validate_tasklist_structure` deterministic tool，用于 tasklist Markdown 结构校验。
- 保持普通问答、docs summary、Tool Calling、Reader Skill、Utility Skill 主链路不退化。

## Non-goals

- 不做通用 Agent Runtime。
- 不做多 Agent。
- 不做长期记忆。
- 不持久化 AgentState。
- 不做工作流编排器。
- 不做 RAG、chunking 或 indexing。
- 不自动扫描 `docs/versions/`。
- 不自动发现最新版本方案。
- 不读取历史 tasklist。
- 不写入 `docs/tasklists/` 或任何 docs 文件。
- 不从裸目标直接生成 tasklist。

## Key Changes

### Controlled Agent Entry

Agent 入口严格要求：

- Composer command 为 `/tasklist`。
- Composer resource 显式引用 `docs://versions/*.md`。

如果缺少 version plan reference，Runtime 会 fail closed，并提示先引用版本方案。

### Runtime-controlled Agent Path

本版不让模型自由决定下一步做什么。

Runtime 固定主路径：

- read resource
- plan extract
- draft tasklist v1
- validate structure
- optional revise v2
- validate v2
- final answer

模型只在受控生成节点产出 tasklist 草稿或修正文稿。

### Agent State Machine

状态机限制当前允许执行的动作：

```text
idle -> plan_read -> drafted_v1 -> validated_v1 -> revised_v2 -> validated_v2 -> final
```

关键限制：

- `maxSteps = 8`
- `maxDraftRevisions = 1`
- `maxOptionalContextReads = 1`

### Tasklist Structure Quality Gate

新增 `validate_tasklist_structure` 工具，用确定性规则检查 tasklist 草稿结构。

它检查：

- 标题
- 来源方案 URI
- Step / checklist
- 验证项
- 执行纪律
- 暂停点
- 工程验证
- 风险 / 人工确认点

它只检查结构完整性，不判断内容质量是否完美。

### Agent Trace UI

新增 `agent-step-start` / `agent-step-end` 流式事件。

前端通过 `AgentTracePanel` 聚合展示：

- Agent 名称
- Step 状态
- 耗时
- warning / error 标签
- Resource / Tool 摘要
- 修正次数

## Important Interface Changes

- 新增 `GET /api/ai/resources/docs-catalog`，用于 Composer Resource Menu 枚举受控 docs 候选。
- 新增 Agent invocation resolver：只识别 `/tasklist + @docs://versions/*.md`。
- 新增 Agent State Machine 与 Runner。
- 新增 `validate_tasklist_structure` Tool Definition。
- 新增 stream chunk：`agent-step-start` / `agent-step-end`。
- 新增前端 `AgentTracePanel`。

## Test Plan

- `/tasklist` 缺少 version plan 时返回边界提示。
- `/tasklist + @docs://versions/*.md` 进入受控 Agent。
- `docs://versions/*.md` 缺少 `/tasklist` 时不进入 Agent。
- 普通问答不进入 Agent。
- `/summary @docs://README.md` 不进入 Agent。
- Agent 不读取 `docs/tasklists/*`。
- Agent 不自动扫描 `docs/versions/*`。
- `validate_tasklist_structure` 能识别 pass / warning / fail。
- warning 或 fail 且可修正时，最多生成 `tasklistDraft v2`。
- 不生成 v3。
- Agent Step 能在前端聚合展示。
- 非 Agent 场景的 Tool / Resource / Prompt 卡片不回归。

## Result / Outcome

`v0.1.0` 让 AI Mind 第一次具备受控单 Agent 能力。

它验证了一个更稳的 Agent 起点：不是先做通用智能体，而是先让 Agent 在明确入口、明确上下文、明确工具、明确停止条件和可视化执行过程下完成一个工程任务。
