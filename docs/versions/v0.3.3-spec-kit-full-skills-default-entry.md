# AI Mind v0.3.3: Spec Kit Full Skills Default Entry

## 摘要

v0.3.3 是 AI Mind 的治理与工具链版本，不新增业务功能。

它把 v0.3.2 已验证可行的 Spec Kit CLI + Codex skills dual-track pilot，推进为更明确的默认入口：后续 Level C / Level D 复杂变更，默认从 official Spec Kit full skills 开始；AI Mind 自己的工程约束则继续通过 constitution、specs、ADR、architecture docs 和 AGENTS 生效。

最新业务运行时 baseline 仍是 v0.3.0 Tasklist Agent HITL Checkpoint Resume MVP。

## 为什么需要这个版本

v0.3.2 已经证明三件事：

- official Spec Kit CLI 可以在 Codex skills mode 下生成完整 `speckit-*` 套件。
- Codex skills 能降低复杂版本启动时的重复提示词成本。
- 人工等价路径仍然需要保留，防止外部 tooling 不可用时阻塞开发。

但 v0.3.2 仍是 pilot。当时仓库内的三枚 `speckit-*` 是 AI Mind lightweight skills，不是官方 full skills。这会带来一个长期问题：同一个 `speckit-*` 名字到底代表官方流程，还是项目内替代流程？

v0.3.3 解决这个命名空间问题。

## 本版变化

- 引入 official Spec Kit full skills，作为 canonical `speckit-*` entry。
- official baseline 固定到 `github/spec-kit@v0.11.9` / `specify-cli 0.11.9`。
- 同步 official skills 依赖的 `.specify/scripts`、`.specify/templates`、`.specify/integrations` 和 agent-context extension。
- 保留 AI Mind 自有 `.specify/memory/constitution.md`，不被 official template 覆盖。
- 移除 v0.3.2 lightweight pilot skills 对 `speckit-*` 命名空间的占用。
- 将 pilot skills 中有价值的规则迁移到 constitution、ADR、architecture docs、template overrides 和 AGENTS。
- 新增 ADR-0007，记录 official full skills default entry 决策。
- 将 `speckit-converge` 纳入 Level C / D 收口检查。
- 将 `speckit-taskstoissues` 标记为 optional，不进入默认主流程。

## 当前默认流程

Level A 小改：

- 不需要 full skills。
- 说明修改范围和验证方式即可。

Level B 模块改动：

- 使用 mini spec 或引用现有 spec。
- 只有需求不清或影响面升级时才选择 clarify。

Level C 跨边界改动：

- 默认使用 official full skills。
- 至少覆盖 specify / clarify / plan / checklist / tasks / analyze。
- 实现后执行 converge 或人工等价收口。

Level D 架构改动：

- official full skills + ADR + architecture docs + 人工 review。
- release close 前执行 converge 或人工等价收口。

## 边界

v0.3.3 不修改：

- Tasklist Agent runtime。
- Tasklist Agent Graph。
- GraphState。
- Prisma schema。
- PostgresSaver。
- stream protocol。
- API route。
- 前端 reducer。

本版也不实现 pending HITL recovery、Run History、agent_run_events、Time Travel 或新 Agent。

## 对 AI coding 的价值

v0.3.3 让 Codex 后续处理复杂版本时更少依赖长提示词：

- `$speckit-specify` 帮助启动正式规格。
- `$speckit-plan` 帮助形成实施计划。
- `$speckit-tasks` 帮助拆可执行任务。
- `$speckit-analyze` 帮助实现前检查一致性。
- `$speckit-converge` 帮助实现后检查收口。

同时，AI Mind 没有把官方工具变成唯一事实源。项目事实仍按代码、测试、constitution、specs、ADR 和 architecture docs 判断。

## 后续版本如何复用

后续 v0.3.4 / v0.4.0 如果要做 pending HITL recovery、Run History Lite、agent_run_events 或更大 Agent Runtime 变化，推荐先按 v0.3.3 的流程启动：

1. 判断 Change Level。
2. Level C / D 使用 official full skills 或人工等价。
3. 先写 spec / plan / acceptance / tasks / decisions。
4. 实现前 analyze。
5. 实现后 converge。
6. 收口时同步 ADR、architecture docs、release assets 和 README。

这让 AI Mind 的版本演进既贴近 official Spec Kit，又保留项目自己的工程边界。
