# v0.0.10 Runtime Refactor 与 Stream Core

## Summary

`v0.0.10` 是一次结构升级：先把 Next.js 应用内部的聊天主链边界做清楚，再把稳定的流式内核下沉为内部 workspace 包 `@ai-mind/stream-core`。

最终主链方向收口为：

`route -> chat-service facade -> runtime -> skills / tools / mcp`

这次抽包是克制的。只有稳定的流式协议、生命周期、错误 helper 和 writer 工具进入 `stream-core`，业务编排继续留在 app runtime。

## Goals

- 保持 `createChatService().streamChat()` 外部入口稳定。
- 让 `chat-service` 回到薄 facade 角色。
- 将 `apps/webapp/lib/ai/runtime/` 建立为聊天运行时编排层。
- 统一 NDJSON 流式错误语义。
- 将稳定流式基础能力下沉到 `@ai-mind/stream-core`。
- 保持现有聊天、Tool、Skill、MCP 行为兼容。
- 让测试与文档资产跟随新结构收口。

## Non-goals

- 不做对外 Chat Runtime SDK。
- 不把整个 chat runtime 抽成 package。
- 不抽离 `ChatOrchestrator`、`chat-session` 或 `tool-runtime`。
- 不引入 Agent Runtime。
- 不引入持久化或数据库层。
- 不扩展新的 MCP 能力范围。
- 不重写 `utility-skill` 或 `reader-skill`。

## Key Changes

### chat-service 收口为薄 facade

`chat-service` 保持稳定服务入口，负责创建 stream、构造内部 `StreamResult`、兜底捕获顶层 runtime 错误，并最终包装为 `Response`。

它不再负责 prompt/session 构建、planning、tool execution、final answer 编排或协议级 chunk 拼装。

### Runtime 编排层

Runtime 层正式负责聊天执行路径：

- `chat-session` 构建模型输入、messages、active tools 和 Skill prompt 快照。
- `chat-orchestrator` 编排 planning、tool execution、fallback 和 final answer 阶段。
- `assistant-stream` 消费模型输出并写出 text 或 reasoning chunk。
- `tool-runtime` 负责 tool/resource 结果的校验、执行和展示映射。
- `authoritative-answer` 判断确定性单工具结果是否可以绕过模型改写。

### 流式错误与生命周期统一

流式错误统一为单一 `error` chunk，核心字段包括 `scope`、`errorCode`、`retryable`、`message` 和可选 `stage`。

`StreamLifecycle` 保证终态行为稳定：`start` 最多写一次，`finish` 或 runtime 终态错误只会收口一次。

### 内部 workspace 包

`@ai-mind/stream-core` 新增在 `packages/stream-core` 下。

当前包内包含稳定流式内核：

- `ChatStreamChunk` 协议类型。
- `StreamLifecycle`。
- stream error helpers。
- static text / reasoning writers。
- NDJSON web writer。

它不包含聊天编排、Skill 逻辑、Tool 执行、MCP 消费或业务策略。

### Monorepo 接入

`apps/webapp` 通过 workspace 包消费 `@ai-mind/stream-core`。

该包暴露 root、protocol、web 三个入口，并输出 CommonJS、ESM 和类型声明。

## Important Interface Changes

- `@ai-mind/stream-core` 导出稳定流式协议与 writer 工具。
- Webapp 从内部 workspace 包导入流式协议和 writer 基础能力。
- 流式错误 chunk 使用统一结构，并支持可选 `stage`。
- Runtime 模块在 `apps/webapp/lib/ai/runtime/` 下形成更清晰边界。

## Test Plan

- 验证 webapp route、stream 消费、runtime error、orchestrator 和 authoritative answer。
- 验证 `stream-core` lifecycle、static parts、web chunk writer 和 smoke 场景。
- 对 webapp 与 `stream-core` 执行 typecheck。
- 构建 `stream-core`。
- 构建 webapp。
- 确认没有引入新的 lint error。

## Result / Outcome

`v0.0.10` 在抽包之前先让聊天 runtime 边界变得清晰。

最终结果是：app runtime 更可维护，稳定流式内核成为小而清晰的内部复用包。它没有过早把整个聊天 Runtime 做成通用平台，而是只沉淀最稳定的一层。
