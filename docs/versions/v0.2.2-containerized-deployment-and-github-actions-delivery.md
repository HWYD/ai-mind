# AI Mind v0.2.2：Containerized Production Deployment & GitHub Actions Delivery

## Summary

v0.2.2 把部署链路从“本地开发可跑”推进到“生产拓扑可落地”。本版确认了双应用容器化、宿主机 Nginx 反向代理、生产 env 边界和不可变镜像发布方式，并基于真实腾讯云上线结果收口部署资产。

当前已验证的生产路线为：

- GitHub Actions -> 腾讯云 TCR -> 腾讯云服务器 Docker Compose
- 宿主机 Nginx 终止 HTTPS，并代理到 `127.0.0.1:3000`
- `project-assistant-service` 只保留在 Docker 内网，通过 `webapp -> http://project-assistant-service:8788/mcp` 访问

## Goals

- 为 `webapp` 和 `project-assistant-service` 提供稳定的 Docker 镜像构建与运行方式。
- 保证 `docs/`、Prompt 资产和本地 stdio MCP 脚本进入运行时镜像。
- 让生产 Compose 只消费已构建镜像，不在服务器上执行应用构建。
- 明确生产 env、MCP Token、模型 API Key 与 SSL 证书的职责边界。
- 为后续 GitHub Actions 自动发布准备最小可用的 workflow 和远端部署脚本。

## Real Delivery Update

- 腾讯云服务器访问 GitHub / GHCR 超时，因此生产镜像仓库从 GHCR 调整为腾讯云 TCR。
- 腾讯云服务器访问 Let's Encrypt ACME 超时，因此 HTTPS 不再依赖 Certbot-only 路线，实际采用腾讯云 SSL 证书手动部署。
- `project-assistant-service` 在生产环境缺少 `PROJECT_ASSISTANT_SERVICE_MCP_TOKEN` 时会以 `production_mcp_token_required` fail closed，因此 webapp 与 PAS 必须使用同一个强随机 Token。
- 当前已验证的镜像路径为：
    - `ccr.ccs.tencentyun.com/hwyd-ai-mind/ai-mind-webapp:sha-ef58cb8`
    - `ccr.ccs.tencentyun.com/hwyd-ai-mind/ai-mind-project-assistant-service:sha-ef58cb8`
- 当前已验证的 release metadata 变量名为：
    - `AI_MIND_WEBAPP_IMAGE`
    - `AI_MIND_PROJECT_ASSISTANT_SERVICE_IMAGE`
    - `AI_MIND_IMAGE_TAG`

## Verified Production State

- `project-assistant-service` healthy，且只 `expose 8788`，不映射宿主机端口。
- `webapp` healthy，且只绑定 `127.0.0.1:3000 -> 3000`。
- `https://ai.hwyblog.cloud` 正常访问。
- `http://ai.hwyblog.cloud` 会 `301` 跳转到 HTTPS。
- `https://ai.hwyblog.cloud/mcp` 返回 `404`，说明 PAS 没有经 Nginx 对公网暴露。

## Key Changes

### Production Compose

- 生产 Compose 改为使用 registry SHA 不可变镜像。
- `webapp` 与 `project-assistant-service` 分别使用独立镜像变量和统一 `AI_MIND_IMAGE_TAG`。
- `webapp` 依赖 `project-assistant-service` healthy 后再启动。
- `project-assistant-service` 只在容器网络内开放 `8788`。

### Production Env Boundary

- 仓库仅保留 `*.production.env.example` 示例文件。
- 真实值只放在服务器 `/srv/ai-mind/env/*.production.env`。
- GitHub Actions 不持有模型 API Key、MCP Token 或 SSL 私钥。
- `PROJECT_ASSISTANT_SERVICE_MCP_TOKEN` 必须同时注入 webapp 与 PAS，且值完全一致。

### Host Nginx and HTTPS

- Nginx 模板切换为“宿主机证书管理”通用写法。
- `/api/chat` 预留流式代理配置。
- `/mcp` 在公网入口直接返回 `404`。
- 证书可以来自腾讯云 SSL、Certbot 或其他 CA，但真实证书和私钥不进入仓库。

### Release Workflow

- release workflow 从 GHCR 切换为腾讯云 TCR。
- workflow 负责构建双镜像、推送 TCR，并通过 SSH 同步部署资产与触发远端部署脚本。
- 当前 workflow 已落仓，但还不能算“自动部署完成”；是否完成仍以首次真实生产跑通为准。

## Known Limits

- 当前生产证书由腾讯云 SSL 证书管理，续期不是 GitHub Actions 的职责。
- 证书续期后仍需要在宿主机替换 `/etc/nginx/ssl/YOUR_DOMAIN/` 下的证书文件并 reload Nginx。
- GitHub Actions 自动构建、推送 TCR、SSH 远端部署尚未计入已完成验收，仍需真实 Secrets 和首轮发布记录。
