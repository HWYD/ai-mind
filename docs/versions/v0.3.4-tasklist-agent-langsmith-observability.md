# AI Mind v0.3.4: Tasklist Agent LangSmith Observability Integration

## 摘要

v0.3.4 是一个运行时可观测性版本。

它不改变 v0.3.0 已经落地的 Tasklist Agent HITL checkpoint resume 主流程，而是在 `/tasklist + @docs://versions/*.md` 这条受控 Agent 路径上接入可选 LangSmith tracing。目标是让 initial run、HITL interrupt、human decision、resume、final / blocked / rejected / failed 等关键生命周期状态可以在外部观测平台中被串起来，方便线上排查和版本复盘。

本版本仍然保持 AI Mind 的小步演进原则：LangSmith 是外部 observability layer，不是业务状态源，不决定 AgentRun 状态，不参与 checkpoint resume，不影响 stream / artifact 输出。

## 为什么需要这个版本

v0.3.0 引入了 Tasklist Agent HITL checkpoint resume MVP。它已经能做到：

- Strategy Review 必停。
- Tasklist Revision Review 只在修订前条件式出现。
- 最多两轮受控修订。
- AgentRun / AgentInterrupt 记录业务状态。
- LangGraph PostgresSaver 记录 durable checkpoint。
- resume 后继续更新原 assistant message。

这让 Tasklist Agent 从“一次请求内完成”变成了“跨 initial request、人工审核、resume request、最终结果”的长生命周期执行。

单靠前端 AgentTracePanel、数据库状态和普通日志，线上排查时会遇到几个问题：

- 用户只说“卡住了”或“审核后没继续”，维护者需要跨 UI、DB、日志手动拼线索。
- HITL interrupt 和 human decision 分散在不同请求里，无法快速判断是哪一个审核点、哪一轮 review。
- blocked / rejected / failed 需要知道 result status、failure code 和耗时，但又不能把完整 GraphState 或 prompt 暴露给外部平台。
- 如果未来继续增强 Agent Runtime，需要先建立清晰的观测边界，而不是一上来接入全量 prompt replay。

v0.3.4 因此选择先做 metadata-first lifecycle tracing。

## 本版做了什么

### 1. 新增 Tasklist Agent LangSmith observability 模块

新增 `apps/webapp/lib/ai/runtime/version-plan-tasklist-agent/observability/`，集中承载：

- LangSmith config resolver。
- Tasklist Agent metadata allowlist builder。
- HITL metadata 提取。
- result metadata 提取。
- LangSmith observer adapter。
- no-op observer。

这个模块是一个边界适配层。它负责把 AI Mind 内部运行态转成安全的 LangSmith metadata，但不反向影响业务状态。

### 2. 使用最小 LangSmith 配置

本版采用 LangSmith 官方 env 风格：

```env
LANGSMITH_TRACING=false
LANGSMITH_API_KEY=
LANGSMITH_PROJECT=ai-mind-dev
```

启用条件是：

```text
LANGSMITH_TRACING === "true" && LANGSMITH_API_KEY 存在
```

没有新增 `AI_MIND_LANGSMITH_ENABLED`，避免出现“双开关”状态。

`LANGSMITH_ENDPOINT` 不进入默认 env 模板。自托管 LangSmith 或特殊 endpoint 场景可以在服务器环境中额外配置，但不作为 v0.3.4 的主路径。

### 3. initial run metadata

Tasklist Agent 首次运行创建 AgentRun 后，会记录 initial run metadata。

允许上传的典型字段包括：

- `app`
- `agentType`
- `agentVersion`
- `graphVersion`
- `runId`
- `threadId`
- `assistantMessageId`
- `versionPlanUri`
- `modelId`
- `provider`
- `reasoningEnabled`
- `environment`

这些字段用于在 LangSmith、数据库、前端消息和 checkpoint thread 之间做人工关联。

### 4. HITL interrupt / human decision / resume metadata

当 Tasklist Agent 命中 HITL interrupt 时，observer 会记录当前 interrupt 的摘要信息，例如：

- `interruptKind`
- `interruptId`
- `reviewRound`
- `strategyRegenerations`
- `draftRevision`
- `fixNowCount`
- `blockingIssueCount`
- `weakSectionCount`

当用户从审核卡提交 decision 后，resume 链路会记录 decision type 和 resume metadata。这里明确只记录 `approve / edit / reject / respond` 这类 decision type，不上传完整用户 feedback，也不上传用户直接编辑后的完整 tasklist markdown。

### 5. result metadata

Tasklist Agent 完成、blocked、rejected 或 failed 时，会记录 result metadata：

- `runStatus`
- `resultStatus`
- `artifactGenerated`
- `durationMs`
- `failureCode`
- `sanitizedFailureMessage`

失败信息只保留脱敏摘要，避免把 raw provider error、raw Error 或模型返回正文传到 LangSmith。

### 6. soft fail 策略

LangSmith 在 v0.3.4 中是“旁路观测”。

以下情况都不能影响 Tasklist Agent 主流程：

- LangSmith disabled。
- `LANGSMITH_TRACING=true` 但缺少 `LANGSMITH_API_KEY`。
- LangSmith client 初始化失败。
- trace / run 创建失败。
- update / flush 失败。

即使 LangSmith 不可用，AgentRun、AgentInterrupt、PostgresSaver checkpoint、stream chunk、artifact 输出仍按原业务路径执行。

## 明确不做

v0.3.4 不做以下内容：

- 不做 LangSmith Dataset。
- 不做 LangSmith Evaluation。
- 不做 Experiment Compare。
- 不新增 AI Mind 内置 Trace Viewer。
- 不新增 Run History 页面。
- 不新增 `agent_run_events`。
- 不做 pending HITL refresh recovery。
- 不做 conversation / message persistence。
- 不修改 Prisma schema。
- 不修改 PostgresSaver checkpoint schema。
- 不修改 Tasklist Agent Graph topology。
- 不修改 HITL decision contract。
- 不修改 stream protocol。
- 不修改 frontend message reducer。
- 不把普通聊天、reader-skill、utility-skill、MCP 或普通 Tool Calling 全量接入 LangSmith。
- 不让 LangSmith 失败影响 `/tasklist` 主流程。

## 隐私与 redaction 边界

允许上传：

- ID。
- URI。
- 状态。
- 计数。
- 耗时。
- decision type。
- result status。
- failure code。
- 脱敏 failure message。
- 摘要级 metadata。

禁止上传：

- 完整 GraphState。
- raw checkpoint。
- raw provider error。
- API Key。
- session cookie。
- ownerSessionHash。
- 完整 version plan 正文。
- 完整 prompt。
- 完整 optional context 正文。
- 完整用户 feedback。
- 完整 tasklist markdown。
- Prisma row 原始对象。
- request / writer / model client / AbortSignal / raw Error。

这一边界写入 ADR-0008，后续如果要做 full model call tracing 或 prompt replay，必须重新评估。

## 如何开启

本地开发可以在 `apps/webapp/.env.local` 中加入：

```env
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=your-langsmith-api-key
LANGSMITH_PROJECT=ai-mind-dev
```

生产环境可以在服务器 `/srv/ai-mind/env/webapp.production.env` 中加入：

```env
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=your-langsmith-api-key
LANGSMITH_PROJECT=ai-mind-production
```

关闭时设为：

```env
LANGSMITH_TRACING=false
LANGSMITH_API_KEY=
```

## 如何查看

在 LangSmith 中优先按下面信息定位：

1. `runId`
2. `threadId`
3. `assistantMessageId`
4. `agentVersion`
5. `graphVersion`
6. tag：`ai-mind`
7. tag：`tasklist-agent`

如果用户反馈某次 `/tasklist` 卡住或失败，维护者可以先从前端错误信息或 AgentRun 记录中拿到 `runId` / `threadId` / `assistantMessageId`，再去 LangSmith 搜索对应 trace。

## 对后续版本的意义

v0.3.4 不把 AI Mind 做成完整 LLMOps 平台，但它补上了一个重要边界：外部观测可以存在，但必须通过 allowlist、soft fail 和清晰 non-goals 进入系统。

这为后续 Run History Lite、agent_run_events、redacted model tracing 或更完整 Agent Runtime 调试能力预留了位置，同时避免 v0.3.4 过度膨胀。
