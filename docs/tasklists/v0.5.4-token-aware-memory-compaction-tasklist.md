# v0.5.4 Token-aware Memory Compaction 任务清单

## 已完成

- 修复虚拟聊天首问、草稿升格、续问和完成后的滚动跟随。已完成 measurement 的正向总高变化会在下一帧回底，不再等待迟到的底部状态；用户上翻或手动展开时保持阅读位置，点击到底或向下实际回底恢复跟随；缓存刷新不再重挂载活跃列表。
- 以 shadcn Base UI Toast 封装顶部居中 Messages；把持续故障放回对应功能区域，并将移动会话导航移出消息 viewport。

- 将普通聊天记忆压缩从固定消息数改为 token-aware ContextBudget，并将云端 128K 与 Ollama 32K 作为明确的运行窗口策略。
- 为所有注入 chat memory 的普通聊天路径接入完整输入 preflight；压缩失败或历史过长时使用只读 ephemeral fit 继续回答。
- 保持 checkpoint 原子性与安全 final-turn 边界：只保存最终用户可见 turn，排除 Tool/Agent 内部运行数据。
- 为 Composer desktop skill-mode 增加无操作的聊天记忆用量圆环和 Tooltip，并保持既有 hydration、stream 与公开模型契约不变。
- 保留流式 text/reasoning 的 40ms 合并；pending Map 累计达到 48 个 Unicode code point 时提前请求既有 rAF，不新增滚动命令或展示队列。
- 完成预算、压缩、连续性、取消、Provider、兼容性、前端提示、Messages/局部 Alert、虚拟滚动和 external smoke 的定向验证；慢速流式已测最长 3 帧重新贴底；当前 48 码点早刷下，快速 18 个 25ms delta 产生 18 次真实高度提交，最长 2 帧重新贴底、每帧至多一次回底命令，未观察到反向滚动。

## 验收

- 自动化覆盖 token trigger、候选校验、失败恢复、非记忆超限、所有主链 preflight、Ollama `numCtx`、状态收口和前端只读 usage contract。
- DeepSeek 与本地 Ollama Qwen3 的 structured-compaction smoke 已通过；Ollama 运行窗口确认是 32K。
- Qwen external smoke 受免费额度耗尽影响，作为 Provider 环境限制记录；不影响 Runtime 自动化回归结果。

## 边界

- 不把模型物理窗口直接开放给前端或作为默认运行窗口，不增加手工压缩入口。
- 不修改数据库 schema、现有 hydration DTO、Stream DTO、公开模型列表或 ThreadState 字段 shape。
- 不将聊天原文、prompt、Tool payload、Provider 配置或密钥写入诊断日志或 usage response。

## Scroll Verification

Chrome 测试覆盖真实页面与 1000 条混合消息的 21 个场景，包含自动跟随全过程的按钮显隐，以及慢速和快速增量逐帧采样；慢速增量已测最长 3 帧重新贴底；当前 48 码点早刷下，18 个 25ms delta 产生 18 次真实高度提交，快速增量最长 2 帧重新贴底、每帧至多一次回底命令，未观察到反向滚动，稳定后跟随位置误差不超过 4px。边界见 [聊天消息视口](../architecture/chat-message-viewport.md)。
